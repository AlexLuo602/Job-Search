# [239. Sliding Window Maximum](https://leetcode.com/problems/sliding-window-maximum/)

You are given an array of integers nums, there is a sliding window of size k which is moving from the very left of the array to the very right. You can only see the k numbers in the window. Each time the sliding window moves right by one position.

Return the max sliding window.

**Example 1:**

![[sliding-window-maximum-example-1.svg]]

```text
Input: nums = [1,3,-1,-3,5,3,6,7], k = 3
Output: [3,3,5,5,6,7]
```

**Example 2:**

```text
Input: nums = [1], k = 1
Output: [1]
```

Constraints:
- 1 <= nums.length <= 10^5
- -10^4 <= nums\[i] <= 10^4
- 1 <= k <= nums.length

---

## Solution

### Intuition
Maintain a deque of indices whose values are in decreasing order, so the front is always the window maximum. Any element smaller than a newcomer can never be a future max while the newcomer is in the window, so it is discarded. This is the monotonic-deque pattern (see [[Monotonic Stack]] for the same monotonic reasoning) applied to a [[0.SlidingWindowGuide|Sliding Window]].

### Approach 1: Brute force (for contrast)
Scan each of the `n - k + 1` windows and take its max in O(k). That is O(n*k), which times out for n up to 1e5.

### Approach 2: Optimal
Store indices in a deque kept decreasing by value. For each new index: pop expired indices off the front, pop smaller values off the back, push the new index, and once the first full window is formed, the front index holds the max.

```python
from collections import deque
from typing import List

class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        dq: deque[int] = deque()   # indices, values strictly decreasing front->back
        result: List[int] = []
        for right, val in enumerate(nums):
            # drop indices that have fallen out of the window on the left
            if dq and dq[0] <= right - k:
                dq.popleft()
            # drop smaller values; they can never be the max while val is present
            while dq and nums[dq[-1]] <= val:
                dq.pop()
            dq.append(right)
            # first window completes once right reaches k-1
            if right >= k - 1:
                result.append(nums[dq[0]])
        return result
```

> Store indices, not values. The window-expiry check `dq[0] <= right - k` needs positions to know when the front has slid out of range; values alone cannot tell you that.

### Complexity
- **Time:** O(n). Each index is pushed and popped at most once.
- **Space:** O(k). The deque holds at most one window's worth of indices.

### Key concepts to review
- [[0.SlidingWindowGuide|Sliding Window]] - fixed-size window producing one max per position.
- [[Monotonic Stack]] - the same monotonic-structure reasoning, here as a decreasing deque.
- [[05.MinimumWindowSubstring]] - sibling hard window problem.

### Common pitfalls
- Storing values instead of indices, which breaks the left-expiry check.
- Using `<` instead of `<=` when popping the back: with `<`, equal values linger and waste space (still correct, but `<=` is cleaner).
- Emitting an answer before the first full window forms (only append once `right >= k - 1`).

### Gaps
There is no dedicated "Monotonic Deque" or "Deque" canonical concept; [[Monotonic Stack]] is used per instructions to cover the monotonic-deque reasoning.
