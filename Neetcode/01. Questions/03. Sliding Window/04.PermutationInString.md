# 567. Permutation in String

Given two strings s1 and s2, return true if s2 contains a permutation of s1, or false otherwise.

In other words, return true if one of s1's permutations is the substring of s2.

**Example 1:**

```text
Input: s1 = "ab", s2 = "eidbaooo"
Output: true
Explanation: s2 contains one permutation of s1 ("ba").
```

**Example 2:**

```text
Input: s1 = "ab", s2 = "eidboaoo"
Output: false
```

Constraints:

- 1 <= s1.length, s2.length <= 10^4
- s1 and s2 consist of lowercase English letters.

---

## Solution

### Intuition
A permutation of `s1` is any substring of `s2` with the exact same character frequencies. So slide a fixed-size window (length `len(s1)`) across `s2` and check whether its frequency map equals `s1`'s. This is a fixed-window [[0.SlidingWindowGuide|Sliding Window]] driven by [[Frequency Counting]].

### Approach 1: Brute force (for contrast)
For every starting index in `s2`, sort the length-`len(s1)` substring and compare to sorted `s1`. That is O(n * m log m), too slow for n, m up to 1e4 when many windows overlap.

### Approach 2: Optimal
Maintain a count of the current window and compare against `s1`'s count. Comparing two `Counter`s every step is O(26); to make it tighter we slide by adding the entering char and removing the leaving char. Using [[Frequency Counting]] with fixed-size comparison keeps each step constant.

```python
from collections import Counter

class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        if len(s1) > len(s2):
            return False
        need = Counter(s1)
        window = Counter(s2[:len(s1)])   # first fixed-size window
        if window == need:
            return True
        for right in range(len(s1), len(s2)):
            window[s2[right]] += 1                 # char enters on the right
            left_char = s2[right - len(s1)]
            window[left_char] -= 1                 # char leaves on the left
            if window[left_char] == 0:
                del window[left_char]              # keep Counters comparable
            if window == need:
                return True
        return False
```

> Delete keys that hit zero. Python's `Counter` treats a missing key and a zero-valued key as equal in membership but `==` compares stored items, so leaving `{'a': 0}` around would still equal a Counter without `'a'`. Deleting is the safe, explicit habit and avoids surprises across Python versions.

### Complexity
- **Time:** O(n). One pass over `s2`; each `Counter` comparison is over at most 26 keys, i.e. O(1).
- **Space:** O(1). Counters bounded by the 26-letter alphabet.

### Key concepts to review
- [[0.SlidingWindowGuide|Sliding Window]] - fixed-size window of length `len(s1)`.
- [[Frequency Counting]] - permutation equality reduces to equal character counts.
- [[05.MinimumWindowSubstring]] - sibling window problem matching against a target frequency map.

### Common pitfalls
- Forgetting the early `len(s1) > len(s2)` guard, which would index past the end of `s2`.
- Leaving zero-count keys in the window Counter and relying on `==`; delete them to be safe.
- Treating this as a "contains all characters" problem; it requires exact counts and contiguity.
