# 121. Best Time to Buy and Sell Stock

You are given an array prices where prices\[i] is the price of a given stock on the ith day.

You want to maximize your profit by choosing a single day to buy one stock and choosing a different day in the future to sell that stock.

Return the maximum profit you can achieve from this transaction. If you cannot achieve any profit, return 0.

**Example 1:**

![[best-time-to-buy-and-sell-stock-example-1.svg]]

```text
Input: prices = [7,1,5,3,6,4]
Output: 5
Explanation: Buy on day 2 (price = 1) and sell on day 5 (price = 6), profit = 6-1 = 5.
Note that buying on day 2 and selling on day 1 is not allowed because you must buy before you sell.
```

**Example 2:**

```text
Input: prices = [7,6,4,3,1]
Output: 0
Explanation: In this case, no transactions are done and the max profit = 0.
```

Constraints:

- 1 <= prices.length <= 10^5
- 0 <= prices\[i] <= 10^4

---

## Solution

### Intuition
Track the cheapest price seen so far as the buy day, and at every later day check the profit of selling now. This is a [[0.SlidingWindowGuide|Sliding Window]] where the left pointer (buy day) only ever jumps to a new lower price. The key insight: you never need to revisit an old buy price once a cheaper one appears.

### Approach: Optimal
Walk once, keeping `min_price` (best buy so far) and the running `max_profit`. For each price, update the answer with `price - min_price`, then update `min_price`.

```python
from typing import List

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        min_price = float("inf")   # cheapest buy day seen so far
        max_profit = 0
        for price in prices:
            # selling today against the best earlier buy
            max_profit = max(max_profit, price - min_price)
            # then consider today as a future buy day
            min_price = min(min_price, price)
        return max_profit
```

> Update `max_profit` before `min_price`. If you lower `min_price` first, on a single-element pass you could compute a same-day buy/sell of 0, which is harmless here, but ordering keeps the buy-before-sell invariant explicit.

### Complexity
- **Time:** O(n). Single pass over prices.
- **Space:** O(1). Only two scalars retained.

### Key concepts to review
- [[0.SlidingWindowGuide|Sliding Window]] - left pointer (buy day) advances only to lower prices, right pointer scans forward.
- [[0.GreedyGuide|Greedy]] - keep the locally cheapest buy, which is provably optimal here.
- [[02.LongestSubstringWithoutRepeatingCharacters]] - companion sliding-window problem with a moving left bound.

### Common pitfalls
- Returning a negative number: clamp profit at 0 (handled by initializing `max_profit = 0`) since no transaction is allowed to lose money.
- Allowing the sell day to precede the buy day; processing left-to-right with "buy first" ordering prevents this.
- Forgetting the single-element / strictly-decreasing array case, where the answer must be 0.
