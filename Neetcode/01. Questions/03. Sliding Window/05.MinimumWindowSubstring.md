# [76. Minimum Window Substring](https://leetcode.com/problems/minimum-window-substring/)

Given two strings s and t of lengths m and n respectively, return the minimum window substring of s such that every character in t (including duplicates) is included in the window. If there is no such substring, return the empty string "".

The testcases will be generated such that the answer is unique.

A substring is a contiguous sequence of characters within the string.

**Example 1:**

![[minimum-window-substring-example-1.svg]]

```text
Input: s = "ADOBECODEBANC", t = "ABC"
Output: "BANC"
Explanation: The minimum window substring "BANC" includes 'A', 'B', and 'C' from string t.
```

**Example 2:**

```text
Input: s = "a", t = "a"
Output: "a"
Explanation: The entire string s is the minimum window.
```

**Example 3:**

```text
Input: s = "a", t = "aa"
Output: ""
Explanation: Both 'a's from t must be included in the window.
Since the largest window of s only has one 'a', return empty string.
```

Constraints:
- m == s.length
- n == t.length
- 1 <= m, n <= 10^5
- s and t consist of uppercase and lowercase English letters.

---

## Solution

### Intuition
Expand the window to the right until it covers every required character (with multiplicity), then shrink from the left as far as still-valid to find the smallest such window, recording the best. A `have`/`need` counter tells us in O(1) when the window is satisfied. This is a shrinking [[0.SlidingWindowGuide|Sliding Window]] over [[Frequency Counting]].

### Approach 1: Brute force (for contrast)
Check every substring of `s` and test if it contains all of `t`'s characters. That is O(m^2 * (m + n)) and far too slow for m up to 1e5.

### Approach 2: Optimal
Keep `need` = Counter(t) and `required` = number of distinct chars to satisfy. As `right` extends, increment the window count; when a char's window count reaches its needed count, increment `have`. While `have == required`, the window is valid: record it if smaller, then drop the leftmost char and shrink.

```python
from collections import Counter

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        if not t or not s:
            return ""
        need = Counter(t)
        required = len(need)         # distinct chars that must be fully matched
        window: dict[str, int] = {}
        have = 0                     # how many distinct chars are fully matched
        best_len = float("inf")
        best = (0, 0)                # [start, end] of best window
        left = 0
        for right, ch in enumerate(s):
            window[ch] = window.get(ch, 0) + 1
            if ch in need and window[ch] == need[ch]:
                have += 1
            # shrink while every required char is satisfied
            while have == required:
                if right - left + 1 < best_len:
                    best_len = right - left + 1
                    best = (left, right)
                left_char = s[left]
                window[left_char] -= 1
                if left_char in need and window[left_char] < need[left_char]:
                    have -= 1            # window broke; stop shrinking
                left += 1
        l, r = best
        return s[l : r + 1] if best_len != float("inf") else ""
```

> `have` counts fully-satisfied distinct characters, not total matched characters. It increments only at the exact moment a char's window count equals its need, and decrements only when shrinking pushes it below need. This makes the validity check a single integer comparison.

### Complexity
- **Time:** O(m + n). Build `need` in O(n); each char of `s` enters and leaves the window at most once.
- **Space:** O(m + n). Counters bounded by the distinct characters of `s` and `t`.

### Key concepts to review
- [[0.SlidingWindowGuide|Sliding Window]] - grow-then-shrink variable window to minimize length.
- [[Frequency Counting]] - `need`/`window` counts plus a `have == required` validity test.
- [[Hash Map]] - character-to-count maps backing the counters.
- [[04.PermutationInString]] - sibling problem matching a target frequency map.

### Common pitfalls
- Comparing the whole window map to `need` each step (O(alphabet) per step); the `have`/`required` counter avoids that.
- Decrementing `have` on every left removal instead of only when the count drops below `need`.
- Forgetting to return `""` when no valid window is ever found (guard via `best_len == inf`).
