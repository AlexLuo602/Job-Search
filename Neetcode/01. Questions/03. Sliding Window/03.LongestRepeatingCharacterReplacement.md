# 424. Longest Repeating Character Replacement

You are given a string s and an integer k. You can choose any character of the string and change it to any other uppercase English character. You can perform this operation at most k times.

Return the length of the longest substring containing the same letter you can get after performing the above operations.

**Example 1:**

```text
Input: s = "ABAB", k = 2
Output: 4
Explanation: Replace the two 'A's with two 'B's or vice versa.
```

**Example 2:**

```text
Input: s = "AABABBA", k = 1
Output: 4
Explanation: Replace the one 'A' in the middle with 'B' and form "AABBBBA".
The substring "BBBB" has the longest repeating letters, which is 4.
```

Constraints:

- 1 <= s.length <= 10^5
- s consists of only uppercase English letters.
- 0 <= k <= s.length

---

## Solution

### Intuition
A window is valid if we can make it all one letter using at most `k` replacements, i.e. `window_size - count_of_most_frequent_char <= k`. Grow the window; when it becomes invalid, shrink from the left. This pairs [[0.SlidingWindowGuide|Sliding Window]] with [[Frequency Counting]] over the 26 letters.

### Approach: Optimal
Track per-character counts and `max_freq` (the highest count seen). When `right - left + 1 - max_freq > k`, the window needs more than `k` swaps, so advance `left` and decrement its count.

```python
from collections import defaultdict

class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        count: dict[str, int] = defaultdict(int)
        left = 0
        max_freq = 0       # highest single-char count seen in any window
        result = 0
        for right, ch in enumerate(s):
            count[ch] += 1
            max_freq = max(max_freq, count[ch])
            # chars to replace = window size - most common char
            if (right - left + 1) - max_freq > k:
                count[s[left]] -= 1
                left += 1
            result = max(result, right - left + 1)
        return result
```

> `max_freq` is never decreased when shrinking. That looks like a bug but is fine: the answer only grows, so a stale (possibly too-high) `max_freq` can only keep the window the same size, never produce a wrong larger answer.

### Complexity
- **Time:** O(n). Each character enters and leaves the window at most once.
- **Space:** O(1). At most 26 uppercase-letter counts.

### Key concepts to review
- [[0.SlidingWindowGuide|Sliding Window]] - window expands by one and shrinks by at most one each step.
- [[Frequency Counting]] - count map gives the most-frequent char in the window.
- [[02.LongestSubstringWithoutRepeatingCharacters]] - sibling longest-window problem.

### Common pitfalls
- Recomputing the true max frequency on shrink (O(26) extra) thinking it is required; the never-decreasing `max_freq` is correct and faster.
- Using `while` instead of `if` to shrink: also correct, but since the window never needs to shrink by more than one per step, `if` suffices.
- Confusing "replace at most k" with "window must contain k distinct chars".
