# 20. Valid Parentheses

Given a string s containing just the characters '(', ')', '{', '}', '[' and ']', determine if the input string is valid.

An input string is valid if:

- Open brackets must be closed by the same type of brackets.
- Open brackets must be closed in the correct order.
 

**Example 1:**
```
Input: s = "()"
Output: true
```
**Example 2:**
```
Input: s = "()[]{}"
Output: true
```
**Example 3:**
```
Input: s = "(]"
Output: false
```

Constraints:

- 1 <= s.length <= 104
- s consists of parentheses only '()[]{}'.

---

## Solution

### Intuition
Brackets must close in last-opened-first-closed order, which is exactly the [[Stack]] LIFO property. Push every opening bracket; when a closing bracket appears, the matching opener must be on top of the stack. A [[Hash Map]] from closing to opening bracket makes the match check clean.

### Approach
Iterate over the string. For an opening bracket, push it. For a closing bracket, the stack top must equal its matching opener (and the stack must be non-empty), otherwise the string is invalid. At the end the stack must be empty (no unclosed openers).

```python
class Solution:
    def isValid(self, s: str) -> bool:
        pairs = {")": "(", "]": "[", "}": "{"}  # closing -> opening
        stack: list[str] = []

        for c in s:
            if c in pairs:                      # c is a closing bracket
                # stack must have the matching opener on top
                if not stack or stack.pop() != pairs[c]:
                    return False
            else:                               # c is an opening bracket
                stack.append(c)

        return not stack                        # valid only if nothing is left open
```

> The empty-stack check before `pop()` matters: a leading closing bracket like `"]"` has nothing to match, so it must short-circuit to `False`.

### Walkthrough
Trace `s = "()[]"`:

| char | action | stack |
|------|--------|-------|
| `(` | push | `['(']` |
| `)` | pop `(` matches | `[]` |
| `[` | push | `['[']` |
| `]` | pop `[` matches | `[]` |

Stack empty at end -> output `True`.

### Complexity
- **Time:** O(n). Each character is processed once with O(1) stack operations.
- **Space:** O(n). Worst case (all openers like `"((("`) every char sits on the stack.

### Key concepts to review
- [[Stack]] - LIFO structure that naturally models nested/most-recently-opened matching.
- [[Hash Map]] - O(1) lookup of the opener that each closer expects.

### Common pitfalls
- Forgetting the empty-stack guard before popping, causing an error or wrong result on a leading closer.
- Returning `True` without the final empty-stack check, so unclosed openers like `"("` slip through.
- Pushing closing brackets onto the stack instead of validating them against the top.
