# 84. Largest Rectangle in Histogram


Given an array of integers heights representing the histogram's bar height where the width of each bar is 1, return the area of the largest rectangle in the histogram.

 

**Example 1:**

![[largest-rectangle-in-histogram-example-1.svg]]

```
Input: heights = [2,1,5,6,2,3]
Output: 10
Explanation: The above is a histogram where width of each bar is 1.
The largest rectangle is shown in the red area, which has an area = 10 units.
```
**Example 2:**
```
Input: heights = [2,4]
Output: 4
```

Constraints:

- 1 <= heights.length <= 105
- 0 <= heights[i] <= 104

---

## Solution

### Intuition
A rectangle's area is `height * width`, where width is how far a bar's height can extend left and right before hitting a shorter bar. A [[Monotonic Stack]] of increasing heights finds those boundaries: when a shorter bar arrives, every taller bar on the stack can no longer extend, so we finalize its rectangle, and its starting index tells us how far left it reaches.

### Approach
Keep a stack of `(start_index, height)` in increasing height order. For each bar, pop all taller-or-equal bars on top, each pop yields a candidate area `height * (i - start)`, and the leftmost popped start becomes the new bar's start (it can extend left over the shorter bars it dominated). Push the bar with that start. After the scan, remaining bars extend to the end of the array.

```python
class Solution:
    def largestRectangleArea(self, heights: list[int]) -> int:
        max_area = 0
        stack: list[tuple[int, int]] = []       # (start_index, height), increasing height

        for i, h in enumerate(heights):
            start = i
            # taller bars can't extend past this shorter one -> close them
            while stack and stack[-1][1] > h:
                idx, height = stack.pop()
                max_area = max(max_area, height * (i - idx))
                start = idx                      # h can extend left to here
            stack.append((start, h))

        # bars never closed extend to the end of the histogram
        n = len(heights)
        for idx, height in stack:
            max_area = max(max_area, height * (n - idx))

        return max_area
```

> Carrying the popped `start` backward is the crux: a bar that survives a pop inherits the left reach of every shorter-than-it bar it just removed.

### Walkthrough
Trace `heights = [2,1,5,6,2,3]`:

| i | h | pops (area) | stack (start,h) |
|---|---|-------------|-----------------|
| 0 | 2 | - | `[(0,2)]` |
| 1 | 1 | pop (0,2): 2*(1-0)=2 | `[(0,1)]` |
| 2 | 5 | - | `[(0,1),(2,5)]` |
| 3 | 6 | - | `[(0,1),(2,5),(3,6)]` |
| 4 | 2 | pop (3,6): 6*1=6; pop (2,5): 5*2=10 | `[(0,1),(2,2)]` |
| 5 | 3 | - | `[(0,1),(2,2),(5,3)]` |

End flush: (0,1)->1*6=6, (2,2)->2*4=8, (5,3)->3*1=3. Max overall `10`.

### Complexity
- **Time:** O(n). Each bar is pushed once and popped at most once across the whole run.
- **Space:** O(n). The stack can hold every bar when heights are strictly increasing.

### Key concepts to review
- [[Monotonic Stack]] - increasing-height stack to find each bar's left/right boundaries (see [[05.DailyTemperatures]], [[06.CarFleet]]).
- [[Stack]] - the LIFO base structure storing pending bars.

### Common pitfalls
- Losing the inherited `start` when popping, which undercounts how far left a bar can extend.
- Forgetting the final flush of bars left on the stack (they extend to the array end).
- Off-by-one in the width `i - idx`; the current index `i` is the exclusive right boundary, not inclusive.
