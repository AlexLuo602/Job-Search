# 739. Daily Temperatures


Given an array of integers temperatures represents the daily temperatures, return an array answer such that answer[i] is the number of days you have to wait after the ith day to get a warmer temperature. If there is no future day for which this is possible, keep answer[i] == 0 instead.

 

**Example 1:**
```
Input: temperatures = [73,74,75,71,69,72,76,73]
Output: [1,1,4,2,1,1,0,0]
```
**Example 2:**
```
Input: temperatures = [30,40,50,60]
Output: [1,1,1,0]
```
**Example 3:**
```
Input: temperatures = [30,60,90]
Output: [1,1,0]
```

Constraints:

- 1 <= temperatures.length <= 10<sup>5</sup>
- 30 <= temperatures[i] <= 100

---

## Solution

### Intuition
For each day we want the distance to the next warmer day. A [[Monotonic Stack]] of indices, kept decreasing in temperature, lets us resolve that lazily: when today is warmer than the index on top, today is that index's answer. Each index is pushed and popped at most once, giving linear time.

### Approach
Keep a stack of indices whose temperatures are still waiting for a warmer day. For each day `i`, while the current temperature exceeds the temperature at the stack's top index, pop it and record `i - popped` as its wait. Then push `i`. Indices left on the stack keep their default answer of 0.

```python
class Solution:
    def dailyTemperatures(self, temperatures: list[int]) -> list[int]:
        res = [0] * len(temperatures)
        stack: list[int] = []                       # indices, temps strictly decreasing

        for i, temp in enumerate(temperatures):
            # today resolves every cooler day still on the stack
            while stack and temperatures[stack[-1]] < temp:
                prev = stack.pop()
                res[prev] = i - prev                # days waited
            stack.append(i)

        return res
```

> Store indices, not temperatures: the answer is a day-count, so we need positions to compute `i - prev`.

### Walkthrough
Trace `temperatures = [73,74,75,71,69,72,76,73]`:

| i | temp | pops (set res) | stack (indices) |
|---|------|----------------|-----------------|
| 0 | 73 | - | `[0]` |
| 1 | 74 | 0 -> res[0]=1 | `[1]` |
| 2 | 75 | 1 -> res[1]=1 | `[2]` |
| 3 | 71 | - | `[2,3]` |
| 4 | 69 | - | `[2,3,4]` |
| 5 | 72 | 4 -> res[4]=1, 3 -> res[3]=2 | `[2,5]` |
| 6 | 76 | 5 -> res[5]=1, 2 -> res[2]=4 | `[6]` |
| 7 | 73 | - | `[6,7]` |

Output `[1,1,4,2,1,1,0,0]`.

### Complexity
- **Time:** O(n). Despite the nested loop, each index is pushed and popped at most once, so total work is linear.
- **Space:** O(n). A strictly decreasing input never pops, so the stack can hold all indices.

### Key concepts to review
- [[Monotonic Stack]] - maintain a decreasing stack to find the next greater element efficiently (see [[06.CarFleet]], [[07.LargestRectangleInHistogram]]).
- [[Stack]] - the underlying LIFO structure.

### Common pitfalls
- Pushing temperatures instead of indices, losing the information needed to compute the gap.
- Using `<=` instead of `<` in the pop condition; equal temperatures are not warmer, so they must not resolve.
- Forgetting that indices remaining on the stack keep answer 0 (no future warmer day).
