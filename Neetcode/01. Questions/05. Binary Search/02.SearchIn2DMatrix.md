# 74. Search a 2D Matrix


Write an efficient algorithm that searches for a value target in an m x n integer matrix matrix. This matrix has the following properties:

Integers in each row are sorted from left to right.
The first integer of each row is greater than the last integer of the previous row.
 

**Example 1:**

![[search-a-2d-matrix-example-1.svg]]

```
Input: matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]], target = 3
Output: true
```
**Example 2:**
```
Input: matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]], target = 13
Output: false
```

Constraints:

- m == matrix.length
- n == matrix[i].length
- 1 <= m, n <= 100
- -10<sup>4</sup> <= matrix[i][j], target <= 10<sup>4</sup>

---

## Solution

### Intuition
Because each row is sorted and every row starts above the previous row's end, the whole matrix is one sorted sequence laid out in row-major order. So we can treat the `m x n` grid as a virtual sorted array of length `m * n` and run a single [[0.BinarySearchGuide|Binary Search]], mapping a flat index back to `(row, col)` with division and modulo.

### Approach 1: Staircase search (for contrast)
Start at the top-right corner. Moving left decreases the value, moving down increases it, so each step eliminates a row or a column. Correct and simple, but O(m + n), which does not use the stronger "first of each row > last of previous row" guarantee.

```python
class Solution:
    def searchMatrix(self, matrix: list[list[int]], target: int) -> bool:
        m, n = len(matrix), len(matrix[0])
        row, col = 0, n - 1  # top-right corner
        while row < m and col >= 0:
            val = matrix[row][col]
            if val == target:
                return True
            elif val < target:
                row += 1   # current row too small, go down
            else:
                col -= 1   # current col too big, go left
        return False
```

### Approach 2: Optimal binary search
Index the matrix as a flat sorted array. For flat index `mid`, the cell is `matrix[mid // n][mid % n]` where `n` is the number of columns.

```python
class Solution:
    def searchMatrix(self, matrix: list[list[int]], target: int) -> bool:
        m, n = len(matrix), len(matrix[0])
        lo, hi = 0, m * n - 1  # inclusive flat bounds

        while lo <= hi:
            mid = lo + (hi - lo) // 2
            val = matrix[mid // n][mid % n]  # flat index -> (row, col)
            if val == target:
                return True
            elif val < target:
                lo = mid + 1
            else:
                hi = mid - 1

        return False
```

> The mapping uses `n` (column count), not `m`. `row = mid // n` and `col = mid % n` only line up with row-major order when you divide and mod by the width of a row.

### Walkthrough
`matrix = [[1,3,5,7],[10,11,16,20],[23,30,34,60]]`, `target = 3`, so `n = 4`.

| lo | hi | mid | (row, col) | val | compare | action |
|----|----|-----|-----------|-----|---------|--------|
| 0 | 11 | 5 | (1, 1) | 11 | 11 > 3 | hi = 4 |
| 0 | 4 | 2 | (0, 2) | 5 | 5 > 3 | hi = 1 |
| 0 | 1 | 0 | (0, 0) | 1 | 1 < 3 | lo = 1 |
| 1 | 1 | 1 | (0, 1) | 3 | 3 == 3 | return True |

Output: `True`.

### Complexity
- **Time:** O(log(m*n)). One binary search over `m * n` virtual elements.
- **Space:** O(1). Only index variables.

### Key concepts to review
- [[0.BinarySearchGuide|Binary Search]] - treat a sorted grid as a flat sorted array and halve it; same template as [[01.BinarySearch]].
- [[Matrix Traversal]] - row-major flattening and the `mid // n`, `mid % n` index mapping.
- See [[04.SearchInRotatedSortedArray]] for another adapted binary search.

### Common pitfalls
- Dividing/modding by `m` (rows) instead of `n` (columns) corrupts the index mapping.
- Reading `matrix[0]` without checking the matrix is non-empty (safe here given constraints, but worth a guard in general).
- Using the staircase approach and assuming it is O(log) - it is O(m + n).
