# 704. Binary Search

Given an array of integers nums which is sorted in ascending order, and an integer target, write a function to search target in nums. If target exists, then return its index. Otherwise, return -1.

You must write an algorithm with O(log n) runtime complexity.

 

**Example 1:**
```
Input: nums = [-1,0,3,5,9,12], target = 9
Output: 4
Explanation: 9 exists in nums and its index is 4
```
**Example 2:**
```
Input: nums = [-1,0,3,5,9,12], target = 2
Output: -1
Explanation: 2 does not exist in nums so return -1
```

Constraints:

- 1 <= nums.length <= 104
- -104 < nums[i], target < 104
- All the integers in nums are unique.
- nums is sorted in ascending order.

---

## Solution

### Intuition
The array is sorted, so we can discard half the search space on every comparison. [[0.BinarySearchGuide|Binary Search]] maintains a window `[lo, hi]` that must contain the target if it exists. We compare the middle element to the target and shrink the window toward the side that could still hold the answer.

### Approach
Use inclusive bounds `lo = 0`, `hi = n - 1`. While the window is non-empty, check the midpoint and move `lo` or `hi` past `mid` to avoid rechecking it.

```python
class Solution:
    def search(self, nums: list[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1  # inclusive bounds

        while lo <= hi:
            mid = lo + (hi - lo) // 2  # avoids overflow in fixed-width ints
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                lo = mid + 1  # target is in the right half
            else:
                hi = mid - 1  # target is in the left half

        return -1
```

> With inclusive bounds, the loop condition must be `lo <= hi` (not `<`), otherwise a single-element window is never checked. Moving to `mid + 1` / `mid - 1` (not `mid`) guarantees progress and prevents an infinite loop.

### Walkthrough
`nums = [-1,0,3,5,9,12]`, `target = 9`.

| lo | hi | mid | nums[mid] | compare | action |
|----|----|-----|-----------|---------|--------|
| 0 | 5 | 2 | 3 | 3 < 9 | lo = 3 |
| 3 | 5 | 4 | 9 | 9 == 9 | return 4 |

Output: `4`.

### Complexity
- **Time:** O(log n). The window halves each iteration.
- **Space:** O(1). Only a few index variables.

### Key concepts to review
- [[0.BinarySearchGuide|Binary Search]] - halve the search space using inclusive bounds; the canonical pattern that every sibling here builds on.
- [[Divide and Conquer]] - each step solves a subproblem half the size; binary search is its simplest form.
- See also [[02.SearchIn2DMatrix]] and [[04.SearchInRotatedSortedArray]] for variations on this template.

### Common pitfalls
- Using `lo < hi` with inclusive bounds skips checking the last candidate.
- Computing `mid = (lo + hi) // 2` can overflow in fixed-width languages; `lo + (hi - lo) // 2` is the safe habit.
- Forgetting to move past `mid` (e.g. `lo = mid`) causes an infinite loop.
