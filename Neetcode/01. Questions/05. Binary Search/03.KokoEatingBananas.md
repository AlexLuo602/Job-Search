# 875. Koko Eating Bananas


Koko loves to eat bananas. There are n piles of bananas, the ith pile has piles[i] bananas. The guards have gone and will come back in h hours.

Koko can decide her bananas-per-hour eating speed of k. Each hour, she chooses some pile of bananas and eats k bananas from that pile. If the pile has less than k bananas, she eats all of them instead and will not eat any more bananas during this hour.

Koko likes to eat slowly but still wants to finish eating all the bananas before the guards return.

Return the minimum integer k such that she can eat all the bananas within h hours.

 

**Example 1:**
```
Input: piles = [3,6,7,11], h = 8
Output: 4
```
**Example 2:**
```
Input: piles = [30,11,23,4,20], h = 5
Output: 30
```
**Example 3:**
```
Input: piles = [30,11,23,4,20], h = 6
Output: 23
```

Constraints:

- 1 <= piles.length <= 10<sup>4</sup>
- piles.length <= h <= 10<sup>9</sup>
- 1 <= piles[i] <= 10<sup>9</sup>

---

## Solution

### Intuition
We are not searching an array, we are binary searching on the answer itself: the eating speed `k`. The feasibility "can Koko finish within `h` hours at speed `k`" is monotonic, if speed `k` works then any faster speed also works. That monotonic boundary is exactly what [[0.BinarySearchGuide|Binary Search]] locates, so we search the speed range `[1, max(piles)]` for the smallest feasible `k`.

### Approach
The candidate speeds run from `1` (slowest sensible) to `max(piles)` (any faster than this finishes each pile in one hour, so it never helps). For a given speed `k`, the hours needed for a pile is `ceil(pile / k)`. Binary search for the leftmost `k` whose total hours `<= h`.

```python
from math import ceil

class Solution:
    def minEatingSpeed(self, piles: list[int], h: int) -> int:
        def hours_at(k: int) -> int:
            return sum(ceil(p / k) for p in piles)  # ceil: a partial pile still costs an hour

        lo, hi = 1, max(piles)        # speed range; max(piles) always finishes in time
        result = hi                   # fallback: the fastest speed is always feasible

        while lo <= hi:
            k = lo + (hi - lo) // 2
            if hours_at(k) <= h:      # feasible -> try to go slower
                result = k
                hi = k - 1
            else:                     # too slow -> must speed up
                lo = k + 1

        return result
```

> This is binary search on the answer, not on an input array. It works only because feasibility is monotonic in `k`. When a speed is feasible we move `hi` left to seek an even smaller answer, which is what makes it find the *minimum*.

### Walkthrough
`piles = [3,6,7,11]`, `h = 8`. Range `[1, 11]`.

| lo | hi | k | hours_at(k) | <= 8? | action |
|----|----|---|-------------|-------|--------|
| 1 | 11 | 6 | 1+1+2+2 = 6 | yes | result=6, hi=5 |
| 1 | 5 | 3 | 1+2+3+4 = 10 | no | lo=4 |
| 4 | 5 | 4 | 1+2+2+3 = 8 | yes | result=4, hi=3 |
| 4 | 3 |  |  |  | loop ends |

Output: `4`.

### Complexity
- **Time:** O(n log m), where `n = len(piles)` and `m = max(piles)`. Each feasibility check is O(n) and there are O(log m) of them.
- **Space:** O(1). The generator does not materialize a list.

### Key concepts to review
- [[0.BinarySearchGuide|Binary Search]] - binary search on the answer space using a monotonic feasibility predicate, not on a sorted array; contrast with [[01.BinarySearch]].
- [[0.GreedyGuide|Greedy]] - the feasibility check greedily computes minimum hours pile by pile.
- See [[04.SearchInRotatedSortedArray]] for binary search adapted to a different structure.

### Common pitfalls
- Starting `lo` at `0` causes a division by zero in the feasibility check; speed must be at least `1`.
- Forgetting the ceiling: any leftover bananas in a pile still consume a full hour.
- Moving the wrong bound when feasible. To find the minimum, a feasible `k` should pull `hi` left, not `lo` right.
