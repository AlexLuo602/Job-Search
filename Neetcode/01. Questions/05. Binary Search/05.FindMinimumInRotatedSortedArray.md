# 153. Find Minimum in Rotated Sorted Array


Suppose an array of length n sorted in ascending order is rotated between 1 and n times. For example, the array nums = `[0,1,2,4,5,6,7]` might become:

- `[4,5,6,7,0,1,2]` if it was rotated 4 times.
- `[0,1,2,4,5,6,7]` if it was rotated 7 times.

Notice that rotating an array `[a[0], a[1], a[2], ..., a[n-1]]` 1 time results in the array `[a[n-1], a[0], a[1], a[2], ..., a[n-2]]`.

Given the sorted rotated array nums of unique elements, return the minimum element of this array.

You must write an algorithm that runs in O(log n) time.

 

**Example 1:**

![[find-minimum-in-rotated-sorted-array-example-1.svg]]

```
Input: nums = [3,4,5,1,2]
Output: 1
Explanation: The original array was [1,2,3,4,5] rotated 3 times.
```
**Example 2:**
```
Input: nums = [4,5,6,7,0,1,2]
Output: 0
Explanation: The original array was [0,1,2,4,5,6,7] and it was rotated 4 times.
```
**Example 3:**
```
Input: nums = [11,13,15,17]
Output: 11
Explanation: The original array was [11,13,15,17] and it was rotated 4 times. 
```

Constraints:

- n == nums.length
- 1 <= n <= 5000
- -5000 <= nums[i] <= 5000
- All the integers of nums are unique.
- nums is sorted and rotated between 1 and n times.

## Solution

### Intuition
The minimum is the single "drop" point where the rotation wraps around, the only place where an element is smaller than its predecessor. By comparing `nums[mid]` to `nums[hi]` we learn which side of `mid` that drop lives on: if `nums[mid] > nums[hi]` the minimum is strictly to the right, otherwise it is at `mid` or to its left. This is [[0.BinarySearchGuide|Binary Search]] converging on the pivot.

### Approach
Use inclusive bounds and compare against the right end. Crucially, when `nums[mid] <= nums[hi]` we set `hi = mid` (not `mid - 1`) because `mid` itself could be the minimum. The loop ends when `lo == hi`, pointing at the answer.

```python
class Solution:
    def findMin(self, nums: list[int]) -> int:
        lo, hi = 0, len(nums) - 1

        while lo < hi:                  # stop when the window is a single element
            mid = lo + (hi - lo) // 2
            if nums[mid] > nums[hi]:
                lo = mid + 1            # min is strictly right of mid
            else:
                hi = mid                # min is at mid or to its left; keep mid

        return nums[lo]                 # lo == hi == index of the minimum
```

> Compare to `nums[hi]`, not `nums[lo]`. Comparing to `nums[lo]` is ambiguous on a non-rotated (already sorted) window. Also note `hi = mid` (not `mid - 1`), since discarding `mid` could discard the minimum itself. This is why the loop uses `lo < hi`, not `lo <= hi`.

### Walkthrough
`nums = [4,5,6,7,0,1,2]`.

| lo | hi | mid | nums[mid] | nums[hi] | compare | action |
|----|----|-----|-----------|----------|---------|--------|
| 0 | 6 | 3 | 7 | 2 | 7 > 2 | lo = 4 |
| 4 | 6 | 5 | 1 | 2 | 1 <= 2 | hi = 5 |
| 4 | 5 | 4 | 0 | 1 | 0 <= 1 | hi = 4 |
| 4 | 4 |  |  |  |  | loop ends |

Output: `nums[4] = 0`.

### Complexity
- **Time:** O(log n). The window halves each iteration.
- **Space:** O(1). Only index variables.

### Key concepts to review
- [[0.BinarySearchGuide|Binary Search]] - converge on a boundary with `lo < hi` and `hi = mid`, a different invariant than the exact-match template in [[01.BinarySearch]].
- See [[04.SearchInRotatedSortedArray]] - same rotated structure, locating a target instead of the pivot.

### Common pitfalls
- Comparing `nums[mid]` to `nums[lo]` instead of `nums[hi]` mishandles the already-sorted case.
- Writing `hi = mid - 1` can skip over the minimum; the assignment must be `hi = mid`.
- Using `lo <= hi` with `hi = mid` loops forever when `lo == hi`; the converging form needs `lo < hi`.
