# 4. Median of Two Sorted Arrays


Given two sorted arrays nums1 and nums2 of size m and n respectively, return the median of the two sorted arrays.

The overall run time complexity should be O(log (m+n)).

 

**Example 1:**
```
Input: nums1 = [1,3], nums2 = [2]
Output: 2.00000
Explanation: merged array = [1,2,3] and median is 2.
```

**Example 2:**
```
Input: nums1 = [1,2], nums2 = [3,4]
Output: 2.50000
Explanation: merged array = [1,2,3,4] and median is (2 + 3) / 2 = 2.5.
```

Constraints:
- nums1.length == m
- nums2.length == n
- 0 <= m <= 1000
- 0 <= n <= 1000
- 1 <= m + n <= 2000
- -10<sup>6</sup> <= nums1[i], nums2[i] <= 10<sup>6</sup>

---

## Solution

### Intuition
The median splits the combined elements into a left half and a right half of equal size where every left element is `<=` every right element. We do not need to merge: we only need to decide how many elements of `nums1` belong to the left half. Binary searching that single count over the smaller array, a [[Divide and Conquer]] use of [[0.BinarySearchGuide|Binary Search]], finds the correct partition in O(log(min(m, n))).

### Approach 1: Merge (for contrast)
Merge both arrays and pick the middle element(s). Simple and correct but O(m + n) time and O(m + n) space, which fails the required O(log(m + n)) bound.

### Approach 2: Optimal partition search
Binary search on `nums1` for the partition index `i`. The matching index in `nums2` is `j = half - i`, where `half = (m + n + 1) // 2`. A partition is valid when the largest left element of each array is `<=` the smallest right element of the other. Use infinities at the edges so out-of-range partitions still compare correctly.

```python
class Solution:
    def findMedianSortedArrays(self, nums1: list[int], nums2: list[int]) -> float:
        # Always binary search over the smaller array -> O(log(min(m, n)))
        if len(nums1) > len(nums2):
            nums1, nums2 = nums2, nums1

        m, n = len(nums1), len(nums2)
        total = m + n
        half = (total + 1) // 2          # size of the left half (left gets the extra when odd)
        lo, hi = 0, m                     # i = number of nums1 elements in the left half

        while lo <= hi:
            i = lo + (hi - lo) // 2
            j = half - i

            # use +/- infinity for the missing edge elements
            left1  = nums1[i - 1] if i > 0 else float("-inf")
            right1 = nums1[i]     if i < m else float("inf")
            left2  = nums2[j - 1] if j > 0 else float("-inf")
            right2 = nums2[j]     if j < n else float("inf")

            if left1 <= right2 and left2 <= right1:   # valid partition found
                if total % 2:                          # odd: median is max of left side
                    return max(left1, left2)
                # even: average the two middle elements
                return (max(left1, left2) + min(right1, right2)) / 2
            elif left1 > right2:                        # took too many from nums1
                hi = i - 1
            else:                                      # took too few from nums1
                lo = i + 1

        return 0.0  # unreachable for valid input
```

> Two subtleties: binary search the *smaller* array so `j` never goes negative, and use `+/- inf` sentinels at the boundaries so the partition comparison stays valid when one side is empty. `half = (total + 1) // 2` puts the extra element on the left, so the odd-case median is simply `max(left1, left2)`.

### Complexity
- **Time:** O(log(min(m, n))). Binary search over the smaller array only.
- **Space:** O(1). Only a handful of scalars (the swap rebinds references, no copy).

### Key concepts to review
- [[Divide and Conquer]] - reduce the median to choosing one partition count, then halve the candidate range; the heart of this solution.
- [[0.BinarySearchGuide|Binary Search]] - search the partition index rather than a value; advanced cousin of [[01.BinarySearch]].

### Common pitfalls
- Binary searching the larger array can make `j = half - i` negative; always search the smaller one.
- Forgetting the `+/- inf` sentinels causes index errors or wrong comparisons at the partition edges.
- Mixing up the odd/even median formula, and off-by-one in `half`, which decides whether the left half holds the extra element.
