# 981. Time Based Key-Value Store

Design a time-based key-value data structure that can store multiple values for the same key at different time stamps and retrieve the key's value at a certain timestamp.

Implement the TimeMap class:
- `TimeMap()` Initializes the object of the data structure.
- `void set(String key, String value, int timestamp)` Stores the key key with the value value at the given time timestamp.
- `String get(String key, int timestamp)` Returns a value such that set was called previously, with timestamp_prev <= timestamp. If there are multiple such values, it returns the value associated with the largest timestamp_prev. If there are no values, it returns "".
 

**Example 1:**

![[time-based-key-value-store-example-1.svg]]

```
Input
["TimeMap", "set", "get", "get", "set", "get", "get"]
[[], ["foo", "bar", 1], ["foo", 1], ["foo", 3], ["foo", "bar2", 4], ["foo", 4], ["foo", 5]]
Output
[null, null, "bar", "bar", null, "bar2", "bar2"]

Explanation
TimeMap timeMap = new TimeMap();
timeMap.set("foo", "bar", 1);  // store the key "foo" and value "bar" along with timestamp = 1.
timeMap.get("foo", 1);         // return "bar"
timeMap.get("foo", 3);         // return "bar", since there is no value corresponding to foo at timestamp 3 and timestamp 2, then the only value is at timestamp 1 is "bar".
timeMap.set("foo", "bar2", 4); // store the key "foo" and value "bar2" along with timestamp = 4.
timeMap.get("foo", 4);         // return "bar2"
timeMap.get("foo", 5);         // return "bar2"
```

Constraints:

- 1 <= key.length, value.length <= 100
- key and value consist of lowercase English letters and digits.
- 1 <= timestamp <= 107
- All the timestamps timestamp of set are strictly increasing.
- At most 2 * 105 calls will be made to set and get.

---

## Solution

### Intuition
Store each key's history as a list of `(timestamp, value)` pairs. Because the problem guarantees timestamps for `set` arrive strictly increasing, each list is already sorted by timestamp, so no sorting is needed. A `get(key, t)` is then a [[0.BinarySearchGuide|Binary Search]] for the rightmost entry with `timestamp <= t`, the floor of `t`.

### Approach
Back the store with a [[Hash Map]] from key to a list of `(timestamp, value)`. For `get`, binary search for the largest index whose timestamp does not exceed the query, returning the corresponding value or `""` if none qualifies.

```python
class TimeMap:
    def __init__(self) -> None:
        self.store: dict[str, list[tuple[int, str]]] = {}  # key -> [(timestamp, value)]

    def set(self, key: str, value: str, timestamp: int) -> None:
        # timestamps arrive strictly increasing, so append keeps the list sorted
        self.store.setdefault(key, []).append((timestamp, value))

    def get(self, key: str, timestamp: int) -> str:
        entries = self.store.get(key, [])
        result = ""
        lo, hi = 0, len(entries) - 1

        while lo <= hi:                       # find rightmost entry with ts <= timestamp
            mid = lo + (hi - lo) // 2
            if entries[mid][0] <= timestamp:
                result = entries[mid][1]      # candidate; keep searching right for a later one
                lo = mid + 1
            else:
                hi = mid - 1

        return result
```

> This is a "find the floor" binary search, not exact match. On a `<=` hit we record the value and keep moving `lo` right to find a *later* qualifying timestamp; we never return early. Python's `bisect.bisect_right(keys, timestamp) - 1` gives the same index if you keep a parallel list of keys.

### Walkthrough
After `set("foo","bar",1)` and `set("foo","bar2",4)`, the list is `[(1,"bar"),(4,"bar2")]`. Call `get("foo", 3)`.

| lo | hi | mid | entries[mid][0] | <= 3? | action | result |
|----|----|-----|------------------|-------|--------|--------|
| 0 | 1 | 0 | 1 | yes | result="bar", lo=1 | "bar" |
| 1 | 1 | 1 | 4 | no | hi=0 | "bar" |
| 1 | 0 |  |  |  | loop ends | "bar" |

Output: `"bar"`.

### Complexity
- **Time:** `set` is O(1) amortized (append). `get` is O(log n) for n entries under that key.
- **Space:** O(total number of set calls), storing every `(timestamp, value)` pair.

### Key concepts to review
- [[0.BinarySearchGuide|Binary Search]] - the floor variant (rightmost timestamp `<= t`); compare with the exact-match template in [[01.BinarySearch]].
- [[Hash Map]] - O(1) lookup from key to its time-ordered history list.
- See [[03.KokoEatingBananas]] for another "search for a boundary" use of binary search.

### Common pitfalls
- Returning early on an exact timestamp match misses the requirement to handle the floor; always continue right on `<=`.
- Re-sorting on every `set` is wasteful given timestamps are already strictly increasing, just append.
- Returning `""` requires handling both the missing-key case and the "all timestamps too large" case.
