# 191. Number of 1 Bits

Write a function that takes an unsigned integer and returns the number of '1' bits it has (also known as the Hamming weight).

Note:

Note that in some languages, such as Java, there is no unsigned integer type. In this case, the input will be given as a signed integer type. It should not affect your implementation, as the integer's internal binary representation is the same, whether it is signed or unsigned.
In Java, the compiler represents the signed integers using 2's complement notation. Therefore, in Example 3, the input represents the signed integer. -3.
**Example 1:**

```
Input: n = 00000000000000000000000000001011
Output: 3
Explanation: The input binary string 00000000000000000000000000001011 has a total of three '1' bits.
```
**Example 2:**

```
Input: n = 00000000000000000000000010000000
Output: 1
Explanation: The input binary string 00000000000000000000000010000000 has a total of one '1' bit.
```
**Example 3:**

```
Input: n = 11111111111111111111111111111101
Output: 31
Explanation: The input binary string 11111111111111111111111111111101 has a total of thirty one '1' bits.
```

Constraints:

- The input must be a binary string of length 32.
 

### Follow up: If this function is called many times, how would you optimize it?

---

## Solution

### Intuition
The trick `n & (n - 1)` clears the lowest set bit of `n` in one operation. Each iteration of the loop drops exactly one 1-bit, so the number of iterations equals the number of 1-bits. This is the Brian Kernighan algorithm and is more efficient than checking every bit position.

### Approach 1: Check every bit (naive)
Iterate 32 times, checking `n & 1` and right-shifting. Always O(32) time regardless of how many bits are set.

### Approach 2: Brian Kernighan - drop lowest set bit (optimal)
Loop only as many times as there are 1-bits by clearing the lowest set bit each iteration.

```python
class Solution:
    def hammingWeight(self, n: int) -> int:
        count = 0
        while n:
            n &= n - 1  # clears the lowest set bit; e.g. 1100 & 1011 = 1000
            count += 1
        return count
```

> `n - 1` flips all bits from the lowest set bit downward, so ANDing with `n` zeroes out that lowest set bit while leaving higher bits intact. In Python, `n` is arbitrary precision, but since the problem guarantees a 32-bit input, the loop still terminates in at most 32 iterations.

### Walkthrough
`n = 11` (binary `1011`)

| Iteration | n (binary) | n - 1 (binary) | n & (n-1) | count |
|-----------|-----------|----------------|-----------|-------|
| 1         | 1011      | 1010           | 1010      | 1     |
| 2         | 1010      | 1001           | 1000      | 2     |
| 3         | 1000      | 0111           | 0000      | 3     |

Result: 3 one-bits.

### Complexity
- **Time:** O(k) where k is the number of 1-bits (at most 32 for a 32-bit integer).
- **Space:** O(1). Only a counter variable.

### Common pitfalls
- Using `n >> 1` (right shift) in a loop works in Python for non-negative ints, but for signed negative Java ints you need unsigned right shift `>>>`. Python avoids this since its integers are arbitrary precision and always sign-extend.
- The naive 32-iteration approach works for both positive and negative inputs in any language; the Kernighan trick also works in Python without any masking because Python's `&` treats integers as having infinite precision in two's complement.
- Do not use `n = n & (n - 1)` and then check `n == 0` as the loop condition without first incrementing; the count would be off by one.
