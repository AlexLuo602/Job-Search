# 190. Reverse Bits

Reverse bits of a given 32 bits unsigned integer.

Note:

> Note that in some languages, such as Java, there is no unsigned integer type. In this case, both input and output will be given as a signed integer type. They should not affect your implementation, as the integer's internal binary representation is the same, whether it is signed or unsigned.
In Java, the compiler represents the signed integers using 2's complement notation. Therefore, in Example 2 above, the input represents the signed integer -3 and the output represents the signed integer -1073741825.
**Example 1:**

```
Input: n = 00000010100101000001111010011100
Output:    964176192 (00111001011110000010100101000000)
Explanation: The input binary string 00000010100101000001111010011100 represents the unsigned integer 43261596, so return 964176192 which its binary representation is 00111001011110000010100101000000.
```
**Example 2:**

```
Input: n = 11111111111111111111111111111101
Output:   3221225471 (10111111111111111111111111111111)
Explanation: The input binary string 11111111111111111111111111111101 represents the unsigned integer 4294967293, so return 3221225471 which its binary representation is 10111111111111111111111111111111.
```

Constraints:

- The input must be a binary string of length 32

## Solution

### Intuition
Iterate exactly 32 times. In each iteration, extract bit `i` from the input (by right-shifting and masking), then place it at position `31 - i` in the result (by left-shifting and OR-ing). This is a pure [[0.BitManipulationGuide|Bit Manipulation]] approach that mirrors the bit positions around the center of the 32-bit word.

### Approach: Bit-by-bit reversal (32 iterations)

```python
class Solution:
    def reverseBits(self, n: int) -> int:
        res = 0
        for i in range(32):
            bit = (n >> i) & 1        # extract bit at position i
            res |= bit << (31 - i)    # place it at the mirror position 31 - i
        return res
```

> Python integers are arbitrary precision, so `res` could theoretically accumulate beyond 32 bits if the input were larger. However, since `n` is a valid 32-bit unsigned integer and we only place bits at positions 0-31, the result is always within the unsigned 32-bit range [0, 2^32 - 1]. No masking is needed here.

### Walkthrough

Use the 4-bit input `n = 0b1011`. Each source position `i` moves to position `3 - i`:

```text
source position i:       3  2  1  0
source bit:              1  0  1  1
destination 3 - i:       0  1  2  3

result position:         3  2  1  0
result bit:              1  1  0  1
```

The loop builds that result one bit at a time:

| i  | bit extracted (n >> i) & 1 | placed at 3 - i | res (binary) |
|----|---------------------------|-----------------|--------------|
| 0  | 1                         | 3               | 1000         |
| 1  | 1                         | 2               | 1100         |
| 2  | 0                         | 1               | 1100         |
| 3  | 1                         | 0               | 1101         |

The 4-bit result is `1101`. For the full problem, the destination is `31 - i`, and the loop runs 32 times.

### Complexity
- **Time:** O(1). Exactly 32 iterations, a fixed constant.
- **Space:** O(1). Only `res` and `bit` are needed.

### Key concepts to review
- [[0.BitManipulationGuide|Bit Manipulation]] - right shift to extract a bit, left shift to position it, OR to accumulate.
- [[Complement Pattern]] - the mirror index `31 - i` pairs the MSB and LSB positions.
- See siblings: [[02.NumberOf1Bits]] (also works bit by bit), [[01.SingleNumber]].

### Common pitfalls
- In Java, the sign bit can cause issues with right-shifting signed integers (use `>>>` for unsigned right shift). Python's `>>` on a negative number sign-extends indefinitely, but since the problem provides a 32-bit input as a Python `int`, this is not an issue in practice.
- Forgetting that the loop must run exactly 32 times, not until `n == 0`, because leading zeros in the input become trailing 1-positions that must be placed correctly.
- Confusing `|=` (OR-accumulate) with `+=`; using `+=` would double-count bits that land at positions already set.
