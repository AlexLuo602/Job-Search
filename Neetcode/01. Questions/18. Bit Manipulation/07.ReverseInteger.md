# 7. Reverse Integer

Given a signed 32-bit integer x, return x with its digits reversed. If reversing causes the value to go outside the 32-bit signed integer range [-2^31, 2^31 - 1], return 0.
**Example 1:**

```
Input: x = 123
Output: 321
```
**Example 2:**

```
Input: x = -123
Output: -321
```
**Example 3:**

```
Input: x = 120
Output: 21
```

Constraints:
- -2^31 <= x <= 2^31 - 1

---

## Solution

### Intuition
Extract digits one at a time using modulo and integer division, building the reversed number by multiplying the accumulator by 10 before adding each new digit. Because Python integers are arbitrary precision, there is no native 32-bit overflow; instead, check the bounds explicitly before returning. The sign is handled automatically because Python's `%` on a negative number returns a non-negative remainder, but this can be tricky, so working with `abs(x)` and reattaching the sign is cleaner.

### Approach: Digit-by-digit reversal with explicit 32-bit overflow check

```python
class Solution:
    def reverse(self, x: int) -> int:
        MIN = -(1 << 31)      # -2^31
        MAX = (1 << 31) - 1   # 2^31 - 1

        sign = -1 if x < 0 else 1
        x = abs(x)

        res = 0
        while x:
            digit = x % 10    # extract the last digit
            x //= 10          # remove the last digit
            res = res * 10 + digit  # shift result left and append digit

        res *= sign  # reattach sign

        if res < MIN or res > MAX:
            return 0
        return res
```

> In Java/C, overflow is detected mid-loop by checking `res > Integer.MAX_VALUE / 10` before multiplying. In Python, this guard is unnecessary because integers never overflow; a single bounds check after the loop is sufficient and simpler.

### Walkthrough
`x = -123`:

| Step      | x   | digit | res  |
|-----------|-----|-------|------|
| init      | 123 | -     | 0    |
| iter 1    | 12  | 3     | 3    |
| iter 2    | 1   | 2     | 32   |
| iter 3    | 0   | 1     | 321  |

Apply sign: `321 * -1 = -321`. Check bounds: within [-2^31, 2^31-1]. Return `-321`.

### Complexity
- **Time:** O(log x). The number of digits in x is log10(x), so the loop runs O(log x) times.
- **Space:** O(1). Only `res`, `sign`, and `digit` are used.

### Key concepts to review
- [[0.BitManipulationGuide|Bit Manipulation]] - using `1 << 31` to express 32-bit integer bounds without hardcoding magic numbers.
- [[Complement Pattern]] - two's complement defines the signed 32-bit range; the problem requires clamping to it.

### Common pitfalls
- Python's `%` operator for negative numbers: `-123 % 10` returns `7`, not `-3`, because Python's modulo is always non-negative. This is why separating the sign with `abs()` first is cleaner and avoids surprises.
- In Java, overflow must be caught before it happens (pre-multiplication guard). In Python, just check bounds at the end.
- Trailing zeros: `x = 120` reverses to `021 = 21`. The algorithm handles this naturally because `0 * 10 + 0` at the first step just accumulates a 0, and the leading zero disappears once the next digit makes `res` non-trivial. Actually for `120`: digits extracted are 0, 2, 1, giving `res = 0`, `2`, `21`. Correct.
- Do not forget to return `0` (not just skip the return) when the reversed value is out of range.
