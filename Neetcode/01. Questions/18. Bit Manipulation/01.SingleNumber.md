# 136. Single Number


Given a non-empty array of integers nums, every element appears twice except for one. Find that single one.

You must implement a solution with a linear runtime complexity and use only constant extra space.
**Example 1:**

```
Input: nums = [2,2,1]
Output: 1
```
**Example 2:**

```
Input: nums = [4,1,2,1,2]
Output: 4
```
**Example 3:**

```
Input: nums = [1]
Output: 1
```

Constraints:

- 1 <= nums.length <= 3 * 104
- -3 * 104 <= nums[i] <= 3 * 104
- Each element in the array appears twice except for one element which appears only once.

---

## Solution

### Intuition
[[0.BitManipulationGuide|Bit Manipulation]] via XOR is the key insight here. XOR of a number with itself is 0, and XOR with 0 returns the number unchanged. Because every element except one appears exactly twice, XORing all elements causes paired values to cancel out, leaving only the single element.

### Approach 1: Hash Map (naive)
Use a [[Hash Map]] or [[Set]] to count occurrences and return the element with count 1. This works in O(n) time but uses O(n) space, violating the constant-space constraint.

### Approach 2: XOR (optimal)
XOR every number together. Pairs cancel to 0; the lone element remains.

```python
class Solution:
    def singleNumber(self, nums: list[int]) -> int:
        res = 0
        for num in nums:
            res ^= num  # paired values cancel: a ^ a == 0, 0 ^ b == b
        return res
```

> XOR is both commutative and associative, so the order of elements does not matter. Python integers are arbitrary precision, but XOR on positive and negative ints still works correctly because Python uses two's complement internally for bit ops.

**XOR cancellation on `nums = [4, 1, 2, 1, 2]`** - matched pairs cancel to 0 and drop out; the unpaired value survives:

```text
input order:        100 ^ 001 ^ 010 ^ 001 ^ 010
regroup pairs:      100 ^ (001 ^ 001) ^ (010 ^ 010)
cancel pairs:       100 ^     000     ^     000
result:             100 = 4
```

### Walkthrough
`nums = [4, 1, 2, 1, 2]`

| Step | num | res (binary) | res (decimal) |
|------|-----|-------------|---------------|
| init | -   | 000         | 0             |
| 1    | 4   | 100         | 4             |
| 2    | 1   | 101         | 5             |
| 3    | 2   | 111         | 7             |
| 4    | 1   | 110         | 6             |
| 5    | 2   | 100         | 4             |

Result: 4. The two 1s and two 2s cancelled, leaving 4.

### Complexity
- **Time:** O(n). One pass through the array.
- **Space:** O(1). Only a single integer accumulator.

### Key concepts to review
- [[0.BitManipulationGuide|Bit Manipulation]] - XOR properties: identity (x ^ 0 = x), self-inverse (x ^ x = 0), commutativity, associativity.
- [[Complement Pattern]] - complement/inverse relationships in bit operations.
- [[Hash Map]] - the naive O(n) space alternative using frequency counting.
- See sibling: [[02.NumberOf1Bits]], [[05.MissingNumber]] (XOR also appears there).

### Common pitfalls
- Forgetting that XOR is order-independent; no need to sort.
- Trying to use addition/subtraction instead of XOR, which requires extra handling for the "appear twice" invariant.
- In Python, no 32-bit overflow concern here since we are not masking; arbitrary-precision ints are fine for XOR.
