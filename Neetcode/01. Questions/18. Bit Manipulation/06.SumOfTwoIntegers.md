# 371. Sum of Two Integers

Given two integers a and b, return the sum of the two integers without using the operators + and -.
**Example 1:**

```
Input: a = 1, b = 2
Output: 3
```
**Example 2:**

```
Input: a = 2, b = 3
Output: 5
```

Constraints:

- -1000 <= a, b <= 1000

---

## Solution

### Intuition
Binary addition works in two stages: XOR computes the sum without carries (bits differ), and AND followed by a left shift computes the carry bits. Repeating this until no carry remains simulates full addition using only [[0.BitManipulationGuide|Bit Manipulation]]. In Python, integers are arbitrary precision, so without a 32-bit mask the carry can propagate forever for negative numbers; masking to 32 bits is required.

### Approach: Simulate carry with XOR and AND

```python
class Solution:
    def getSum(self, a: int, b: int) -> int:
        MASK = 0xFFFFFFFF   # 32-bit mask to keep numbers within 32 bits
        MAX  = 0x7FFFFFFF   # max positive 32-bit signed integer

        while b & MASK:
            carry = (a & b) << 1  # carry bits: where both a and b have a 1
            a = a ^ b             # sum bits without carry: bits that differ
            b = carry
            # mask both to 32 bits to prevent infinite carry in Python
            a &= MASK
            b &= MASK

        # if a > MAX, it represents a negative number in 32-bit two's complement
        return a if a <= MAX else ~(a ^ MASK)
```

> Python integers are arbitrary precision, unlike Java/C where 32-bit overflow wraps automatically. Without the `MASK`, a negative carry would sign-extend infinitely and the loop would never terminate. The final conversion `~(a ^ MASK)` recovers the Python negative integer from the masked 32-bit two's complement representation.

### Walkthrough

Use `a = 3 (0011)` and `b = 5 (0101)`. XOR writes the sum without carries. AND finds positions where both inputs have `1`, and the left shift moves those carries to the next position.

```text
Iteration 1
a                 0011
b                 0101
                  ----
a XOR b           0110   sum without carries
(a AND b) << 1    0010   carry

Iteration 2
a                 0110
b                 0010
                  ----
a XOR b           0100
(a AND b) << 1    0100

Iteration 3
a                 0100
b                 0100
                  ----
a XOR b           0000
(a AND b) << 1    1000

Iteration 4
a                 0000
b                 1000
                  ----
a XOR b           1000
(a AND b) << 1    0000
```

The carry is now zero, so the result is `1000`, or `8`.

### Complexity
- **Time:** O(1). At most 32 iterations for a 32-bit integer (each carry shifts left, so after 32 steps the carry is zeroed out by the mask).
- **Space:** O(1). Only a and b are mutated in place.

### Common pitfalls
- Forgetting the 32-bit mask in Python: without it, the carry can grow without bound for negative inputs and the loop never terminates.
- The final sign correction `~(a ^ MASK)` is Python-specific. In Java/C, the 32-bit int wraps naturally and no correction is needed.
- Using `a += carry` or `b += sum_bits` reintroduces the forbidden `+` operator.
- The loop condition `while b & MASK` (not just `while b`) is necessary because after masking, `b` might still be a Python int with high bits set if carry propagated; masking the condition ensures we check only the 32-bit portion.
