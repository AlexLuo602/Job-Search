# 268. Missing Number


Given an array nums containing n distinct numbers in the range [0, n], return the only number in the range that is missing from the array.
**Example 1:**

```
Input: nums = [3,0,1]
Output: 2
Explanation: n = 3 since there are 3 numbers, so all numbers are in the range [0,3]. 2 is the missing number in the range since it does not appear in nums.
```
**Example 2:**

```
Input: nums = [0,1]
Output: 2
Explanation: n = 2 since there are 2 numbers, so all numbers are in the range [0,2]. 2 is the missing number in the range since it does not appear in nums.
```
**Example 3:**

```
Input: nums = [9,6,4,2,3,5,7,0,1]
Output: 8
Explanation: n = 9 since there are 9 numbers, so all numbers are in the range [0,9]. 8 is the missing number in the range since it does not appear in nums.
```

Constraints:

- n == nums.length
- 1 <= n <= 104
- 0 <= nums[i] <= n
- All the numbers of nums are unique.
 

### Follow up: Could you implement a solution using only O(1) extra space complexity and O(n) runtime complexity?

---

## Solution

### Intuition
Two clean O(n) / O(1) approaches exist. The Gauss sum approach computes the expected sum of 0..n and subtracts the actual sum; the difference is the missing number. Alternatively, the XOR approach (mirroring [[01.SingleNumber]]) XORs every index with every value - all present pairs cancel, leaving the missing number.

### Approach 1: Gauss sum
Expected sum of 0..n is `n * (n + 1) / 2`. Subtract the actual array sum; the remainder is the missing number.

```python
class Solution:
    def missingNumber(self, nums: list[int]) -> int:
        n = len(nums)
        return n * (n + 1) // 2 - sum(nums)  # Gauss formula minus actual sum
```

### Approach 2: XOR (bit manipulation)
XOR all indices 0..n with all values in nums. Each present number cancels with its matching index; only the missing number's index survives.

```python
class Solution:
    def missingNumber(self, nums: list[int]) -> int:
        res = len(nums)           # start with n (the last index that has no paired value yet)
        for i, num in enumerate(nums):
            res ^= i ^ num        # each present value cancels with its index
        return res
```

> Both approaches use O(1) extra space. The Gauss sum is slightly simpler to read. The XOR approach generalizes the [[01.SingleNumber]] pairing trick: each number in 0..n is XOR'd with itself once as an index and once as a value - except the missing number, which only appears as an index.

### Walkthrough
`nums = [3, 0, 1]`, n = 3. Gauss sum = 3*4/2 = 6. Actual sum = 3+0+1 = 4. Missing = 6 - 4 = **2**.

**Index/value XOR pairing for `nums = [3, 0, 1]`** - each present value cancels with its matching index; the index with no value pair is the missing number:

```text
indices 0 through 3:     000 ^ 001 ^ 010 ^ 011
array values:            011 ^ 000 ^ 001

regroup equal values:   (000 ^ 000) ^ (001 ^ 001) ^ (011 ^ 011) ^ 010
after cancellation:      000         ^ 000         ^ 000         ^ 010
result:                  010 = 2
```

XOR walkthrough:

| Step       | operation       | res    |
|------------|-----------------|--------|
| init       | res = 3         | 011    |
| i=0,num=3  | res ^= 0 ^ 3    | 000    |
| i=1,num=0  | res ^= 1 ^ 0    | 001    |
| i=2,num=1  | res ^= 2 ^ 1    | 010    |

Result: `010` = **2**.

### Complexity
- **Time:** O(n). One pass through the array for both approaches.
- **Space:** O(1). No auxiliary data structures.

### Key concepts to review
- [[0.BitManipulationGuide|Bit Manipulation]] - XOR pairing trick: values cancel when XOR'd with themselves.
- [[Complement Pattern]] - the Gauss sum uses the complement idea: expected minus actual.
- [[Prefix Sum]] - the Gauss formula is a closed-form prefix sum of 0..n.
- See siblings: [[01.SingleNumber]] (XOR cancellation), [[06.SumOfTwoIntegers]].

### Common pitfalls
- Integer overflow in languages like Java: `n * (n + 1)` can overflow a 32-bit int for large n. Use `long` or compute as `n / 2 * (n + 1)` to halve first. Python has arbitrary-precision ints, so this is not an issue.
- Using `range(n)` instead of `range(n + 1)` in the XOR approach misses the index n; compensate by initializing `res = n` as shown.
- The Gauss formula only works because all numbers in 0..n are distinct; it would give wrong answers if duplicates were present.
