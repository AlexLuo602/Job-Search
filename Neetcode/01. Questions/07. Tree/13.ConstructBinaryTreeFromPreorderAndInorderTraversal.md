# [105. Construct Binary Tree from Preorder and Inorder Traversal](https://leetcode.com/problems/construct-binary-tree-from-preorder-and-inorder-traversal/)


Given two integer arrays preorder and inorder where preorder is the preorder traversal of a binary tree and inorder is the inorder traversal of the same tree, construct and return the binary tree.

 

**Example 1:**

![[construct-binary-tree-example.svg]]

```
Input: preorder = [3,9,20,15,7], inorder = [9,3,15,20,7]
Output: [3,9,20,null,null,15,7]
```

**Example 2:**
```
Input: preorder = [-1], inorder = [-1]
Output: [-1]
```

Constraints:

- 1 <= preorder.length <= 3000
- inorder.length == preorder.length
- -3000 <= preorder[i], inorder[i] <= 3000
- preorder and inorder consist of unique values.
- Each value of inorder also appears in preorder.
- preorder is guaranteed to be the preorder traversal of the tree.
- inorder is guaranteed to be the inorder traversal of the tree.

---

## Solution

### Intuition
Preorder traversal visits the root first, so `preorder[0]` is always the current subtree's root. In the inorder array, everything to the left of this root value belongs to the left subtree, and everything to the right belongs to the right subtree. This gives us the split point: we recursively rebuild the tree using [[Divide and Conquer]], slicing both arrays based on where the root falls in inorder.

### Approach: Optimal
Build a [[Hash Map]] from value to inorder index for O(1) root lookups. Use a preorder index pointer (advanced with each recursive call) and inorder bounds to define each subtree's slice without copying arrays.

```python
# TreeNode definition:
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def buildTree(self, preorder: list[int], inorder: list[int]) -> Optional['TreeNode']:
        # Map each value to its index in inorder for O(1) lookup
        inorder_index = {val: i for i, val in enumerate(inorder)}
        self.pre_idx = 0  # pointer into preorder, advanced pre-order

        def helper(left: int, right: int) -> Optional['TreeNode']:
            # Base case: no elements in this inorder slice
            if left > right:
                return None

            # The next preorder value is this subtree's root
            root_val = preorder[self.pre_idx]
            self.pre_idx += 1
            root = TreeNode(root_val)

            # Find where this root sits in inorder to split left/right
            mid = inorder_index[root_val]

            # Build left subtree first (preorder visits left before right)
            root.left  = helper(left,    mid - 1)
            root.right = helper(mid + 1, right)

            return root

        return helper(0, len(inorder) - 1)
```

> Left subtree must be built before right because the preorder pointer `self.pre_idx` advances in preorder sequence. Building left first ensures the pointer is at the correct position when right subtree construction begins.

### Walkthrough
preorder = `[3,9,20,15,7]`, inorder = `[9,3,15,20,7]`.

The first preorder value chooses the root. Its position in inorder fixes the left and right slices:

```text
Whole tree slices                              Partial tree
preorder: root [3] | left [9] | right [20,15,7]     3
inorder:  left [9] | root [3] | right [15,20,7]     |-- left: 9
                                                    `-- right: build next
```

The next unused preorder value is 20, so the same split builds the right subtree:

```text
Right subtree slices                           Subtree created
preorder: root [20] | left [15] | right [7]         20
inorder:  left [15] | root [20] | right [7]         |-- left: 15
                                                   `-- right: 7

Assembled tree
        3
       / \
      9   20
         /  \
        15   7
```

| Call | pre_idx | root_val | mid (in inorder) | left range | right range |
|------|---------|---------|-----------------|------------|-------------|
| helper(0,4) | 0 | 3 | 1 | (0,0) | (2,4) |
| helper(0,0) | 1 | 9 | 0 | (0,-1)=None | (1,0)=None |
| helper(2,4) | 2 | 20 | 3 | (2,2) | (4,4) |
| helper(2,2) | 3 | 15 | 2 | None | None |
| helper(4,4) | 4 | 7 | 4 | None | None |

Result: `3 -> [9, 20]`, `20 -> [15, 7]`.

### Complexity
- **Time:** O(N). Each node is created once; inorder lookups are O(1) via the hash map.
- **Space:** O(N). Hash map stores N entries; call stack depth is O(H) (O(log N) balanced, O(N) skewed).

### Key concepts to review
- [[Divide and Conquer]] - split the problem at the root, solve left and right subtrees independently.
- [[Hash Map]] - O(1) lookup of inorder position avoids O(N) linear scans per recursive call.
- [[Recursion]] - the preorder index advances globally (shared state) while inorder bounds define the local scope.
- [[Binary Tree]] - understanding preorder (root, left, right) and inorder (left, root, right) traversal orders is prerequisite.
- [[DFS|Depth-First Search]] - building the tree mirrors a preorder DFS traversal.

### Common pitfalls
- Building the right subtree before the left, which advances `pre_idx` out of order and builds an incorrect tree.
- Slicing the preorder and inorder arrays at each recursive call, which is O(N) per call and leads to O(N^2) total time.
- Using linear search to find `root_val` in inorder instead of a hash map (O(N) per call = O(N^2) total).
- Off-by-one in the inorder bounds when splitting: left subtree is `[left, mid-1]` and right is `[mid+1, right]`, not including mid itself.
