# 100. Same Tree

Given the roots of two binary trees p and q, write a function to check if they are the same or not.

Two binary trees are considered the same if they are structurally identical, and the nodes have the same value.

 

**Example 1:**

![[tree-same-tree-example-1.svg]]

```
Input: p = [1,2,3], q = [1,2,3]
Output: true
```

**Example 2:**

![[same-tree-example-2.svg]]

```
Input: p = [1,2], q = [1,null,2]
Output: false
```

**Example 3:**
```
Input: p = [1,2,1], q = [1,1,2]
Output: false
```

Constraints:
- The number of nodes in both trees is in the range [0, 100].
- -104 <= Node.val <= 104

---

## Solution

### Intuition
Two [[Binary Tree]] instances are identical if their roots match and both subtrees are identical. This is a direct recursive definition: walk both trees in lockstep using [[Recursion]], and fail as soon as any node pair differs in value or structure.

### Approach: Optimal
Handle the three base cases (both null, one null, values differ) before recursing on both children.

```python
# TreeNode definition:
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right

from typing import Optional

class Solution:
    def isSameTree(self, p: Optional['TreeNode'], q: Optional['TreeNode']) -> bool:
        # Both null: structurally the same at this position
        if p is None and q is None:
            return True

        # One null and one not: structural mismatch
        if p is None or q is None:
            return False

        # Both exist but values differ
        if p.val != q.val:
            return False

        # Recursively check left and right subtrees in lockstep
        return self.isSameTree(p.left, q.left) and self.isSameTree(p.right, q.right)
```

> The order of base cases matters. Check both-null first (success), then one-null (failure), then value mismatch (failure). Reaching the recursive call means both nodes exist and have equal values.

### Walkthrough
Trace `p = [1,2,3]` and `q = [1,2,3]`:

| Call | p.val | q.val | Continues? |
|------|-------|-------|-----------|
| isSameTree(1,1) | 1 | 1 | yes |
| isSameTree(2,2) | 2 | 2 | yes |
| isSameTree(None,None) | - | - | True (left of 2) |
| isSameTree(None,None) | - | - | True (right of 2) |
| isSameTree(3,3) | 3 | 3 | yes |
| isSameTree(None,None) | - | - | True (both children of 3) |

All return True, so overall result is True.

### Complexity
- **Time:** O(N). In the worst case all N nodes are visited (trees are identical).
- **Space:** O(H). Call stack depth equals tree height. O(log N) balanced, O(N) skewed.

### Key concepts to review
- [[Recursion]] - walking two trees simultaneously in lockstep is a natural recursive pattern.
- [[DFS|Depth-First Search]] - pre-order: check current node before recursing into children.
- [[Binary Tree]] - structural identity requires matching both shape and values.
- [[06.SubtreeOfAnotherTree]] - uses `isSameTree` as a subroutine.

### Common pitfalls
- Checking `p is None or q is None` before checking both-null, which would incorrectly return False when both are null.
- Using `==` to compare node objects instead of `.val`, which compares references.
- Forgetting that `and` short-circuits: once the left subtree returns False, the right is not evaluated.
- Missing the structural mismatch case where one tree has an extra level.
