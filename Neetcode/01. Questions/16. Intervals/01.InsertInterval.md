# [57. Insert Interval](https://leetcode.com/problems/insert-interval/)


You are given an array of non-overlapping intervals intervals where intervals[i] = [starti, endi] represent the start and the end of the ith interval and intervals is sorted in ascending order by starti. You are also given an interval newInterval = [start, end] that represents the start and end of another interval.

Insert newInterval into intervals such that intervals is still sorted in ascending order by starti and intervals still does not have any overlapping intervals (merge overlapping intervals if necessary).

Return intervals after the insertion.
**Example 1:**

![[insert-interval-example.svg]]

```text
Input: intervals = [[1,3],[6,9]], newInterval = [2,5]
Output: [[1,5],[6,9]]
```

**Example 2:**

![[intervals-insert-interval-example2.svg]]

```text
Input: intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]], newInterval = [4,8]
Output: [[1,2],[3,10],[12,16]]
Explanation: Because the new interval [4,8] overlaps with [3,5],[6,7],[8,10].
```

Constraints:

- 0 <= intervals.length <= 10<sup>4</sup>
- intervals[i].length == 2
- 0 <= starti <= endi <= 10<sup>5</sup>
- intervals is sorted by starti in ascending order.
- newInterval.length == 2
- 0 <= start <= end <= 10<sup>5</sup>

---

## Solution

### Intuition
Because the input is already sorted by start time, we can process it in a single linear sweep with three phases: copy intervals that end before the new one starts, merge all overlapping intervals into the new one, then copy the rest. No [[Sorting]] is needed, making this a clean O(n) pass.

### Approach: Linear sweep (3 phases)

Scan left to right. Phase 1 copies non-overlapping intervals before the new interval. Phase 2 absorbs every interval that overlaps by expanding the new interval's boundaries. Phase 3 copies the remainder.

```python
class Solution:
    def insert(self, intervals: list[list[int]], newInterval: list[int]) -> list[list[int]]:
        res = []
        i = 0
        n = len(intervals)

        # Phase 1: intervals that end before newInterval starts (no overlap)
        while i < n and intervals[i][1] < newInterval[0]:
            res.append(intervals[i])
            i += 1

        # Phase 2: merge all overlapping intervals into newInterval
        while i < n and intervals[i][0] <= newInterval[1]:
            newInterval[0] = min(newInterval[0], intervals[i][0])  # expand left
            newInterval[1] = max(newInterval[1], intervals[i][1])  # expand right
            i += 1
        res.append(newInterval)

        # Phase 3: intervals that start after newInterval ends (no overlap)
        while i < n:
            res.append(intervals[i])
            i += 1

        return res
```

> The overlap condition in Phase 2 is `intervals[i][0] <= newInterval[1]` (not strict `<`). Touching boundaries like [1,3] and [3,5] are considered overlapping and should be merged into [1,5].

### Walkthrough
Input: `intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]]`, `newInterval = [4,8]`

| Phase | Action | newInterval | res |
|-------|--------|-------------|-----|
| 1 | [1,2] ends before 4 | [4,8] | `[[1,2]]` |
| 2 | [3,5] overlaps: expand left to 3 | [3,8] | `[[1,2]]` |
| 2 | [6,7] overlaps | [3,8] | `[[1,2]]` |
| 2 | [8,10] overlaps: expand right to 10 | [3,10] | `[[1,2]]` |
| append | add merged | [3,10] | `[[1,2],[3,10]]` |
| 3 | [12,16] copied | - | `[[1,2],[3,10],[12,16]]` |

Output: `[[1,2],[3,10],[12,16]]`

### Complexity
- **Time:** O(n). Single pass through all intervals.
- **Space:** O(n). Output list holds at most n+1 intervals.

### Key concepts to review
- [[Interval Scheduling]] - the foundation for all interval merge/insert problems
- [[0.GreedyGuide|Greedy]] - phase-based processing avoids backtracking
- [[Sorting]] - not needed here (contrast with [[02.MergeInterval]] where input is unsorted)

### Common pitfalls
- Using strict `<` instead of `<=` in the overlap check, which misses touching intervals like [1,3] and [3,5].
- Forgetting to append `newInterval` after Phase 2 before starting Phase 3.
- Mutating the input list in-place instead of building a fresh result list.
- Not handling the empty `intervals` input (the loop simply skips and returns `[newInterval]`).
