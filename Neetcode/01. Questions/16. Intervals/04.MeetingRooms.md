# 920 · Meeting Rooms [LintCode]

Given an array of meeting time intervals consisting of start and end times `[[s1,e1], [s2,e2], ...]` (`si < ei`), determine if a person could attend all meetings.

> (0,8),(8,10) is not conflict at 8
**Example 1:**

![[meeting-rooms-example.svg]]

```text
Input: intervals = [(0,30),(5,10),(15,20)]
Output: false
Explanation: 
(0,30), (5,10) and (0,30),(15,20) will conflict
```

**Example 2:**

```text
Input: intervals = [(5,8),(9,15)]
Output: true
Explanation: 
Two times will not conflict 
```

---

## Solution

### Intuition
A person can attend all meetings only if no two intervals overlap. After [[Sorting]] by start time, any overlap must occur between consecutive intervals. We need a single linear pass to check whether each interval starts before the previous one ends.

### Approach: Sort + consecutive overlap check

Sort by start time, then scan pairs. If any interval starts strictly before the previous one ends, a conflict exists.

```python
class Solution:
    def canAttendMeetings(self, intervals: list[list[int]]) -> bool:
        intervals.sort(key=lambda x: x[0])  # sort by start time

        for i in range(1, len(intervals)):
            # overlap if current start is strictly before previous end
            if intervals[i][0] < intervals[i - 1][1]:
                return False

        return True
```

> The problem states `(0,8)` and `(8,10)` do NOT conflict. Use strict `<` (not `<=`) when checking for overlap so that touching endpoints are allowed.

### Walkthrough
Input: `[(0,30),(5,10),(15,20)]` sorted: `[(0,30),(5,10),(15,20)]`

| i | intervals[i] | prev end | 5 < 30? |
|---|-------------|----------|---------|
| 1 | (5,10) | 30 | Yes - conflict! |

Output: `false`

Input: `[(5,8),(9,15)]` sorted: `[(5,8),(9,15)]`

| i | intervals[i] | prev end | 9 < 8? |
|---|-------------|----------|--------|
| 1 | (9,15) | 8 | No |

Output: `true`

### Complexity
- **Time:** O(n log n). Dominated by sorting.
- **Space:** O(1). No extra data structures beyond the sorted input.

### Key concepts to review
- [[Sorting]] - makes consecutive comparison sufficient
- [[Interval Scheduling]] - simpler cousin of [[05.MeetingRoomsII]] which counts rooms
- [[0.GreedyGuide|Greedy]] - no greedy choice needed here; just validation after sorting

### Common pitfalls
- Using `<=` in the overlap check, which would incorrectly flag touching intervals like (5,8) and (8,10) as conflicts.
- Comparing non-consecutive intervals (not necessary after sorting).
- Forgetting to sort before scanning, leading to missed overlaps.
- Returning early on the first non-overlap instead of the first overlap.
