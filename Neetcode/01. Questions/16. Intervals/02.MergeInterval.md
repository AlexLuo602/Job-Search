# [56. Merge Intervals](https://leetcode.com/problems/merge-intervals/)


Given an array of intervals where intervals[i] = [starti, endi], merge all overlapping intervals, and return an array of the non-overlapping intervals that cover all the intervals in the input.
**Example 1:**

![[merge-intervals-example.svg]]

```text
Input: intervals = [[1,3],[2,6],[8,10],[15,18]]
Output: [[1,6],[8,10],[15,18]]
Explanation: Since intervals [1,3] and [2,6] overlaps, merge them into [1,6].
```

**Example 2:**

```text
Input: intervals = [[1,4],[4,5]]
Output: [[1,5]]
Explanation: Intervals [1,4] and [4,5] are considered overlapping.
```

Constraints:

- 1 <= intervals.length <= 10<sup>4</sup>
- intervals[i].length == 2
- 0 <= starti <= endi <= 10<sup>4</sup>

---

## Solution

### Intuition
After [[Sorting]] by start time, any interval that overlaps the previous one must start at or before the previous interval's end. We can merge greedily by extending the last result interval's end whenever we detect overlap, requiring only a single linear scan after sorting.

### Approach: Sort + linear sweep

Sort by start time, seed the result with the first interval, then walk through the rest. If the current interval overlaps the last entry in result, extend the end; otherwise append a new entry.

```python
class Solution:
    def merge(self, intervals: list[list[int]]) -> list[list[int]]:
        intervals.sort(key=lambda x: x[0])  # sort by start time
        merged = [intervals[0]]

        for start, end in intervals[1:]:
            last_end = merged[-1][1]
            if start <= last_end:          # overlap: extend the current merged interval
                merged[-1][1] = max(last_end, end)
            else:                          # no overlap: start a new interval
                merged.append([start, end])

        return merged
```

> When merging, use `max(last_end, end)` rather than just `end`. A fully-contained interval like [1,10] followed by [2,5] should stay [1,10], not shrink to [1,5].

### Walkthrough
Input: `[[1,3],[2,6],[8,10],[15,18]]` (already sorted)

| Current | Last in merged | Overlap? | merged |
|---------|---------------|----------|--------|
| [2,6] | [1,3], end=3 | 2<=3 yes | `[[1,6]]` |
| [8,10] | [1,6], end=6 | 8<=6 no | `[[1,6],[8,10]]` |
| [15,18] | [8,10], end=10 | 15<=10 no | `[[1,6],[8,10],[15,18]]` |

Output: `[[1,6],[8,10],[15,18]]`

### Complexity
- **Time:** O(n log n). Dominated by sorting; the sweep is O(n).
- **Space:** O(n). The output list holds all merged intervals.

### Key concepts to review
- [[Sorting]] - prerequisite step that makes the greedy sweep correct
- [[0.GreedyGuide|Greedy]] - extending the end greedily is always safe once sorted
- [[Interval Scheduling]] - core interval problem; compare with [[01.InsertInterval]] (pre-sorted input) and [[03.Non-OverlappingIntervals]] (removal variant)

### Common pitfalls
- Forgetting to use `max` when extending the end, causing a contained interval to shrink the boundary.
- Sorting by end instead of start, which breaks the greedy invariant.
- Modifying `intervals` in-place during iteration instead of reading from sorted copy.
- Not seeding `merged` with the first interval before the loop.
