# [253. Meeting Rooms II](https://leetcode.com/problems/meeting-rooms-ii/)

Given an array of meeting time intervals consisting of start and end times `[[s1,e1], [s2,e2], ...]` (`si < ei`), find the minimum number of conference rooms required.

> (0,8),(8,10) is not conflict at 8
**Example 1:**

![[meeting-rooms-ii-example.svg]]

```text
Input: intervals = [(0,30),(5,10),(15,20)]
Output: 2
Explanation:
We need two meeting rooms
room1: (0,30)
room2: (5,10),(15,20)
```

**Example 2:**

```text
Input: intervals = [(2,7)]
Output: 1
Explanation: 
Only need one meeting room
```

## Solution

### Intuition
Each room in use corresponds to a meeting whose end time has not been reached yet. A [[Heap]] (min-heap) of active end times lets us efficiently check whether any room has freed up before the next meeting starts. If the earliest-ending room finishes before the new meeting starts, reuse it; otherwise allocate a new room.

### Approach: Sort by start + min-heap of end times

Sort by start time. Push each meeting's end time onto the min-heap. Before pushing, if the heap's minimum (earliest ending meeting) finishes at or before the new meeting's start, pop it to reuse that room.

```python
import heapq

class Solution:
    def minMeetingRooms(self, intervals: list[list[int]]) -> int:
        if not intervals:
            return 0

        intervals.sort(key=lambda x: x[0])  # sort by start time
        min_heap: list[int] = []             # stores end times of active meetings

        for start, end in intervals:
            # if earliest-ending room is free, reuse it (pop it)
            if min_heap and min_heap[0] <= start:
                heapq.heappop(min_heap)
            heapq.heappush(min_heap, end)    # assign this meeting to a room

        return len(min_heap)  # rooms still in use = total rooms needed
```

> The condition is `min_heap[0] <= start` (not strict `<`). A room ending at 8 can host a meeting starting at 8, matching the problem's note that (0,8) and (8,10) do not conflict.

### Walkthrough
Input: `[(0,30),(5,10),(15,20)]` sorted by start.

| Meeting | Heap before | Free? (heap[0] <= start) | Action | Heap after |
|---------|------------|--------------------------|--------|------------|
| (0,30) | [] | No | push 30 | [30] |
| (5,10) | [30] | 30<=5? No | push 10 | [10,30] |
| (15,20) | [10,30] | 10<=15? Yes | pop 10, push 20 | [20,30] |

`len([20,30]) = 2`. Output: `2`

### Complexity
- **Time:** O(n log n). Sorting is O(n log n); each heap push/pop is O(log n) for n intervals.
- **Space:** O(n). The heap holds at most n end times.

### Key concepts to review
- [[Heap]] - min-heap tracks the earliest-ending active room efficiently
- [[Sorting]] - sorting by start time ensures meetings are processed in order
- [[Interval Scheduling]] - generalization of [[04.MeetingRooms]] (detection vs. counting)
- [[0.GreedyGuide|Greedy]] - always reuse the earliest-ending room when possible

### Common pitfalls
- Using strict `<` in the free-room check, incorrectly requiring a room to end before (not at) the new start.
- Forgetting to sort by start time, causing rooms to be allocated out of order.
- Counting heap size at the wrong time (count after all meetings are processed, not during).
- Using a max-heap (default in some languages) instead of a min-heap.
