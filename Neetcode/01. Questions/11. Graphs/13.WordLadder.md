# [127. Word Ladder](https://leetcode.com/problems/word-ladder/)


A transformation sequence from word beginWord to word endWord using a dictionary wordList is a sequence of words `beginWord -> s1 -> s2 -> ... -> sk` such that:

- Every adjacent pair of words differs by a single letter.
- Every si for 1 <= i <= k is in wordList. Note that beginWord does not need to be in wordList.
- sk == endWord

Given two words, beginWord and endWord, and a dictionary wordList, return the number of words in the shortest transformation sequence from beginWord to endWord, or 0 if no such sequence exists.

 

**Example 1:**

![[word-ladder-example.svg]]

```
Input: beginWord = "hit", endWord = "cog", wordList = ["hot","dot","dog","lot","log","cog"]
Output: 5
Explanation: One shortest transformation sequence is "hit" -> "hot" -> "dot" -> "dog" -> "cog", which is 5 words long.
```
**Example 2:**
```
Input: beginWord = "hit", endWord = "cog", wordList = ["hot","dot","dog","lot","log"]
Output: 0
Explanation: The endWord "cog" is not in wordList, therefore there is no valid transformation sequence.
``` 

Constraints:

- 1 <= beginWord.length <= 10
- endWord.length == beginWord.length
- 1 <= wordList.length <= 5000
- wordList[i].length == beginWord.length
- beginWord, endWord, and wordList[i] consist of lowercase English letters.
- beginWord != endWord
- All the words in wordList are unique.

---

## Solution

### Intuition
Each word is a graph node; two words share an edge if they differ by exactly one letter. We need the shortest path from beginWord to endWord, which is the classic use case for [[BFS|Breadth-First Search]]. The key insight for efficiency: instead of comparing every word pair (O(N^2 * L)), build a pattern map where each pattern like `h*t` maps to all words matching it, so each word's neighbors can be found in O(L * 26) time.

### Approach 1: Brute force
For each BFS step, compare the current word against every remaining word in the list to find single-letter neighbors. This is O(N^2 * L) per level and acceptable for small inputs but slow for N=5000.

### Approach 2: Optimal
Pre-build an adjacency map keyed by wildcard patterns. Each word of length L generates L patterns (replace each position with `*`). Two words that share a pattern are neighbors. BFS from beginWord, tracking a visited set to avoid revisiting, and count levels.

```python
import collections


class Solution:
    def ladderLength(self, beginWord: str, endWord: str, wordList: list[str]) -> int:
        word_set = set(wordList)
        if endWord not in word_set:
            return 0  # endWord must be reachable

        # Build pattern -> [words] adjacency map
        pattern_map: dict[str, list[str]] = collections.defaultdict(list)
        for word in wordList:
            for i in range(len(word)):
                pattern = word[:i] + '*' + word[i + 1:]
                pattern_map[pattern].append(word)

        queue: collections.deque[str] = collections.deque([beginWord])
        visited: set[str] = {beginWord}
        length = 1  # beginWord itself counts as step 1

        while queue:
            for _ in range(len(queue)):  # process one BFS level at a time
                word = queue.popleft()
                if word == endWord:
                    return length
                for i in range(len(word)):
                    pattern = word[:i] + '*' + word[i + 1:]
                    for neighbor in pattern_map[pattern]:
                        if neighbor not in visited:
                            visited.add(neighbor)  # mark before enqueue to avoid duplicates
                            queue.append(neighbor)
            length += 1

        return 0  # endWord unreachable
```

> The visited set must be updated when a word is first enqueued, not when it is dequeued. If you mark visited on dequeue, the same word can be enqueued multiple times from different neighbors in the same BFS level, blowing up the queue for dense word graphs.

### Complexity
- **Time:** O(N * L^2). N words, L length; each word generates L patterns, each pattern lookup is O(L) string slice.
- **Space:** O(N * L^2). Pattern map stores N * L entries each of length L.

### Key concepts to review
- [[BFS|Breadth-First Search]] - shortest path in an unweighted graph; BFS guarantees the first time endWord is reached is via the shortest route.
- [[Graph]] - implicit word graph; nodes are words, edges connect single-letter neighbors.
- [[Hash Map]] - pattern map enables O(L) neighbor lookup per word instead of O(N * L) pairwise comparison.
- [[Set]] - visited set prevents revisiting and controls BFS correctness.
- [[06.RottenOranges]] - multi-source BFS contrast; this is single-source BFS for shortest path.

### Common pitfalls
- Marking visited on dequeue rather than enqueue - allows the same word to be enqueued many times from the same BFS level, causing incorrect length counts and slow performance.
- Forgetting that beginWord itself counts as step 1, so the sequence length off-by-one is common.
- Not checking `endWord not in word_set` upfront - wastes BFS time when the answer is always 0.
- Building neighbor lists by pairwise comparison (O(N^2)) instead of using the pattern map - technically correct but times out for large inputs.
