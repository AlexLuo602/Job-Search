# [417. Pacific Atlantic Water Flow](https://leetcode.com/problems/pacific-atlantic-water-flow/)


There is an m x n rectangular island that borders both the Pacific Ocean and Atlantic Ocean. The Pacific Ocean touches the island's left and top edges, and the Atlantic Ocean touches the island's right and bottom edges.

The island is partitioned into a grid of square cells. You are given an m x n integer matrix heights where heights[r][c] represents the height above sea level of the cell at coordinate (r, c).

The island receives a lot of rain, and the rain water can flow to neighboring cells directly north, south, east, and west if the neighboring cell's height is less than or equal to the current cell's height. Water can flow from any cell adjacent to an ocean into the ocean.

Return a 2D list of grid coordinates result where result[i] = [ri, ci] denotes that rain water can flow from cell (ri, ci) to both the Pacific and Atlantic oceans.

 

**Example 1:**

![[pacific-atlantic-water-flow-example.svg]]

```
Input: heights = [[1,2,2,3,5],[3,2,3,4,4],[2,4,5,3,1],[6,7,1,4,5],[5,1,1,2,4]]
Output: [[0,4],[1,3],[1,4],[2,2],[3,0],[3,1],[4,0]]
```
**Example 2:**
```
Input: heights = [[2,1],[1,2]]
Output: [[0,0],[0,1],[1,0],[1,1]]
```

Constraints:

- m == heights.length
- n == heights[r].length
- 1 <= m, n <= 200
- 0 <= heights[r][c] <= 10<sup>5</sup>

## Solution

### Intuition
Instead of simulating water flowing downhill from every cell (expensive), we reverse the direction: start at each ocean's border and flood inward using [[DFS|Depth-First Search]], moving to neighbors whose height is greater than or equal to the current cell. Any cell reachable from both the Pacific border and the Atlantic border is in the answer.

The key insight is to run reverse DFS from both ocean borders, then keep the cells reached by both searches. This overlay uses Example 1:

```text
                         Pacific (top)
                              ↓
                         c0 c1 c2 c3 c4
                    r0   1P 2P 2P 3P 5B
Pacific (left)  →   r1   3P 2P 3P 4B 4B   ←  Atlantic (right)
                    r2   2P 4P 5B 3A 1A
                    r3   6B 7B 1A 4A 5A
                    r4   5B 1A 1A 2A 4A
                              ↓
                         Atlantic (bottom)
```

Each cell shows `height + reachability`: `P` = Pacific only, `A` = Atlantic only, and `B` = both oceans. The seven `B` cells are the answer.

### Approach
Run two separate DFS passes - one seeded from all Pacific-bordering cells (top row and left column), one from all Atlantic-bordering cells (bottom row and right column). Collect each ocean's reachable set, then return the intersection.

```python
class Solution:
    def pacificAtlantic(self, heights: list[list[int]]) -> list[list[int]]:
        rows, cols = len(heights), len(heights[0])
        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        def dfs(r: int, c: int, visited: set[tuple[int, int]]) -> None:
            visited.add((r, c))
            for dr, dc in directions:
                nr, nc = r + dr, c + dc
                if (0 <= nr < rows and 0 <= nc < cols
                        and (nr, nc) not in visited
                        and heights[nr][nc] >= heights[r][c]):  # reverse flow: go uphill
                    dfs(nr, nc, visited)

        pacific: set[tuple[int, int]] = set()
        atlantic: set[tuple[int, int]] = set()

        for r in range(rows):
            dfs(r, 0, pacific)          # left column borders Pacific
            dfs(r, cols - 1, atlantic)  # right column borders Atlantic
        for c in range(cols):
            dfs(0, c, pacific)          # top row borders Pacific
            dfs(rows - 1, c, atlantic)  # bottom row borders Atlantic

        # cells reachable from both oceans
        return [[r, c] for r, c in pacific & atlantic]
```

> The key reversal: normal water flow goes from high to low, so reverse DFS goes from the ocean border uphill (neighbor height >= current height). This avoids an O(m*n) DFS from every cell.

### Walkthrough
heights (2x2): `[[2,1],[1,2]]`

Pacific seeds: top row (0,0),(0,1) and left col (0,0),(1,0).
- DFS from (0,0) h=2: can go to (0,1) h=1? No (1<2). Can go to (1,0) h=1? No. Pacific = {(0,0)}.
- DFS from (0,1) h=1: (0,0) h=2 >= 1, yes. Pacific gains (0,0) already visited, Pacific adds (0,1). Pacific = {(0,0),(0,1)}.
- DFS from (1,0) h=1: (0,0) h=2 >= 1, yes. Pacific gains (1,0). Pacific = {(0,0),(0,1),(1,0)}.

Atlantic seeds: bottom row (1,0),(1,1) and right col (0,1),(1,1).
- Similar traversal yields Atlantic = {(0,0),(0,1),(1,0),(1,1)}: the seed (1,0) with height 1 lets the reverse DFS climb to (0,0) with height 2.

Intersection: {(0,1),(1,0)} plus also (0,0) from Pacific x Atlantic overlap = all four cells.
Output: `[[0,0],[0,1],[1,0],[1,1]]`.

### Complexity
- **Time:** O(m * n). Each cell is visited at most twice (once per ocean's DFS).
- **Space:** O(m * n). Two visited sets and recursion stack.

### Key concepts to review
- [[DFS|Depth-First Search]] - reverse flood-fill from ocean borders.
- [[BFS|Breadth-First Search]] - iterative alternative; same idea, seeds both oceans' queues simultaneously.
- [[Matrix Traversal]] - direction vectors for 4-directional traversal.
- [[Set]] - intersection of two reachable sets gives the answer efficiently.

### Common pitfalls
- Forgetting to reverse the flow direction (checking `>=` not `<=`) - the DFS goes uphill from the ocean.
- Seeding only one edge per ocean (e.g., only top row for Pacific, missing the left column).
- Using a single DFS pass and trying to track both oceans simultaneously - makes the visited logic much harder.
- Returning indices in the wrong order (row, col vs col, row).
