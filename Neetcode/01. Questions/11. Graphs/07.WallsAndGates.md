# 286 - Walls and Gates


You are given a m x n 2D grid initialized with these three possible values.

-1 : A wall or an obstacle.

0 : A gate.

INF - Infinity means an empty room. We use the value 2^31 - 1 = 2147483647 to represent INF as you may assume that the distance to a gate is less than 2147483647.

Fill each empty room with the distance to its nearest gate. If it is impossible to reach a Gate, that room should remain filled with INF


**Example 1:**

![[walls-and-gates-example.svg]]

```
Input:
[
[2147483647,-1,0,2147483647],
[2147483647,2147483647,2147483647,-1],
[2147483647,-1,2147483647,-1],
[0,-1,2147483647,2147483647]]
Output:
[
[3,-1,0,1],
[2,2,1,-1],
[1,-1,2,-1],
[0,-1,3,4]]
```
**Example 2:**
```
Input:
[
[0,-1],
[2147483647,2147483647]]
Output:
[
[0,-1],
[1,2]]
```

## Solution

### Intuition
Each room needs its distance to the nearest gate - a shortest-distance problem from multiple sources simultaneously. Multi-source [[BFS|Breadth-First Search]] handles this perfectly: seed the BFS with all gates at distance 0 and let the wavefront expand outward, filling rooms with increasing distances.

BFS starts from both gates and fills one distance at a time. A room's first number is its shortest distance to any gate:

```text
Distance 0         After distance 1    After distance 2
∞  #  G  ∞         ∞  #  G  1         ∞  #  G  1
∞  ∞  ∞  #    →    ∞  ∞  1  #    →    2  2  1  #
∞  #  ∞  #         1  #  ∞  #         1  #  2  #
G  #  ∞  ∞         G  #  ∞  ∞         G  #  ∞  ∞

After distance 3   After distance 4 (final)
3  #  G  1         3  #  G  1
2  2  1  #    →    2  2  1  #
1  #  2  #         1  #  2  #
G  #  3  ∞         G  #  3  4
```

`G` = gate with distance 0, `#` = wall, and `∞` = an unfilled room.

### Approach
Collect every gate (value 0) into a deque as the initial BFS frontier. Process level by level. When visiting a neighbor that is INF, update it to the current distance + 1 and enqueue it. Walls (-1) and already-updated rooms are skipped.

```python
import collections

INF = 2147483647


class Solution:
    def wallsAndGates(self, rooms: list[list[int]]) -> None:
        rows, cols = len(rooms), len(rooms[0])
        directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

        queue: collections.deque[tuple[int, int]] = collections.deque()

        # Seed all gates as distance-0 sources
        for r in range(rows):
            for c in range(cols):
                if rooms[r][c] == 0:
                    queue.append((r, c))

        while queue:
            r, c = queue.popleft()
            for dr, dc in directions:
                nr, nc = r + dr, c + dc
                if (0 <= nr < rows and 0 <= nc < cols
                        and rooms[nr][nc] == INF):   # only update unvisited rooms
                    rooms[nr][nc] = rooms[r][c] + 1  # BFS guarantees shortest distance
                    queue.append((nr, nc))
```

> Checking `rooms[nr][nc] == INF` serves as the visited guard. Because BFS expands in order of distance, the first time a room is reached is always via the shortest path - no need to re-enqueue or compare.

### Walkthrough
Grid (4x4), gates at (0,2) and (3,0):

| step | queue | update |
|------|-------|--------|
| init | [(0,2),(3,0)] | distances 0 |
| pop (0,2) | enqueue (0,3),(1,2) | set to 1 |
| pop (3,0) | enqueue (2,0) | set to 1 |
| pop (0,3) | enqueue (1,3) skipped (-1) | (0,3)=1 already |
| ... | wavefront expands | fills all reachable INF rooms |

Final: matches example output.

### Complexity
- **Time:** O(m * n). Each cell enters the queue at most once.
- **Space:** O(m * n). Queue size bounded by grid area.

### Key concepts to review
- [[BFS|Breadth-First Search]] - multi-source BFS guarantees shortest distances from the nearest gate; identical pattern to [[06.RottenOranges]].
- [[Matrix Traversal]] - direction vectors for 4-directional movement.
- [[Graph]] - grid as an implicit graph; gates are source nodes.

### Common pitfalls
- Starting BFS from a single gate instead of all gates - gives correct answers only for rooms nearest that one gate.
- Using DFS instead of BFS - DFS does not guarantee shortest distance, so rooms may get overwritten with longer paths.
- Forgetting to skip walls (-1) in addition to already-updated rooms.
- Modifying `rooms[nr][nc]` after enqueue (rather than before) - allows the same cell to be enqueued multiple times.
