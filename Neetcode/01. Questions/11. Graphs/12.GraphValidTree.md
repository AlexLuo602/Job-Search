# [261. Graph Valid Tree](https://leetcode.com/problems/graph-valid-tree/)

Given n nodes labeled from 0 to n - 1 and a list of undirected edges (each edge is a pair of nodes), write a function to check whether these edges make up a valid tree.

You can assume that no duplicate edges will appear in edges. Since all edges are undirected, [0, 1] is the same as [1, 0] and thus will not appear together in edges.


**Example 1:**

![[graph-valid-tree-example-1.svg]]

```
Input: n = 5 edges = [[0, 1], [0, 2], [0, 3], [1, 4]]
Output: true.
```
**Example 2:**

![[graph-valid-tree-example-2.svg]]

```
Input: n = 5 edges = [[0, 1], [1, 2], [2, 3], [1, 3], [1, 4]]
Output: false.
```

## Solution

### Intuition
A valid tree on n nodes has exactly two properties: it is fully connected (one component) and contains no cycles. These conditions together imply exactly n-1 edges. [[Union-Find|Union Find]] checks both at once: process each edge and union its endpoints. If two endpoints are already in the same component, a cycle exists. At the end, verify exactly one component remains.

### Approach
Initialize [[Union-Find|Union Find]] with n nodes and a component counter of n. For each edge, attempt to union the endpoints. If they are already connected, return False immediately (cycle detected). Each successful union decrements the component count. After all edges, return True only if one component remains (equivalently, edges.length == n - 1 is a fast pre-check).

```python
class UnionFind:
    def __init__(self, n: int) -> None:
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n  # start: every node is its own component

    def find(self, x: int) -> int:
        while x != self.parent[x]:
            self.parent[x] = self.parent[self.parent[x]]  # path halving
            x = self.parent[x]
        return x

    def union(self, x: int, y: int) -> bool:
        """Returns True if a merge happened, False if already connected (cycle)."""
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False  # same component - adding this edge creates a cycle
        if self.size[rx] < self.size[ry]:
            rx, ry = ry, rx
        self.parent[ry] = rx
        self.size[rx] += self.size[ry]
        self.components -= 1
        return True


class Solution:
    def validTree(self, n: int, edges: list[list[int]]) -> bool:
        # A tree must have exactly n-1 edges
        if len(edges) != n - 1:
            return False

        uf = UnionFind(n)
        for a, b in edges:
            if not uf.union(a, b):
                return False  # cycle detected

        return uf.components == 1  # must be fully connected
```

> The edge-count pre-check (`len(edges) != n - 1`) short-circuits most invalid inputs in O(1), but it is not sufficient alone: n=4, edges=`[[0,1],[1,2],[0,2]]` has 3 edges but forms a cycle and is not a tree. The union-find cycle check is still required.

### Walkthrough
n=5, edges=`[[0,1],[0,2],[0,3],[1,4]]`, components starts at 5.

| edge | roots before | action | components |
|------|-------------|--------|-----------|
| [0,1] | 0,1 | merge | 4 |
| [0,2] | 0,2 | merge | 3 |
| [0,3] | 0,3 | merge | 2 |
| [1,4] | find(1)=0, 4 | merge | 1 |

components == 1, return True.

Counter-example n=5, edges=`[[0,1],[1,2],[2,3],[1,3],[1,4]]`: len(edges)=5, but 5 != 4 so return False immediately.

### Complexity
- **Time:** O(n + E * alpha(n)). E = edges.length; each union/find is nearly O(1) amortized.
- **Space:** O(n). Parent and size arrays.

### Key concepts to review
- [[Union-Find|Union Find]] - detects cycles and counts components simultaneously; ideal for this two-condition check.
- [[DFS|Depth-First Search]] - alternative: DFS from node 0, check all n nodes are visited and no back edges exist.
- [[Graph]] - valid tree = connected + acyclic; n nodes + n-1 edges is necessary but not sufficient alone.
- [[10.RedundantConnection]] - similar UF setup; that problem finds the cycle-causing edge rather than just detecting it.
- [[11.NumberOfConnectedComponentsInAnUndirectedGraph]] - counts components; valid tree requires exactly 1.

### Common pitfalls
- Relying only on the edge count check (n-1 edges) without detecting cycles - a disconnected forest with n-1 edges passes the count but is not a valid tree.
- Using a visited set in DFS without tracking the parent, causing the undirected back-edge to a parent to be mistaken for a cycle.
- Initializing Union Find with size n but nodes labeled 1 to n (off-by-one); here nodes are 0-indexed.
- Forgetting to check `uf.components == 1` after processing all edges - a forest with no cycles but multiple components would otherwise pass.
