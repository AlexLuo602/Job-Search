# [39. Combination Sum](https://leetcode.com/problems/combination-sum/)


Given an array of distinct integers candidates and a target integer target, return a list of all unique combinations of candidates where the chosen numbers sum to target. You may return the combinations in any order.

The same number may be chosen from candidates an unlimited number of times. Two combinations are unique if the frequency of at least one of the chosen numbers is different.

It is guaranteed that the number of unique combinations that sum up to target is less than 150 combinations for the given input.

 

**Example 1:**
```
Input: candidates = [2,3,6,7], target = 7
Output: [[2,2,3],[7]]
Explanation:
2 and 3 are candidates, and 2 + 2 + 3 = 7. Note that 2 can be used multiple times.
7 is a candidate, and 7 = 7.
These are the only two combinations.
```
**Example 2:**
```
Input: candidates = [2,3,5], target = 8
Output: [[2,2,2,2],[2,3,3],[3,5]]
```
**Example 3:**
```
Input: candidates = [2], target = 1
Output: []
```

Constraints:

- 1 <= candidates.length <= 30
- 1 <= candidates\[i\] <= 200
- All elements of candidates are distinct.
- 1 <= target <= 500

---

## Solution

### Intuition
Unlike [[01.Subsets]], each candidate can be reused any number of times, so the decision tree is not binary. At each level we loop over candidates starting from the current index (to avoid reordered duplicates) and subtract from the remaining target. [[0.BacktrackingGuide|Backtracking]] prunes any branch where the remaining target goes negative.

### Approach
Pass a `start` index so earlier candidates are never reconsidered, keeping combinations in non-decreasing order and avoiding duplicates. Recurse with the same index `i` (not `i+1`) to allow reuse of the same element.

```python
class Solution:
    def combinationSum(self, candidates: list[int], target: int) -> list[list[int]]:
        res: list[list[int]] = []
        path: list[int] = []

        def backtrack(start: int, remaining: int) -> None:
            if remaining == 0:          # found a valid combination
                res.append(path[:])
                return
            if remaining < 0:           # over-shot, prune this branch
                return
            for i in range(start, len(candidates)):
                path.append(candidates[i])
                backtrack(i, remaining - candidates[i])  # i not i+1: reuse allowed
                path.pop()                               # undo

        backtrack(0, target)
        return res
```

> Passing `i` (not `i + 1`) on the recursive call is the key difference from [[01.Subsets]]. It lets the same candidate appear multiple times while still preventing earlier candidates from being chosen again (which would create duplicate combinations like \[3,2\] alongside \[2,3\]).

### Complexity
- **Time:** O(N^(T/M)) where T is the target and M is the smallest candidate. Each node in the tree can branch N ways and the tree depth is at most T/M.
- **Space:** O(T/M). The recursion stack depth is bounded by how many times the smallest candidate fits into the target.

### Key concepts to review
- [[0.BacktrackingGuide|Backtracking]] - loop of choices at each level, prune on negative remaining.
- [[Recursion]] - recursive depth bounded by target divided by smallest element.
- [[01.Subsets]] - simpler binary-choice version without a target constraint.
- [[05.CombinationSumII]] - variant where each element may only be used once and duplicates exist.

### Common pitfalls
- Using `i + 1` instead of `i`, which prevents reusing the same candidate.
- Not pruning when `remaining < 0`, leading to infinite recursion if candidates include 0.
- Forgetting to copy `path` before appending to `res`.
- Starting the loop at `0` on every recursive call, generating combinatorial duplicates like \[2,3\] and \[3,2\].
