# [40. Combination Sum II](https://leetcode.com/problems/combination-sum-ii/)


Given a collection of candidate numbers (candidates) and a target number (target), find all unique combinations in candidates where the candidate numbers sum to target.

Each number in candidates may only be used once in the combination.

Note: The solution set must not contain duplicate combinations.

 

**Example 1:**
```
Input: candidates = [10,1,2,7,6,1,5], target = 8
Output: 
[
[1,1,6],
[1,2,5],
[1,7],
[2,6]
]
```
**Example 2:**
```
Input: candidates = [2,5,2,1,2], target = 5
Output: 
[
[1,2,2],
[5]
]
```

Constraints:

- 1 <= candidates.length <= 100
- 1 <= candidates\[i\] <= 50
- 1 <= target <= 30

---

## Solution

### Intuition
This merges [[02.CombinationSum]] (target sum, no index reuse) with [[04.SubsetsII]] (duplicate elements need skip logic). [[Sorting]] groups equal candidates so that at each level of the decision tree, we can skip subsequent equal values after the "exclude" branch to avoid generating duplicate combinations.

### Approach
[[Sorting]] first. Loop from `start` to end, advancing `i` by 1 each step. After an "exclude" (i.e., after the recursive call and undo), skip over any duplicates at the current level before incrementing `i`.

```python
class Solution:
    def combinationSum2(self, candidates: list[int], target: int) -> list[list[int]]:
        candidates.sort()               # group duplicates; also enables early pruning
        res: list[list[int]] = []
        path: list[int] = []

        def backtrack(start: int, remaining: int) -> None:
            if remaining == 0:          # valid combination found
                res.append(path[:])
                return
            i = start
            while i < len(candidates):
                if candidates[i] > remaining:
                    break               # sorted array: all further candidates too large
                path.append(candidates[i])
                backtrack(i + 1, remaining - candidates[i])  # i+1: each element used once
                path.pop()
                # skip duplicates at this level to avoid duplicate combinations
                while i + 1 < len(candidates) and candidates[i] == candidates[i + 1]:
                    i += 1
                i += 1

        backtrack(0, target)
        return res
```

> The `break` on `candidates[i] > remaining` is an early-termination pruning that only works because the array is sorted. Without [[Sorting]], this optimization would be incorrect and we would need to check every candidate even if it exceeds the remaining target.

### Complexity
- **Time:** O(2^N). Each element is included or excluded; duplicates reduce branches but worst case remains exponential.
- **Space:** O(N). Recursion stack depth is at most N (length of the input array).

### Key concepts to review
- [[0.BacktrackingGuide|Backtracking]] - include/exclude loop with duplicate-skip and target pruning.
- [[Sorting]] - prerequisite for both the skip rule and the early `break` optimization.
- [[02.CombinationSum]] - same target-sum idea but elements can be reused and no duplicates exist.
- [[04.SubsetsII]] - same duplicate-skip pattern without a target constraint.

### Common pitfalls
- Using `i` instead of `i + 1` in the recursive call, which would allow the same element to be reused.
- Applying the skip after the include branch (before the recursive call) rather than after the exclude (undo) step.
- Forgetting to sort, which breaks both the skip logic and the early `break` optimization.
- Pruning with `remaining < 0` instead of `candidates[i] > remaining`, which misses the sorted-array early exit.
