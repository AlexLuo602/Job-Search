# [78. Subsets](https://leetcode.com/problems/subsets/)


Given an integer array nums of unique elements, return all possible subsets (the power set).

The solution set must not contain duplicate subsets. Return the solution in any order.

 
**Example 1:**
```
Input: nums = [1,2,3]
Output: [[],[1],[2],[1,2],[3],[1,3],[2,3],[1,2,3]]
```
**Example 2:**
```
Input: nums = [0]
Output: [[],[0]]
```

Constraints:

- 1 <= nums.length <= 10
- -10 <= nums\[i\] <= 10
- All the numbers of nums are unique.

---

## Solution

### Intuition
Every element in the array faces a binary decision: include it or exclude it. Traversing these decisions as a [[0.BacktrackingGuide|Backtracking]] decision tree produces all 2^N subsets. At each index we recurse into the "include" branch, undo the addition, then recurse into the "exclude" branch, collecting a result at every node.

### Approach
Fix a pointer `start` that advances right on every call to avoid revisiting earlier elements. Record the current path at every node (not just leaves) because every partial selection is a valid subset.

```python
class Solution:
    def subsets(self, nums: list[int]) -> list[list[int]]:
        res: list[list[int]] = []
        path: list[int] = []

        def backtrack(start: int) -> None:
            # Every node in the tree is a valid subset, not just the leaves
            res.append(path[:])
            for i in range(start, len(nums)):
                path.append(nums[i])       # choose
                backtrack(i + 1)           # explore
                path.pop()                 # undo

        backtrack(0)
        return res
```

> `path[:]` makes a snapshot of the current list. Without copying, every entry in `res` would be a reference to the same list that gets mutated by later calls, so all entries would end up identical.

### Complexity
- **Time:** O(N * 2^N). There are 2^N subsets and copying each path takes O(N) in the worst case.
- **Space:** O(N). The recursion stack reaches depth N; result storage is not counted as auxiliary space.

### Key concepts to review
- [[0.BacktrackingGuide|Backtracking]] - build a candidate incrementally, recurse, then undo the last choice.
- [[Recursion]] - the call stack mirrors the depth of the decision tree.
- [[04.SubsetsII]] - extends this problem to handle duplicate elements using sorting and skip logic.

### Common pitfalls
- Appending `path` directly instead of `path[:]`, causing all results to reference the same mutating list.
- Starting the inner loop at `0` instead of `start`, which generates duplicate subsets.
- Forgetting to call `backtrack(0)` which also captures the empty subset at the root.
- Returning only at leaves instead of recording at every node.
