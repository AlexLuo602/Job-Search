# [90. Subsets II](https://leetcode.com/problems/subsets-ii/)


Given an integer array nums that may contain duplicates, return all possible subsets (the power set).

The solution set must not contain duplicate subsets. Return the solution in any order.

 

**Example 1:**
```
Input: nums = [1,2,2]
Output: [[],[1],[1,2],[1,2,2],[2],[2,2]]
```
**Example 2:**
```
Input: nums = [0]
Output: [[],[0]]
```

Constraints:

- 1 <= nums.length <= 10
- -10 <= nums\[i\] <= 10

---

## Solution

### Intuition
This extends [[01.Subsets]] to handle duplicate elements. [[Sorting]] groups equal values together, which allows a simple skip rule: after deciding NOT to include an element, skip all subsequent equal values at the same recursion level. This prevents generating the same subset through different index paths.

### Approach
[[Sorting]] first. Record the current path at every node (same as [[01.Subsets]]). In the "skip" branch, advance `i` past all duplicates before the next iteration.

```python
class Solution:
    def subsetsWithDup(self, nums: list[int]) -> list[list[int]]:
        nums.sort()                      # sorting groups duplicates together
        res: list[list[int]] = []
        path: list[int] = []

        def backtrack(start: int) -> None:
            res.append(path[:])
            i = start
            while i < len(nums):
                path.append(nums[i])
                backtrack(i + 1)
                path.pop()              # undo the inclusion
                # skip duplicates at this level: advance past all equal values
                while i + 1 < len(nums) and nums[i] == nums[i + 1]:
                    i += 1
                i += 1

        backtrack(0)
        return res
```

> [[Sorting]] is the enabler: it guarantees all copies of a value are adjacent. The skip loop only fires after the "exclude" decision, meaning duplicates can still be included multiple times via the "include" branch, generating \[2\] and \[2,2\] correctly from \[1,2,2\].

### Complexity
- **Time:** O(N * 2^N). Sorting is O(N log N), dominated by the O(N * 2^N) subset generation.
- **Space:** O(N). Recursion stack depth is at most N.

### Key concepts to review
- [[0.BacktrackingGuide|Backtracking]] - same include/exclude structure as [[01.Subsets]], augmented with a skip step.
- [[Sorting]] - prerequisite that makes adjacent-duplicate detection possible.
- [[01.Subsets]] - base version without duplicates.
- [[05.CombinationSumII]] - similar duplicate-skip pattern applied to combinations with a target sum.

### Common pitfalls
- Forgetting to sort, causing non-adjacent duplicates to slip through as separate subsets.
- Applying the skip rule before recursing into the "include" branch, which would block valid multi-occurrence subsets like \[2,2\].
- Skipping inside `backtrack` instead of at the same level (i.e., incrementing `start` inside the recursive call rather than looping `i`).
- Off-by-one in the skip condition: use `i + 1 < len(nums)` not `i < len(nums) - 1` (they are equivalent but the former is clearer).
