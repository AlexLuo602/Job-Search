# [51. N-Queens](https://leetcode.com/problems/n-queens/)

The n-queens puzzle is the problem of placing n queens on an n x n chessboard such that no two queens attack each other.

Given an integer n, return all distinct solutions to the n-queens puzzle. You may return the answer in any order.

Each solution contains a distinct board configuration of the n-queens' placement, where 'Q' and '.' both indicate a queen and an empty space, respectively.

 

**Example 1:**

![[n-queens-example.svg]]

```
Input: n = 4
Output: [[".Q..","...Q","Q...","..Q."],["..Q.","Q...","...Q",".Q.."]]
Explanation: There are two distinct solutions to the 4-queens puzzle, as shown above.
```

**Example 2:**
```
Input: n = 1
Output: [["Q"]]
```

Constraints:
- 1 <= n <= 9

## Solution

### Intuition
Place queens one row at a time using [[0.BacktrackingGuide|Backtracking]]. At row `r`, try each column `c`. A placement is valid only if no existing queen shares the column, the left diagonal (r - c), or the right diagonal (r + c). Three sets track occupied columns and diagonals so each check is O(1). When all `n` rows are filled, record the board.

### Approach
Maintain three sets: `cols`, `left_diag` (indexed by r - c), and `right_diag` (indexed by r + c). Recurse row by row. On a valid column, add to all three sets, place the queen, recurse to the next row, then undo all three sets and restore the cell.

```python
class Solution:
    def solveNQueens(self, n: int) -> list[list[str]]:
        board: list[list[str]] = [["." ] * n for _ in range(n)]
        res: list[list[str]] = []
        cols: set[int] = set()
        left_diag: set[int] = set()    # r - c is constant along a left diagonal
        right_diag: set[int] = set()   # r + c is constant along a right diagonal

        def backtrack(r: int) -> None:
            if r == n:                  # all rows filled, valid solution
                res.append(["".join(row) for row in board])
                return
            for c in range(n):
                if c in cols or (r - c) in left_diag or (r + c) in right_diag:
                    continue            # this column is under attack, prune
                # choose
                cols.add(c)
                left_diag.add(r - c)
                right_diag.add(r + c)
                board[r][c] = "Q"
                # explore
                backtrack(r + 1)
                # undo
                cols.discard(c)
                left_diag.discard(r - c)
                right_diag.discard(r + c)
                board[r][c] = "."

        backtrack(0)
        return res
```

> The key insight is that `r - c` uniquely identifies a top-left-to-bottom-right diagonal and `r + c` uniquely identifies a top-right-to-bottom-left diagonal. Two cells share a diagonal if and only if they share that value, so a set lookup is sufficient for O(1) conflict detection without scanning the board.

### Complexity
- **Time:** O(N!). The first row has N choices, the second has at most N-1, and so on. The actual count of valid placements is much smaller.
- **Space:** O(N^2). The board is N x N; the sets and call stack are O(N).

### Key concepts to review
- [[0.BacktrackingGuide|Backtracking]] - row-by-row placement with three-set conflict detection and full undo.
- [[Set]] - O(1) lookup for column, left diagonal, and right diagonal conflicts.
- [[DFS|Depth-First Search]] - the recursive row-by-row traversal strategy.
- [[03.Permutations]] - each row places exactly one queen, so valid column assignments are a constrained permutation.

### Common pitfalls
- Using row-conflict detection: since we recurse row by row, two queens can never share a row - no `rows` set is needed.
- Forgetting to undo all three sets, leaving stale entries that prune valid placements in sibling branches.
- Using `r - c` for one diagonal type and `r + c` for the other but swapping their labels, causing incorrect conflict detection.
- Building the board snapshot with a reference to the inner lists rather than joining them into strings, producing a result that gets mutated after recording.
