# [17. Letter Combinations of a Phone Number](https://leetcode.com/problems/letter-combinations-of-a-phone-number/)


Given a string containing digits from 2-9 inclusive, return all possible letter combinations that the number could represent. Return the answer in any order.

A mapping of digit to letters (just like on the telephone buttons) is given below. Note that 1 does not map to any letters.

 

**Example 1:**

![[letter-combinations-phone-example.svg]]

```
Input: digits = "23"
Output: ["ad","ae","af","bd","be","bf","cd","ce","cf"]
```
**Example 2:**
```
Input: digits = ""
Output: []
```
**Example 3:**
```
Input: digits = "2"
Output: ["a","b","c"]
```

Constraints:

- 0 <= digits.length <= 4
- digits\[i\] is a digit in the range \['2', '9'\].

---

## Solution

### Intuition
Each digit maps to 2-4 letters. The problem asks for every combination formed by picking exactly one letter per digit in order. This is a [[0.BacktrackingGuide|Backtracking]] decision tree where each level corresponds to one digit and the branching factor equals the number of letters for that digit.

### Approach
Use a digit-to-letters mapping. Recurse through each digit index, appending one letter at a time to the current path. Because strings are immutable in Python, passing `path + letter` automatically "undoes" on return without an explicit pop step.

```python
class Solution:
    def letterCombinations(self, digits: str) -> list[str]:
        if not digits:
            return []

        phone_map: dict[str, str] = {
            "2": "abc", "3": "def", "4": "ghi",
            "5": "jkl", "6": "mno", "7": "pqrs",
            "8": "tuv", "9": "wxyz",
        }
        res: list[str] = []

        def backtrack(idx: int, path: str) -> None:
            if idx == len(digits):      # one letter chosen per digit
                res.append(path)
                return
            for letter in phone_map[digits[idx]]:
                backtrack(idx + 1, path + letter)  # new string = automatic undo

        backtrack(0, "")
        return res
```

> Because `path + letter` creates a new string object rather than mutating the existing one, there is no explicit "undo" step needed. This contrasts with list-based [[0.BacktrackingGuide|Backtracking]] where `path.pop()` is required. The trade-off is that each recursive call allocates a new string, which is fine here given the constraint of at most 4 digits.

### Complexity
- **Time:** O(4^N * N) where N is the number of digits. Each digit branches up to 4 ways, and building each result string is O(N).
- **Space:** O(N). The recursion stack depth equals the number of digits.

### Key concepts to review
- [[0.BacktrackingGuide|Backtracking]] - one decision per digit, branching by letters mapped to that digit.
- [[Hash Map]] - the phone mapping is a dictionary lookup at each level.
- [[Recursion]] - tree depth exactly equals the number of digits.
- [[02.CombinationSum]] - another multi-way branching backtracking problem.

### Common pitfalls
- Not handling the empty string edge case, which would add an empty string to results.
- Mutating a shared list for `path` without popping, requiring explicit undo unlike the immutable string approach here.
- Using `idx >= len(digits)` as the base case instead of `idx == len(digits)`, which works but is less precise.
- Forgetting that digit '7' maps to 4 letters ("pqrs") and '9' also maps to 4 ("wxyz"), so the branching factor is not always 3.
