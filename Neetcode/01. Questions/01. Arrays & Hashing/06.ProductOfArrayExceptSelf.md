# 238. Product of Array Except Self


Given an integer array nums, return an array answer such that answer[i] is equal to the product of all the elements of nums except nums[i].

The product of any prefix or suffix of nums is guaranteed to fit in a 32-bit integer.

You must write an algorithm that runs in O(n) time and without using the division operation.

 

**Example 1:**

```text
Input: nums = [1,2,3,4]
Output: [24,12,8,6]
```

**Example 2:**

```text
Input: nums = [-1,1,0,-3,3]
Output: [0,0,9,0,0]
```

Constraints:

- 2 <= nums.length <= 105
- -30 <= nums[i] <= 30
- The product of any prefix or suffix of nums is guaranteed to fit in a 32-bit integer.

Follow up: Can you solve the problem in O(1) extra space complexity? (The output array does not count as extra space for space complexity analysis.)

---

## Solution

### Intuition

The product of everything except `nums[i]` equals (product of all elements to its left) times (product of all elements to its right). If we precompute those left and right running products, each answer is a single multiplication. This is the [[Prefix Sum]] idea applied to products, and it sidesteps the banned division operator (which would also break on zeros).

### Approach 1: Brute force (for contrast)

For each index, multiply every other element.

```python
class Solution:
    def productExceptSelf(self, nums: list[int]) -> list[int]:
        n = len(nums)
        res = []
        for i in range(n):
            prod = 1
            for j in range(n):
                if i != j:
                    prod *= nums[j]
            res.append(prod)
        return res
```

This is O(n^2), too slow for n up to 10^5.

### Approach 2: Prefix and suffix products (optimal)

Do two passes over the output array. The first pass fills each slot with the product of everything to its left. The second pass walks right to left, multiplying in the running product of everything to the right.

```python
class Solution:
    def productExceptSelf(self, nums: list[int]) -> list[int]:
        n = len(nums)
        res = [1] * n

        prefix = 1
        for i in range(n):
            res[i] = prefix         # product of all elements before i
            prefix *= nums[i]

        suffix = 1
        for i in range(n - 1, -1, -1):
            res[i] *= suffix        # fold in product of all elements after i
            suffix *= nums[i]

        return res
```

> This meets the O(1) extra space follow-up: the output array does not count, and we use only the two scalars `prefix` and `suffix`, not separate left/right arrays.

### Walkthrough

`nums = [1, 2, 3, 4]`

| i | prefix pass: res[i] = prefix | prefix after |
|---|------------------------------|--------------|
| 0 | 1                            | 1 |
| 1 | 1                            | 2 |
| 2 | 2                            | 6 |
| 3 | 6                            | 24 |

| i | suffix pass: res[i] *= suffix | suffix after |
|---|-------------------------------|--------------|
| 3 | 6 * 1 = 6                      | 4 |
| 2 | 2 * 4 = 8                      | 12 |
| 1 | 1 * 12 = 12                    | 24 |
| 0 | 1 * 24 = 24                    | 24 |

Output: `[24, 12, 8, 6]`.

### Complexity

- **Time:** O(n). Two linear passes over the array.
- **Space:** O(1) extra, ignoring the output array, since only two running-product scalars are kept.

### Key concepts to review

- [[Prefix Sum]] - here adapted to running products; precomputing cumulative values turns repeated range queries into O(1) lookups.
- [[Space-Time Tradeoff]] - we reuse the output array to avoid separate left/right buffers and hit O(1) extra space.

### Common pitfalls

- Reaching for division; it is banned and would fail when any element is 0.
- Allocating separate left and right product arrays, which works but misses the O(1) space follow-up.
- Off-by-one in the suffix loop range; it must include index 0 (`range(n - 1, -1, -1)`).
