# 1. Two Sum

Given an array of integers nums and an integer target, return indices of the two numbers such that they add up to target.

You may assume that each input would have exactly one solution, and you may not use the same element twice.

You can return the answer in any order.

 

**Example 1:**

```text
Input: nums = [2,7,11,15], target = 9
Output: [0,1]
Explanation: Because nums[0] + nums[1] == 9, we return [0, 1].
```

**Example 2:**

```text
Input: nums = [3,2,4], target = 6
Output: [1,2]
```

**Example 3:**

```text
Input: nums = [3,3], target = 6
Output: [0,1]
```

Constraints:

- 2 <= nums.length <= 104
- -109 <= nums[i] <= 109
- -109 <= target <= 109
- Only one valid answer exists.
 

Follow-up: Can you come up with an algorithm that is less than O(n2) time complexity?

---

## Solution

### Intuition

For every number `x` in the array, we are really asking one question: "Have I already seen the number `target - x`?" That missing partner is called the **complement**. If we have seen it, we are done. If we have not, we remember `x` so that a later number can find it.

The trick is making "have I already seen it?" fast. Scanning the rest of the array each time is slow. A [[Hash Map]] answers that lookup in O(1) on average, which is what lets us beat the brute force O(n^2).

### Approach 1: Brute force (for contrast)

Check every pair `(i, j)` and see if they add to `target`.

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):      # j starts after i so we never reuse an element
                if nums[i] + nums[j] == target:
                    return [i, j]
        return []
```

This works but is O(n^2) time. The follow-up explicitly asks us to do better, which is the hint to trade memory for speed.

### Approach 2: One-pass hash map (optimal)

Walk the array once. At each index, first check whether the current number's complement is already in the map. If yes, return both indices. If no, store the current number and its index so future numbers can match against it.

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        seen: dict[int, int] = {}          # value -> index of values we've passed

        for i, num in enumerate(nums):
            complement = target - num      # the partner we'd need to hit target
            if complement in seen:         # O(1) average lookup
                return [seen[complement], i]
            seen[num] = i                  # remember this number for a future match

        return []                          # problem guarantees we never reach here
```

> Why check the complement *before* inserting? It guarantees we never pair an element with itself. The current element is only added to the map after we have failed to match it, so a later element can pick it up but the current one cannot match its own slot.

### Walkthrough

`nums = [3, 2, 4]`, `target = 6`

| i | num | complement (6 - num) | complement in `seen`? | action | `seen` after |
|---|-----|----------------------|------------------------|--------|--------------|
| 0 | 3   | 3                    | no                     | store 3 | `{3: 0}` |
| 1 | 2   | 4                    | no                     | store 2 | `{3: 0, 2: 1}` |
| 2 | 4   | 2                    | yes (index 1)          | return `[1, 2]` | -- |

Output: `[1, 2]`, because `nums[1] + nums[2] = 2 + 4 = 6`.

### Complexity

- **Time:** O(n). Each element is visited once and each hash lookup/insert is O(1) on average.
- **Space:** O(n). In the worst case the map holds almost every element before a match is found.

This is the classic **space-for-time** tradeoff: we spend O(n) memory to turn an O(n^2) scan into an O(n) pass. See [[Big-O Notation]].

### Key concepts to review

- [[Hash Map]] - O(1) average lookup is the engine behind the speedup.
- [[Complement Pattern]] - "search for `target - x`" recurs in [[02.TwoSumII]], [[03.3Sum]], and many sum problems.
- [[Space-Time Tradeoff]] - extra memory to cut down runtime.
- [[Big-O Notation]] - reasoning about why O(n) beats O(n^2).

### Common pitfalls

- Returning the values instead of the **indices** that the problem asks for.
- Inserting into the map before checking the complement, which can let an element falsely match itself when `target == 2 * num`.
- Assuming the input is sorted. It is not. If it were, the [[0.TwoPointerGuide|Two Pointer]] approach in [[02.TwoSumII]] would use O(1) space instead.
