# 242. Valid Anagram

Given two strings s and t, return true if t is an anagram of s, and false otherwise.

An Anagram is a word or phrase formed by rearranging the letters of a different word or phrase, typically using all the original letters exactly once.

 

**Example 1:**

```text
Input: s = "anagram", t = "nagaram"
Output: true
```

**Example 2:**

```text
Input: s = "rat", t = "car"
Output: false
```

Constraints:

- 1 <= s.length, t.length <= 5 * 104
- s and t consist of lowercase English letters.

Follow up: What if the inputs contain Unicode characters? How would you adapt your solution to such a case?

---

## Solution

### Intuition

Two strings are anagrams if and only if they contain the exact same letters with the exact same counts. So the whole problem reduces to comparing letter frequencies. If every character appears the same number of times in both strings, they are anagrams. This is a textbook use of [[Frequency Counting]] backed by a [[Hash Map]].

### Approach 1: Sorting (for contrast)

If you sort both strings, anagrams collapse to the identical string.

```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        return sorted(s) == sorted(t)
```

Simple, but sorting costs O(n log n), and we can do better by counting.

### Approach 2: Frequency count (optimal)

Count characters in `s`, then decrement for each character in `t`. If the multisets match, all counts return to zero. An early length check short-circuits obvious non-anagrams.

```python
from collections import Counter

class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):          # different lengths can never be anagrams
            return False
        return Counter(s) == Counter(t)   # compares letter -> count maps directly
```

> The length check is not strictly required since `Counter` equality would also catch a mismatch, but it lets us bail out in O(1) before building any maps.

### Walkthrough

`s = "anagram"`, `t = "nagaram"`

| step | structure | state |
|------|-----------|-------|
| count `s` | `Counter(s)` | `{a:3, n:1, g:1, r:1, m:1}` |
| count `t` | `Counter(t)` | `{n:1, a:3, g:1, r:1, m:1}` |
| compare | equal? | yes |

Output: `True`.

### Complexity

- **Time:** O(n). We scan each string once to build its counter.
- **Space:** O(1) for lowercase English (at most 26 keys); O(k) in general where k is the alphabet size.

### Key concepts to review

- [[Frequency Counting]] - counting occurrences is the core technique here and in [[04.GroupAnagrams]].
- [[Hash Map]] - `Counter` is a dict subclass; O(1) average updates drive the linear time.
- [[Sorting]] - the alternative approach, slower at O(n log n) but needs no extra structure.

### Common pitfalls

- Forgetting the length check, which can mask a difference if you only verify that each char in `t` exists in `s`.
- For the Unicode follow-up, do not hardcode a size-26 array; use a [[Hash Map]] / `Counter` that scales to any alphabet.
- Comparing strings character by character without accounting for counts (e.g. just using a set), which loses multiplicity.
