# 347. Top K Frequent Elements

Given an integer array nums and an integer k, return the k most frequent elements. You may return the answer in any order.

 

**Example 1:**

```text
Input: nums = [1,1,1,2,2,3], k = 2
Output: [1,2]
```

**Example 2:**

```text
Input: nums = [1], k = 1
Output: [1]
```

Constraints:

- 1 <= nums.length <= 105
- k is in the range [1, the number of unique elements in the array].
- It is guaranteed that the answer is unique.

Follow up: Your algorithm's time complexity must be better than O(n log n), where n is the array's size.

---

## Solution

### Intuition

First count how often each number appears with [[Frequency Counting]]. The question then becomes "which k counts are largest?" A full sort of all unique values is O(m log m), but we only need the top k, so a [[Heap]] of size k, or better, bucket sort by frequency, gets us under O(n log n).

### Approach 1: Heap

Count frequencies, then use `heapq.nlargest` to pull the k highest-frequency values.

```python
from collections import Counter
import heapq

class Solution:
    def topKFrequent(self, nums: list[int], k: int) -> list[int]:
        counts = Counter(nums)                       # value -> frequency
        return heapq.nlargest(k, counts.keys(), key=counts.get)
```

`nlargest` keeps a heap of size k, giving O(m log k) where m is the number of unique values. Good, but for the strict follow-up we can hit true O(n).

### Approach 2: Bucket sort (optimal)

A value's frequency is at most `len(nums)`, so index buckets by frequency. Walk buckets from high frequency to low and collect until we have k values.

```python
from collections import Counter

class Solution:
    def topKFrequent(self, nums: list[int], k: int) -> list[int]:
        counts = Counter(nums)
        # buckets[f] holds all values that appear exactly f times
        buckets: list[list[int]] = [[] for _ in range(len(nums) + 1)]
        for num, freq in counts.items():
            buckets[freq].append(num)

        result: list[int] = []
        for freq in range(len(nums), 0, -1):   # high frequency first
            for num in buckets[freq]:
                result.append(num)
                if len(result) == k:           # stop as soon as we have k
                    return result
        return result
```

> Bucket indices run from 0 to `len(nums)` because a value can appear at most `len(nums)` times. Index 0 is never used (every counted value has frequency >= 1) but keeping it simplifies the indexing.

### Walkthrough

`nums = [1,1,1,2,2,3]`, `k = 2`

| step | structure | state |
|------|-----------|-------|
| count | `Counter` | `{1:3, 2:2, 3:1}` |
| bucket | `buckets` | `[[], [3], [2], [1], [], [], []]` (index = freq) |
| scan freq 6..1 | collect | freq 3 -> add 1; freq 2 -> add 2; len == k |

Output: `[1, 2]`.

### Complexity

- **Time:** O(n). Counting is O(n), bucket fill is O(m), and the bucket scan visits O(n) slots total.
- **Space:** O(n). The counter and buckets together hold O(n) entries.

### Key concepts to review

- [[Frequency Counting]] - the first step in nearly every "top k by count" problem.
- [[Heap]] - the O(m log k) alternative; ideal when k is small relative to m.
- [[Hash Map]] - `Counter` backs the frequency table with O(1) average updates.

### Common pitfalls

- Sizing the bucket array to `len(nums)` instead of `len(nums) + 1`, causing an index-out-of-range for a value that fills the whole array.
- Forgetting to stop once k values are collected, which still works but wastes time.
- Reaching for a full sort and failing the better-than-O(n log n) follow-up.
