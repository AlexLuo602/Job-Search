# 49. Group Anagrams


Given an array of strings strs, group the anagrams together. You can return the answer in any order.

An Anagram is a word or phrase formed by rearranging the letters of a different word or phrase, typically using all the original letters exactly once.

 

**Example 1:**

```text
Input: strs = ["eat","tea","tan","ate","nat","bat"]
Output: [["bat"],["nat","tan"],["ate","eat","tea"]]
```

**Example 2:**

```text
Input: strs = [""]
Output: [[""]]
```

**Example 3:**

```text
Input: strs = ["a"]
Output: [["a"]]
```

Constraints:

- 1 <= strs.length <= 104
- 0 <= strs[i].length <= 100
- strs[i] consists of lowercase English letters.

---

## Solution

### Intuition

Anagrams share an identical multiset of letters, so they need a canonical "signature" that is the same for every word in a group. If we can map each word to such a signature, we just bucket words by that signature in a [[Hash Map]]. The two natural signatures are the sorted string or the per-letter count tuple. See [[02.ValidAnagram]] for the same equivalence idea applied to a single pair.

### Approach 1: Sorted-string key

Sort each word; anagrams produce the same sorted string, which becomes the dictionary key.

```python
from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: list[str]) -> list[list[str]]:
        groups: dict[str, list[str]] = defaultdict(list)
        for s in strs:
            key = "".join(sorted(s))   # canonical form shared by all anagrams
            groups[key].append(s)
        return list(groups.values())
```

This is clean but sorting each word costs O(k log k), so total time is O(n * k log k).

### Approach 2: Count-tuple key (optimal)

Instead of sorting, use a length-26 count vector as the key. Building it is O(k) per word, removing the log factor.

```python
from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: list[str]) -> list[list[str]]:
        groups: dict[tuple[int, ...], list[str]] = defaultdict(list)
        for s in strs:
            count = [0] * 26               # counts for 'a'..'z'
            for ch in s:
                count[ord(ch) - ord("a")] += 1
            groups[tuple(count)].append(s)  # tuple is hashable, so usable as a key
        return list(groups.values())
```

> The key must be hashable. A Python `list` is mutable and unhashable, so we convert the count vector to a `tuple` before using it as a dictionary key.

### Walkthrough

`strs = ["eat", "tea", "tan", "ate"]` using count keys

| word | count signature (nonzero) | bucket after |
|------|---------------------------|--------------|
| eat  | a:1,e:1,t:1               | `{(eat-sig): [eat]}` |
| tea  | a:1,e:1,t:1               | `{(eat-sig): [eat, tea]}` |
| tan  | a:1,n:1,t:1               | `{..., (tan-sig): [tan]}` |
| ate  | a:1,e:1,t:1               | `{(eat-sig): [eat, tea, ate], (tan-sig): [tan]}` |

Output: `[["eat","tea","ate"], ["tan"]]`.

### Complexity

- **Time:** O(n * k), where n is the number of words and k is the max word length; each word's count signature is built in O(k).
- **Space:** O(n * k) to store all words across the buckets.

### Key concepts to review

- [[Hash Map]] - bucketing by a canonical key is the heart of the solution.
- [[Frequency Counting]] - the count-tuple signature avoids the sort, same idea as [[02.ValidAnagram]].
- [[Sorting]] - the alternative signature; simpler code, slower by a log factor.

### Common pitfalls

- Using a mutable `list` as a dict key, which raises `TypeError`; convert to a `tuple`.
- Returning the dictionary itself instead of `list(groups.values())`.
- Assuming groups come back in a particular order; the problem allows any order.
