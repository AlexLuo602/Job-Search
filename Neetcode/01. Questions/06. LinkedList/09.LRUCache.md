# 146. LRU Cache


Design a data structure that follows the constraints of a Least Recently Used (LRU) cache.

Implement the LRUCache class:
- `LRUCache(int capacity)` Initialize the LRU cache with positive size capacity.
- `int get(int key)` Return the value of the key if the key exists, otherwise return -1.
- `void put(int key, int value)` Update the value of the key if the key exists. Otherwise, add the key-value pair to the cache. If the number of keys exceeds the capacity from this operation, evict the least recently used key.
- The functions get and put must each run in O(1) average time complexity.

 

**Example 1:**

```text
Input
["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]
[[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]]
Output
[null, null, null, 1, null, -1, null, -1, 3, 4]

Explanation
LRUCache lRUCache = new LRUCache(2);
lRUCache.put(1, 1); // cache is {1=1}
lRUCache.put(2, 2); // cache is {1=1, 2=2}
lRUCache.get(1);    // return 1
lRUCache.put(3, 3); // LRU key was 2, evicts key 2, cache is {1=1, 3=3}
lRUCache.get(2);    // returns -1 (not found)
lRUCache.put(4, 4); // LRU key was 1, evicts key 1, cache is {4=4, 3=3}
lRUCache.get(1);    // return -1 (not found)
lRUCache.get(3);    // return 3
lRUCache.get(4);    // return 4
```

Constraints:

- 1 <= capacity <= 3000
- 0 <= key <= 10<sup>4</sup>
- 0 <= value <= 10<sup>5</sup>
- At most 2 * 10<sup>5</sup> calls will be made to get and put.

## Solution

### Intuition
O(1) `get` requires instant lookup, so use a [[Hash Map]] from key to node. O(1) `put` with eviction requires instant removal of the LRU node and insertion of a new one. A doubly [[Linked List]] with sentinel head and tail satisfies both: any node can be unlinked in O(1) given a pointer to it, and insertion at the "most-recently-used" end is also O(1). The map and the list together are the classic LRU combination seen in caches.

### Approach: Optimal (doubly linked list + hash map)
"Most recently used" = just after the head sentinel. "Least recently used" = just before the tail sentinel. On every `get` or `put`, move the affected node to the MRU position. On overflow, remove the node just before the tail.

```python
class Node:
    # doubly linked list node storing key so we can delete it from the map on eviction
    def __init__(self, key: int = 0, val: int = 0):
        self.key = key
        self.val = val
        self.prev: 'Node | None' = None
        self.next: 'Node | None' = None

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.cache: dict[int, Node] = {}   # key -> node
        # sentinel head (MRU side) and tail (LRU side) - no real data
        self.head = Node()
        self.tail = Node()
        self.head.next = self.tail
        self.tail.prev = self.head

    # --- helpers ---
    def _remove(self, node: Node) -> None:
        """Unlink node from the doubly linked list."""
        node.prev.next = node.next  # bridge over the node
        node.next.prev = node.prev

    def _insert_front(self, node: Node) -> None:
        """Insert node right after head (MRU position)."""
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    # --- API ---
    def get(self, key: int) -> int:
        if key not in self.cache:
            return -1
        node = self.cache[key]
        self._remove(node)        # pull out of current position
        self._insert_front(node)  # move to MRU end
        return node.val

    def put(self, key: int, value: int) -> None:
        if key in self.cache:
            self._remove(self.cache[key])   # evict old entry first
            del self.cache[key]
        if len(self.cache) == self.cap:
            # evict LRU: node just before tail
            lru = self.tail.prev
            self._remove(lru)
            del self.cache[lru.key]         # need the key stored in the node
        node = Node(key, value)
        self._insert_front(node)
        self.cache[key] = node
```

> The sentinel (dummy) head and tail eliminate all boundary checks: `_remove` and `_insert_front` work identically whether the list has one node or a thousand, because there is always a valid `prev` and `next` thanks to the sentinels.

### Complexity
- **Time:** O(1) for both `get` and `put`. Hash map lookup is O(1); list insert/remove of a known node is O(1).
- **Space:** O(capacity). The map and list together hold at most `capacity` nodes.

### Key concepts to review
- [[Hash Map]] - O(1) key-to-node lookup; see [[05.CopyListWithRandomPointer]].
- [[Linked List]] - doubly linked so removal is O(1) without scanning for the predecessor.
- [[Dummy Head|Dummy Node]] - sentinel head and tail simplify boundary cases for insert and remove.
- [[Space-Time Tradeoff]] - storing the key inside each node costs a little space but makes O(1) map cleanup on eviction possible.

### Common pitfalls
- Storing only the value (not the key) in the node, making it impossible to delete the evicted entry from the map.
- Forgetting to update `del self.cache[key]` after removing an existing key in `put`, causing the cache to think capacity is lower than it is.
- Linking sentinel nodes head-to-tail during `__init__`; skipping this causes a crash on the first insert.
- Doing the eviction check after inserting the new node rather than before, causing a momentary over-capacity.
