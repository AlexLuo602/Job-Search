# [25. Reverse Nodes in k-Group](https://leetcode.com/problems/reverse-nodes-in-k-group/)


Given the head of a linked list, reverse the nodes of the list k at a time, and return the modified list.

k is a positive integer and is less than or equal to the length of the linked list. If the number of nodes is not a multiple of k then left-out nodes, in the end, should remain as it is.

You may not alter the values in the list's nodes, only nodes themselves may be changed.

 

**Example 1:**

![[reverse-nodes-k-group-example.svg]]

```
Input: head = [1,2,3,4,5], k = 2
Output: [2,1,4,3,5]
```

**Example 2:**

```
Input: head = [1,2,3,4,5], k = 3
Output: [3,2,1,4,5]
```

Constraints:
- The number of nodes in the list is n.
- 1 <= k <= n <= 5000
- 0 <= Node.val <= 1000
 

> Follow-up: Can you solve the problem in O(1) extra memory space?

---

## Solution

### Intuition
Generalise [[Linked List Reversal|In-place Reversal]] (from [[01.ReverseLinkedList]]) to chunks of k nodes. Walk a pointer k steps to confirm a full group exists, reverse exactly those k nodes, then reconnect the reversed segment to the rest of the list. A [[Dummy Head|Dummy Node]] before the head gives a stable anchor so the very first group can be connected the same way as all others.

### Approach: Optimal (iterative, O(1) space)
For each group: check that k nodes remain (skip otherwise), advance a pointer k steps to find the boundary, reverse the k nodes, then wire `group_prev.next` to the new head and the original group head (now the tail) to `curr` (the start of the next group).

```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next
from typing import Optional

class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        group_prev = dummy          # node just before the current group

        while True:
            # check that k nodes remain starting from group_prev.next
            kth = self._get_kth(group_prev, k)
            if not kth:
                break               # fewer than k nodes left - leave as-is

            group_next = kth.next   # first node of the next group

            # reverse k nodes between group_prev and group_next
            prev, curr = group_next, group_prev.next
            while curr != group_next:
                nxt = curr.next
                curr.next = prev    # flip pointer
                prev = curr
                curr = nxt

            # reconnect: group_prev -> new head (kth), original head -> group_next
            tmp = group_prev.next   # original first node (now the tail after reversal)
            group_prev.next = kth   # kth is the new head of this reversed group
            group_prev = tmp        # advance anchor to the tail of the reversed group

        return dummy.next

    def _get_kth(self, node: Optional[ListNode], k: int) -> Optional[ListNode]:
        """Return the kth node after `node`, or None if fewer than k nodes exist."""
        while node and k > 0:
            node = node.next
            k -= 1
        return node
```

> The reversed group's original first node (`tmp`) becomes the new `group_prev` because after reversal it is the tail of the group, and the next group starts right after it.

### Complexity
- **Time:** O(n). Every node is visited at most twice: once by `_get_kth` and once during reversal.
- **Space:** O(1). All pointer manipulation is in place.

### Key concepts to review
- [[Linked List Reversal|In-place Reversal]] - reversing k nodes at a time; see [[01.ReverseLinkedList]] for the base case.
- [[Dummy Head|Dummy Node]] - the sentinel anchor makes reconnecting the first group identical to all later groups.
- [[Linked List]] - careful sequencing of pointer assignments during both reversal and reconnection.

### Common pitfalls
- Forgetting to save `group_next` before reversing; the reversal overwrites the links into the next group.
- Advancing `group_prev` to `kth` instead of `tmp` (the original group head), leaving the anchor one node too far and misconnecting the next group.
- Not checking for a full group of k before reversing; reversing a partial tail is incorrect.
