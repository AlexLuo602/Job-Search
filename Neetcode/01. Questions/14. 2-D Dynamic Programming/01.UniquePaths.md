# [62. Unique Paths](https://leetcode.com/problems/unique-paths/)


There is a robot on an m x n grid. The robot is initially located at the top-left corner (i.e., grid[0][0]). The robot tries to move to the bottom-right corner (i.e., grid[m - 1][n - 1]). The robot can only move either down or right at any point in time.

Given the two integers m and n, return the number of possible unique paths that the robot can take to reach the bottom-right corner.

The test cases are generated so that the answer will be less than or equal to 2 * 109.
**Example 1:**

![[unique-paths-example.svg]]

```
Input: m = 3, n = 7
Output: 28
```
**Example 2:**

```
Input: m = 3, n = 2
Output: 3
Explanation: From the top-left corner, there are a total of 3 ways to reach the bottom-right corner:
1. Right -> Down -> Down
2. Down -> Down -> Right
3. Down -> Right -> Down
```

Constraints:

- 1 <= m, n <= 100

---

## Solution

### Intuition

`dp[i][j]` represents the number of unique paths to reach cell `(i, j)`. Since the robot can only move right or down, the number of paths to any cell is the sum of paths from the cell above and the cell to the left: `dp[i][j] = dp[i-1][j] + dp[i][j-1]`. Every cell on the top row and left column has exactly one path (only one direction to reach it), giving clean base cases.

**Recurrence:** `dp(i, j) = dp(i-1, j) + dp(i, j-1)` with `dp(0, j) = dp(i, 0) = 1`.

### Approach 1: Top-down memoization

Define `dp(i, j)` as the number of paths from `(0, 0)` to `(i, j)`. Recurse by asking: "How many paths reach the cell above?" and "How many paths reach the cell to the left?" Cache every result so each `(i, j)` pair is solved once.

```python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        memo = {}

        def dp(i: int, j: int) -> int:
            if (i, j) in memo:
                return memo[(i, j)]
            if i == 0 or j == 0:
                memo[(i, j)] = 1  # top row or left column: only one path
                return 1
            memo[(i, j)] = dp(i - 1, j) + dp(i, j - 1)
            return memo[(i, j)]

        return dp(m - 1, n - 1)
```

### Approach 2: Bottom-up tabulation

Fill a grid left-to-right, top-to-bottom. Each cell depends only on its top and left neighbors. The space can be reduced to 1-D by reusing a single row.

```python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        dp = [[1] * n for _ in range(m)]
        for i in range(1, m):
            for j in range(1, n):
                dp[i][j] = dp[i-1][j] + dp[i][j-1]
        return dp[m-1][n-1]

    def uniquePaths_optimized(self, m: int, n: int) -> int:
        row = [1] * n
        for _ in range(1, m):
            for j in range(1, n):
                row[j] += row[j-1]
        return row[n-1]
```

> `dp[0][j]` and `dp[i][0]` are all 1 because there is only one way to travel along the top row (pure right) or left column (pure down). Initializing the 2-D array with 1s handles both base cases simultaneously.

### Complexity

- **Time:** O(m * n). Every cell is computed once in both approaches.
- **Space:** O(m * n) for the 2-D table. O(n) for the rolling 1-D version.

### Key concepts to review

- [[Dynamic Programming]] - grid DP where each cell depends on neighbors.
- [[Memoization]] - top-down alternative caching each `(i, j)` result in an explicit dictionary.
- [[Space-Time Tradeoff]] - rolling 1-D array reduces space without affecting time.
- [[02.LongestCommonSubsequence]] - another 2-D DP that also reduces to 1-D.

### Common pitfalls

- Forgetting that the first row and first column must all be initialized to 1, not 0.
- Using bottom-up traversal from `(m-1, n-1)` without adjusting base cases for last row/column.
- Off-by-one errors when indexing dp vs. grid dimensions.
- Reducing space to 1-D without accounting for the dependency order (must iterate left-to-right within each row).
