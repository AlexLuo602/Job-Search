# 115. Distinct Subsequences

Given two strings s and t, return the number of distinct subsequences of s which equals t.
**Example 1:**

```
Input: s = "rabbbit", t = "rabbit"
Output: 3
```
**Example 2:**

```
Input: s = "babgbag", t = "bag"
Output: 5
```

Constraints:
- 1 <= s.length, t.length <= 1000
- s and t consist of English letters

---

## Solution

### Intuition

`dp(i, j)` represents the number of distinct subsequences of `s[:i]` that equal `t[:j]`. For each character in s, we can either skip it (always carry forward the previous count: `dp(i-1, j)`) or, if `s[i-1] == t[j-1]`, use it to match the current character in t (adding `dp(i-1, j-1)`).

**Recurrence:**
- `dp(i, j) = dp(i-1, j) + (dp(i-1, j-1) if s[i-1] == t[j-1] else 0)`
- Base case: `dp(i, 0) = 1` for all i (one way to form the empty target: select nothing). `dp(0, j) = 0` for j > 0 (cannot form a non-empty target from an empty source).

This is a [[Dynamic Programming]] counting problem on two string pointers.

### Approach 1: Top-down memoization

Define `dp(i, j)` as the count of distinct subsequences of `s[:i]` matching `t[:j]`. At each step, always include the "skip s\[i-1\]" count, and add the "use s\[i-1\]" count when characters match. Cache every `(i, j)` pair so each is computed once.

```python
class Solution:
    def numDistinct(self, s: str, t: str) -> int:
        m, n = len(s), len(t)
        memo = {}

        def dp(i: int, j: int) -> int:
            if j == 0:
                return 1  # empty target: one way (select nothing)
            if i == 0:
                return 0  # empty source: no way to form non-empty target
            if (i, j) in memo:
                return memo[(i, j)]
            # Always have the option to skip s[i-1]
            result = dp(i - 1, j)
            # If characters match, also count using s[i-1] to match t[j-1]
            if s[i - 1] == t[j - 1]:
                result += dp(i - 1, j - 1)
            memo[(i, j)] = result
            return result

        return dp(m, n)
```

### Approach 2: Bottom-up tabulation

Build an `(m+1) x (n+1)` table. `dp[i][0] = 1` for all i because there is exactly one way to form the empty target (select nothing). `dp[0][j] = 0` for j > 0 because you cannot form a non-empty target from an empty source. Fill row by row.

```python
class Solution:
    def numDistinct(self, s: str, t: str) -> int:
        m, n = len(s), len(t)
        # dp[i][j] = number of ways to form t[:j] from s[:i]
        dp = [[0] * (n + 1) for _ in range(m + 1)]

        # Base case: empty t can always be formed (1 way: select nothing)
        for i in range(m + 1):
            dp[i][0] = 1

        for i in range(1, m + 1):
            for j in range(1, n + 1):
                # Always have the option to skip s[i-1]
                dp[i][j] = dp[i-1][j]
                # Additionally, if characters match, use s[i-1] to match t[j-1]
                if s[i-1] == t[j-1]:
                    dp[i][j] += dp[i-1][j-1]

        return dp[m][n]

    def numDistinct_optimized(self, s: str, t: str) -> int:
        # 1-D rolling array: process right to left to avoid using updated values
        n = len(t)
        dp = [0] * (n + 1)
        dp[0] = 1  # base case: empty t

        for ch_s in s:
            # Iterate right to left so dp[j-1] still reflects the previous row
            for j in range(n, 0, -1):
                if ch_s == t[j-1]:
                    dp[j] += dp[j-1]

        return dp[n]
```

> In the 1-D optimized version we iterate `j` from right to left. If we went left to right, `dp[j-1]` would already reflect the current character of s being used for position j-1, which would allow the same s character to be matched multiple times.

### Complexity

- **Time:** O(m * n). Each (i, j) cell is computed once.
- **Space:** O(m * n) for the 2-D table. O(n) for the 1-D optimized version.

### Key concepts to review

- [[Dynamic Programming]] - 2-D string DP where we count ways to embed one string into another.
- [[Memoization]] - top-down alternative caching each `(i, j)` result in an explicit dictionary.
- [[Space-Time Tradeoff]] - 1-D reduction requires right-to-left iteration to preserve correctness.
- [[02.LongestCommonSubsequence]] - similar 2-D string table but maximizes length instead of counting.
- [[09.EditDistance]] - also a 2-D string DP. Compare the recurrence structures.

### Common pitfalls

- Forgetting `dp[i][0] = 1` for all i. There is always exactly one way to match the empty target.
- In the 1-D version, iterating left to right instead of right to left (allows the same s character to match multiple t positions).
- Integer overflow on large inputs. Python handles big integers natively, but other languages may need `long`.
- Confusing this with LCS: here we count distinct subsequences of s equaling t exactly, not the length of the longest shared subsequence.
