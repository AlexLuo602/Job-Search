# 2-D Dynamic Programming Guide

> **Core idea:** extend [[Dynamic Programming]] into two dimensions either by tracking two indices into separate sequences or by letting a second axis encode a constraint such as capacity, cooldown, or budget. The state design is everything: once you can write "`dp[i][j]` = ___", the transition and iteration order follow mechanically.

## ⚡ Cheatsheet

| Pattern | Reach for it when… | Mechanism |
| --- | --- | --- |
| Grid DP | move through a 2-D grid with a fixed set of moves | `dp[r][c]` = best from top-left. Fill row-by-row |
| Grid [[DFS]] + memo | arbitrary moves, no fixed direction (longest path, reachability) | DFS from each cell, cache `(r, c)` result |
| Two-sequence DP | compare or align two strings / arrays | `dp[i][j]` over prefixes. Diagonal = match, edges = gap |
| Knapsack-style 2D | 1-D sequence + a numeric constraint (capacity, budget, count) | `dp[i][c]` = best using first `i` items with constraint `c` |
| Interval DP | optimize over contiguous sub-ranges of one sequence | `dp[i][j]` over range length. Try every split point `k` |

## How to think about it

1-D DP has one "position" to track. 2-D DP arises when you need **two independent pieces of information** to describe where you are in the search space. The second dimension is almost always one of:

- **A second sequence index**: You're aligning `s1[i]` with `s2[j]` (LCS, edit distance, interleaving).
- **A resource or constraint**: You're at item `i` with `capacity` remaining (knapsack, coin change 2, target sum).
- **A range boundary**: You're optimizing the sub-array `[i..j]` (burst balloons, palindrome partitioning).
- **A second grid coordinate**: You're at cell `(r, c)` (unique paths, longest increasing path).

The mental move that unlocks most problems: **ask "what do I need to know, beyond the current position, to make the right decision at this step?"** That answer becomes your second dimension.

Grid DFS with [[Memoization|memoization]] is technically 2-D DP. The cache `(r, c)` is your DP table. The reason to reach for it over a bottom-up grid loop is when **the recurrence goes in multiple directions** (up, down, left, right) rather than just top-to-bottom, left-to-right. [[07.LongestIncreasingPathInAMatrix|LongestIncreasingPathInAMatrix]] is the canonical example: you can only fill the table in sorted value order, which makes a loop awkward. DFS from each cell is cleaner.

## The five patterns

### Grid DP: fixed-direction traversal

You can only move right or down (or some fixed subset). Every cell depends only on cells you've already filled, so a simple nested loop works.

```python
# [[01.UniquePaths|UniquePaths]]: count paths from (0,0) to (m-1, n-1)
def uniquePaths(m: int, n: int) -> int:
    dp = [[1] * n for _ in range(m)]
    for r in range(1, m):
        for c in range(1, n):
            dp[r][c] = dp[r-1][c] + dp[r][c-1]
    return dp[m-1][n-1]
```

Each cell = left + above. Fill row-by-row so dependencies are always ready. The first row and column stay 1 because the only route goes straight. Every other cell adds paths from above and from the left.

### Grid DFS + memo: multi-directional traversal

When you can move in any direction (up/down/left/right), the dependencies are circular in a naive fill order. The fix: memoize a DFS instead of filling a table directly.

```python
# [[07.LongestIncreasingPathInAMatrix|LongestIncreasingPathInAMatrix]]
def longestIncreasingPath(matrix: list[list[int]]) -> int:
    rows, cols = len(matrix), len(matrix[0])
    memo = {}

    def dfs(r, c):
        if (r, c) in memo:
            return memo[(r, c)]
        best = 1
        for dr, dc in [(-1,0),(1,0),(0,-1),(0,1)]:
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols and matrix[nr][nc] > matrix[r][c]:
                best = max(best, 1 + dfs(nr, nc))
        memo[(r, c)] = best
        return best

    return max(dfs(r, c) for r in range(rows) for c in range(cols))
```

The DAG property (strictly increasing) guarantees no cycles, so DFS terminates. Without a strictly increasing (or decreasing) constraint, you'd need cycle detection.

### Two-sequence DP: aligning prefixes

The table has shape `(len(s1)+1) x (len(s2)+1)`. Row 0 and column 0 are base cases (empty prefix). The transition at `(i, j)` always depends on some combination of `(i-1, j-1)`, `(i-1, j)`, and `(i, j-1)`.

**LCS pattern**: Characters match -> extend diagonal. Mismatch -> take best of skipping either:

```python
# [[02.LongestCommonSubsequence|LongestCommonSubsequence]]
def longestCommonSubsequence(text1: str, text2: str) -> int:
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i-1] == text2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1      # match: extend diagonal
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])  # skip one char from either
    return dp[m][n]
```

```python
# [[09.EditDistance|EditDistance]]
def minDistance(word1: str, word2: str) -> int:
    m, n = len(word1), len(word2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1): dp[i][0] = i   # delete all of word1
    for j in range(n + 1): dp[0][j] = j   # insert all of word2
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if word1[i-1] == word2[j-1]:
                dp[i][j] = dp[i-1][j-1]
            else:
                dp[i][j] = 1 + min(
                    dp[i-1][j],    # delete from word1
                    dp[i][j-1],    # insert into word1
                    dp[i-1][j-1]   # replace
                )
    return dp[m][n]
```

The key insight shared by both LCS and edit distance is that `dp[i][j]` only asks about the prefixes `word1[:i]` and `word2[:j]`, so every shorter-prefix answer is already in the table.

### Knapsack-style 2D: sequence + numeric constraint

One axis is "how far through the items" and the other is "how much of the resource remains." The 2-D DP problem [[04.CoinChange2|CoinChange2]] is the canonical example. It's unbounded knapsack (coins can repeat):

```python
# [[04.CoinChange2|CoinChange2]]: number of ways to make amount using coins (unlimited each)
def change(amount: int, coins: list[int]) -> int:
    dp = [0] * (amount + 1)
    dp[0] = 1
    for coin in coins:
        for a in range(coin, amount + 1):   # left-to-right = unlimited use
            dp[a] += dp[a - coin]
    return dp[amount]
```

Here the 2-D table `dp[i][a]` (first `i` coins, amount `a`) collapses to 1-D because each row only needs the current row. Iterating left-to-right lets the same coin be reused.

**[[05.TargetSum|TargetSum]]** is the 0/1 variant (each number used exactly once). The standard trick is to convert it to subset sum with a sign flip, then use right-to-left iteration to prevent reuse.

**[[03.BestTimeToBuyAndSellStockWithCooldown|BestTimeToBuyAndSellStockWithCooldown]]** is a different shape: one axis is day index, the second axis is state (holding / not holding / cooldown). The transitions are:

```python
def maxProfit(prices: list[int]) -> int:
    hold = -float('inf')   # max profit while holding a stock
    free = 0               # max profit while free to buy
    cool = 0               # max profit on cooldown day
    for p in prices:
        hold, free, cool = max(hold, free - p), max(free, cool), hold + p
    return max(free, cool)
```

The "state machine" intuition: three states, three transitions, roll forward one day at a time.

```python
# [[10.BurstBalloons|BurstBalloons]]: the classic interval DP
def maxCoins(nums: list[int]) -> int:
    nums = [1] + nums + [1]   # sentinel borders
    n = len(nums)
    dp = [[0] * n for _ in range(n)]

    for length in range(2, n):           # interval length
        for left in range(0, n - length):
            right = left + length
            for k in range(left + 1, right):   # k = LAST balloon to burst
                coins = nums[left] * nums[k] * nums[right]
                dp[left][right] = max(dp[left][right],
                                      dp[left][k] + coins + dp[k][right])
    return dp[0][n - 1]
```

The key inversion is to treat `k` as the **last** balloon burst in `(left, right)`, not the first. When `k` is last, `left` and `right` are still standing, so the border multipliers are unambiguously `nums[left]` and `nums[right]`.

## How to approach a new problem

1. **Name your state.** Write the sentence: "`dp[i][j]` = ___." If you can't complete it unambiguously, you don't have the state yet. Try adding or removing a dimension.
2. **Identify the second dimension's origin.** Is it a second sequence index? A running constraint? An interval boundary? That tells you which pattern you're in.
3. **Write the transition for one cell, by hand, on a small example.** Draw a 3x3 or 4x4 table and fill one interior cell manually. The formula you use is your recurrence.
4. **Determine base cases.** Row 0 and column 0 usually represent an empty prefix, zero capacity, or another trivial input. Fill those states first.
5. **Choose fill order.** Standard two-sequence and grid DP: fill left-to-right, top-to-bottom. Interval DP: fill by increasing `(right - left)`. Knapsack: outer loop = items, inner = capacity.
6. **Check the answer location.** Is it `dp[m][n]`? `dp[0][n-1]`? `max(dp[i][j])`? This is easy to get wrong on interval DP.
7. **Edge cases.** Empty string(s), `m=0` or `n=0`, `amount=0`, single row/column grid. Trace through your recurrence on `n=0` and `n=1` before submitting.

## Worked example: Burst Balloons and why "last burst" matters

[[10.BurstBalloons|BurstBalloons]] trips people up because the naive recurrence "burst balloon `k` first in `[i..j]`" breaks the sub-interval independence: after bursting `k`, the borders of `[i..k-1]` and `[k+1..j]` change, so those sub-problems are no longer self-contained.

The fix is **reversing time**: define `k` as the last balloon you burst inside `(left, right)`. Now when you're computing `dp[left][right]`, both `dp[left][k]` and `dp[k][right]` are already done, and their border multipliers (`nums[left]`, `nums[right]`) haven't changed, because `left` and `right` are still standing. The sub-problems truly don't interfere.

Trace on `nums = [3, 1, 5, 8]` -> padded `[1, 3, 1, 5, 8, 1]`:

- `dp[0][5]` (the whole array) tries `k` in {1,2,3,4}.
- For `k=3` (burst balloon with value 5 last): coins = `nums[0]*5*nums[5]` = `1*5*1` = 5, plus `dp[0][3]` and `dp[3][5]`.
- The recursion bottoms out at adjacent borders (`right = left + 1`), which enclose no interior balloon and contribute 0.

## When it's the wrong tool

- **Only one sequence, no constraint:** plain 1-D Dynamic Programming suffices. Don't reach for a 2-D table.
- **Need all combinations, not just count/optimum:** use [[0.BacktrackingGuide|Backtracking]] to enumerate explicitly.
- **Graph shortest path with arbitrary edges:** use [[Dijkstra]] or [[BFS]]. DP only works on DAGs or grids with a fixed move set.
- **Constraint is a set, not a number (n <= 20):** consider bitmask DP. State is `(position, bitmask of visited items)`.
- **Greedy choice is locally provable:** see [[0.GreedyGuide|Greedy]]. Don't build a table when a single sweep suffices.
- **Grid traversal with arbitrary moves but no DAG property:** you need to detect cycles. Pure memoization DFS will loop. Add a "visited" set per DFS path or prove the graph is a DAG before memoizing.

## Python Tricks

Idioms specific to 2-D tables, grid DP, and interval DP. General syntax: [[Python Cheatsheet]].

**`[[0] * cols] * rows` is a bug. Every row aliases the same list.**
```python
dp = [[0] * cols for _ in range(rows)]   # correct: fresh row each time
dp = [[0] * cols] * rows                 # BUG: dp[0][j] edits every row
```

**Pad the table with an extra row/col of zeros to kill boundary `if`s.**
```python
dp = [[0] * (n + 1) for _ in range(m + 1)]   # row 0 / col 0 = empty-prefix base case
# loop runs i, j from 1..m, 1..n: no `if i == 0` special-casing needed
```

**Roll a 2-D table down to one row when each row only reads the row above it.**
```python
prev = [0] * (n + 1)
for i in range(1, m + 1):
    cur = [0] * (n + 1)
    for j in range(1, n + 1):
        cur[j] = prev[j-1] + 1 if text1[i-1] == text2[j-1] else max(prev[j], cur[j-1])
    prev = cur
```

**`enumerate(text, 1)` gives you the 1-indexed row/col AND the character in one step. Skip the `s[i-1]` lookups.**
```python
for i, c1 in enumerate(text1, 1):
    for j, c2 in enumerate(text2, 1):
        if c1 == c2:
            dp[i][j] = dp[i-1][j-1] + 1
```

**A state machine's transitions update in one tuple-assignment line. Every read happens before any write, so order can't corrupt the roll-forward.**
```python
hold, free, cool = max(hold, free - p), max(free, cool), hold + p
```

**Sentinel-pad the input array itself, not just the DP table, to remove edge-index checks.**
```python
nums = [1] + nums + [1]   # BurstBalloons: fake border balloons act as neutral multipliers
```

**`min()`/`max()` over the transition's competing sources reads like the recurrence itself.**
```python
dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])   # delete, insert, replace
```
