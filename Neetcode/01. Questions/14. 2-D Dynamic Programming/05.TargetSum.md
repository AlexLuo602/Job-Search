# 494. Target Sum

You are given an integer array nums and an integer target. Build an expression by adding '+' or '-' before each integer in nums and concatenating them. Return the number of different expressions that evaluate to target.
**Example 1:**

```
Input: nums = [1,1,1,1,1], target = 3
Output: 5
```
**Example 2:**

```
Input: nums = [1], target = 1
Output: 1
```

Constraints:
- 1 <= nums.length <= 20
- 0 <= nums[i] <= 1000
- 0 <= sum(nums[i]) <= 1000
- -1000 <= target <= 1000

---

## Solution

### Intuition

`dp(i, total)` represents the number of ways to assign signs to `nums[i:]` such that the running sum reaches `target`. At each index we branch: add `nums[i]` or subtract it. The state space is `O(n * S)` where `S = sum(nums)`, and overlapping subproblems appear whenever the same `(index, running_sum)` pair is reached by different sign assignments.

**Recurrence:**
- `dp(i, total) = dp(i+1, total + nums[i]) + dp(i+1, total - nums[i])`
- Base case: `dp(n, total) = 1 if total == target else 0`

### Approach 1: Top-down memoization

Define `dp(i, total)` as the number of sign assignments for `nums[i:]` that make the running sum equal `target`. Cache each `(i, total)` pair.

```python
class Solution:
    def findTargetSumWays(self, nums: list[int], target: int) -> int:
        n = len(nums)
        memo = {}

        def dp(i: int, total: int) -> int:
            if i == n:
                return 1 if total == target else 0
            if (i, total) in memo:
                return memo[(i, total)]
            memo[(i, total)] = dp(i + 1, total + nums[i]) + dp(i + 1, total - nums[i])
            return memo[(i, total)]

        return dp(0, 0)
```

### Approach 2: Bottom-up tabulation

Use a dictionary keyed on running sum. Each number branches every existing sum into two new sums. A dictionary avoids managing offset indices for negative sums.

```python
class Solution:
    def findTargetSumWays(self, nums: list[int], target: int) -> int:
        dp: dict[int, int] = {0: 1}
        for num in nums:
            next_dp: dict[int, int] = {}
            for total, count in dp.items():
                next_dp[total + num] = next_dp.get(total + num, 0) + count
                next_dp[total - num] = next_dp.get(total - num, 0) + count
            dp = next_dp
        return dp.get(target, 0)
```

> The running sum can range from `-sum(nums)` to `+sum(nums)`. A dictionary handles sparse sums efficiently and avoids manual offset arithmetic.

The dictionary grows as each number doubles the possible sums. Overlapping sums merge their counts instead of duplicating work.

### Complexity

- **Time:** O(n * S) where S = sum(nums). The memoization table has at most n * (2S + 1) entries.
- **Space:** O(n * S) for the cache. O(S) for the bottom-up dictionary at any given step.

### Key concepts to review

- [[Memoization]] - an explicit dictionary on `(index, running_sum)` captures the 2-D state.
- [[Dynamic Programming]] - 0/1 knapsack counting variant. Each element used exactly once.
- [[Recursion]] - the branching recursion tree makes overlapping subproblems visible.
- [[04.CoinChange2]] - sibling counting DP but with unbounded item use and no sign choice.

### Common pitfalls

- Forgetting the base case returns 1 (not 0) when the sum equals target exactly after all elements.
- Skipping memoization entirely, leading to exponential runtime on the branching recursion.
- Using a list/array for the dp state without accounting for negative sums (need an offset).
- Mistaking this for an unbounded knapsack: each `nums[i]` is used exactly once.
