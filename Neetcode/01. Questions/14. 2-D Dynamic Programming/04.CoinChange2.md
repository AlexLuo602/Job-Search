# [518. Coin Change 2](https://leetcode.com/problems/coin-change-2/)


You are given an integer array coins representing coins of different denominations and an integer amount representing a total amount of money.

Return the number of combinations that make up that amount. If that amount of money cannot be made up by any combination of the coins, return 0.

You may assume that you have an infinite number of each kind of coin.

The answer is guaranteed to fit into a signed 32-bit integer.
**Example 1:**

```
Input: amount = 5, coins = [1,2,5]
Output: 4
Explanation: there are four ways to make up the amount:
5=5
5=2+2+1
5=2+1+1+1
5=1+1+1+1+1
```
**Example 2:**

```
Input: amount = 3, coins = [2]
Output: 0
Explanation: the amount of 3 cannot be made up just with coins of 2.
```
**Example 3:**

```
Input: amount = 10, coins = [10]
Output: 1
```

Constraints:

- 1 <= coins.length <= 300
- 1 <= coins[i] <= 5000
- All the values of coins are unique.
- 0 <= amount <= 5000

---

## Solution

### Intuition

`dp(i, j)` represents the number of combinations to make amount `j` using only coins from index `i` onward. For each coin, we can either skip it (move to the next coin) or use it and stay at the same index (unbounded knapsack): `dp(i, j) = dp(i+1, j) + dp(i, j - coins[i])`. Staying at the same index after using a coin allows unlimited reuse. Processing coins in order prevents counting the same combination twice with a different ordering.

**Recurrence:**
- `dp(i, j) = dp(i+1, j) + dp(i, j - coins[i])` when `j >= coins[i]`
- `dp(i, j) = dp(i+1, j)` when `j < coins[i]`
- Base case: `dp(*, 0) = 1` (one way to make amount 0: use nothing), `dp(n, j>0) = 0`

### Approach 1: Top-down memoization

Define `dp(i, remaining)` as the number of combinations using coins from index `i` onward to make `remaining`. Skip the current coin or use it (staying at the same index for unbounded reuse). Cache every `(i, remaining)` pair.

```python
class Solution:
    def change(self, amount: int, coins: list[int]) -> int:
        n = len(coins)
        memo = {}

        def dp(i: int, remaining: int) -> int:
            if remaining == 0:
                return 1
            if i == n:
                return 0
            if (i, remaining) in memo:
                return memo[(i, remaining)]
            skip = dp(i + 1, remaining)
            use = dp(i, remaining - coins[i]) if remaining >= coins[i] else 0
            memo[(i, remaining)] = skip + use
            return memo[(i, remaining)]

        return dp(0, amount)
```

The key mechanism: `dp(i, remaining - coins[i])` stays at the same coin index, which allows unbounded reuse. `dp(i+1, remaining)` skips to the next coin, which prevents counting duplicate orderings.

### Approach 2: Bottom-up tabulation

Iterate coins in the outer loop and amounts in the inner loop (left to right). This order guarantees that each coin denomination is counted at most once per combination, producing combinations rather than permutations.

```python
class Solution:
    def change(self, amount: int, coins: list[int]) -> int:
        dp = [0] * (amount + 1)
        dp[0] = 1

        for coin in coins:
            for j in range(coin, amount + 1):
                dp[j] += dp[j - coin]

        return dp[amount]
```

> Swapping the loop order (amounts outer, coins inner) would count each ordering separately and give the wrong answer. The coin-outer loop means we decide for each denomination how many times to use it before moving on.

The left-to-right scan within each coin pass shows how `dp[j - coin]` reuses the same coin (unbounded knapsack). The outer coin loop prevents duplicate orderings.

### Complexity

- **Time:** O(n * amount). Each (coin, amount) pair is processed once.
- **Space:** O(n * amount) for the 2-D memoization. O(amount) for the 1-D tabulation.

### Key concepts to review

- [[Dynamic Programming]] - unbounded knapsack variant where each item can be used unlimited times.
- [[Memoization]] - top-down with an explicit dictionary on `(coin_index, remaining)`.
- [[Space-Time Tradeoff]] - the 1-D reduction works because each row depends only on the same row (left side) and the row above.
- [[05.TargetSum]] - similar counting DP but with 0/1 choices per element.
- [[01.UniquePaths]] - also a counting DP reducible from 2-D to 1-D.

### Common pitfalls

- Using `dp(i-1, j - coin)` (0/1 knapsack) instead of `dp(i, j - coin)` (unbounded), which prevents reusing the same coin.
- Forgetting `dp(*, 0) = 1`: there is exactly one way to make amount 0 (select nothing).
- In the 1-D version, iterating amounts right-to-left (correct for 0/1 knapsack but wrong for unbounded).
- Confusing combinations (order does not matter) with permutations (order matters). The coin-outer/amount-inner loop order enforces combinations.
