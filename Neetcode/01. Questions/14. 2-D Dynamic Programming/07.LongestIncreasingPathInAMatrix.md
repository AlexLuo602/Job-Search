# [329. Longest Increasing Path in a Matrix](https://leetcode.com/problems/longest-increasing-path-in-a-matrix/)


Given an m x n integers matrix, return the length of the longest increasing path in matrix.

From each cell, you can either move in four directions: left, right, up, or down. You may not move diagonally or move outside the boundary (i.e., wrap-around is not allowed).
**Example 1:**

![[longest-increasing-path-example.svg]]

```
Input: matrix = [[9,9,4],[6,6,8],[2,1,1]]
Output: 4
Explanation: The longest increasing path is [1, 2, 6, 9].
```
**Example 2:**

```
Input: matrix = [[3,4,5],[3,2,6],[2,2,1]]
Output: 4
Explanation: The longest increasing path is [3, 4, 5, 6]. Moving diagonally is not allowed.
```
**Example 3:**

```
Input: matrix = [[1]]
Output: 1
```

Constraints:

- m == matrix.length
- n == matrix\[i\].length
- 1 <= m, n <= 200
- 0 <= matrix\[i\]\[j\] <= 2<sup>31</sup> - 1

---

## Solution

### Intuition

`dp[r][c]` represents the length of the longest increasing path starting at cell `(r, c)`. We use [[DFS|Depth-First Search]] from each cell, moving to neighbors with strictly larger values. The strictly-increasing constraint guarantees no cycles, so the graph of valid moves is a DAG. [[Memoization]] ensures each cell is computed exactly once.

**Recurrence:**
- `dp[r][c] = 1 + max(dp[nr][nc] for each valid neighbor (nr, nc))`
- Base case: a cell with no valid neighbor returns 1 (just itself)

Because the graph is a DAG, the DFS naturally visits cells in topological order. Tabulation is possible via explicit topological sort (by cell value), but it obscures the core DFS insight without improving complexity.

### Approach: DFS with memoization

Launch a memoized DFS from every cell. Each call explores four directions, only moving to strictly larger neighbors. The cache stores the longest path starting at each cell, so no cell is expanded more than once.

```python
class Solution:
    def longestIncreasingPath(self, matrix: list[list[int]]) -> int:
        m, n = len(matrix), len(matrix[0])
        DIRS = [(0, 1), (0, -1), (1, 0), (-1, 0)]
        memo = {}

        def dfs(r: int, c: int) -> int:
            # Returns the longest increasing path starting at (r, c)
            if (r, c) in memo:
                return memo[(r, c)]
            best = 1  # the cell itself counts as a path of length 1
            for dr, dc in DIRS:
                nr, nc = r + dr, c + dc
                # Move only to strictly larger neighbors within bounds
                if 0 <= nr < m and 0 <= nc < n and matrix[nr][nc] > matrix[r][c]:
                    best = max(best, 1 + dfs(nr, nc))
            memo[(r, c)] = best
            return best

        # Launch DFS from every cell; cache prevents redundant work
        return max(dfs(r, c) for r in range(m) for c in range(n))
```

> Because we only move to strictly larger values, the DFS call graph is a DAG (directed acyclic graph). There can never be a cycle, so [[Memoization]] is safe. A cell's result is fully determined before it can be needed by a cell that called it. This is why no `visited` set is needed.

### Complexity

- **Time:** O(m * n). Each cell's DFS result is computed once and cached.
- **Space:** O(m * n) for the memoization cache and recursion stack depth.

### Key concepts to review

- [[Memoization]] - an explicit dictionary on `(r, c)` converts exponential DFS to O(m*n).
- [[DFS|Depth-First Search]] - DFS explores paths. The strictly-increasing constraint makes the graph a DAG.
- [[Dynamic Programming]] - the cache table is effectively a 2-D DP table filled in topological order.
- [[Topological Sort]] - alternative approach: compute in-degrees and process cells in order of value to avoid recursion.
- [[Matrix Traversal]] - four-directional neighbor expansion pattern.

### Common pitfalls

- Adding a `visited` set (unnecessary and harmful because it would break re-entry from different starting cells).
- Moving to neighbors with values greater than or equal to (not strictly greater than), which introduces cycles.
- Forgetting to launch DFS from every cell. The longest path may not start at any corner or edge.
- Assuming the recursion depth is bounded by m or n. It can be up to m*n in a sorted matrix.
