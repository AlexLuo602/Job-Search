# [309. Best Time to Buy and Sell Stock with Cooldown](https://leetcode.com/problems/best-time-to-buy-and-sell-stock-with-cooldown/)


You are given an array prices where prices[i] is the price of a given stock on the ith day.

Find the maximum profit you can achieve. You may complete as many transactions as you like (i.e., buy one and sell one share of the stock multiple times) with the following restrictions:

After you sell your stock, you cannot buy stock on the next day (i.e., cooldown one day).
Note: You may not engage in multiple transactions simultaneously (i.e., you must sell the stock before you buy again).
**Example 1:**

![[stock-cooldown-example.svg]]

```
Input: prices = [1,2,3,0,2]
Output: 3
Explanation: transactions = [buy, sell, cooldown, buy, sell]
```
**Example 2:**

```
Input: prices = [1]
Output: 0
```

Constraints:

- 1 <= prices.length <= 5000
- 0 <= prices[i] <= 1000

---

## Solution

### Intuition

The state at each day is fully described by `(day_index, can_buy)`. When buying, we can either buy (spending `prices[i]` and switching to selling state) or skip the day. When selling, we can either sell (gaining `prices[i]` and jumping to `i+2` for the mandatory cooldown) or skip. The "2-D" aspect comes from these two state dimensions.

**Recurrence:**
- `dp(i, buying=True) = max(dp(i+1, True), dp(i+1, False) - prices[i])`
- `dp(i, buying=False) = max(dp(i+1, False), dp(i+2, True) + prices[i])`
- Base case: `dp(i >= n, *) = 0`

### Approach 1: Top-down memoization

Define `dp(i, buying)` as the maximum profit from day `i` onward given the current state. Cache each `(i, buying)` pair. The recursion naturally handles the cooldown jump.

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        n = len(prices)
        memo = {}

        def dp(i: int, buying: bool) -> int:
            if i >= n:
                return 0
            if (i, buying) in memo:
                return memo[(i, buying)]
            cooldown = dp(i + 1, buying)
            if buying:
                buy = dp(i + 1, False) - prices[i]
                memo[(i, buying)] = max(cooldown, buy)
            else:
                sell = dp(i + 2, True) + prices[i]
                memo[(i, buying)] = max(cooldown, sell)
            return memo[(i, buying)]

        return dp(0, True)
```

### Approach 2: Bottom-up tabulation

Scan days from the end backward. Track three state arrays: `free` (can buy), `held` (holding stock), and `cool` (just sold, must wait).

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        n = len(prices)
        held = [0] * (n + 2)
        free = [0] * (n + 2)
        cool = [0] * (n + 2)

        for i in range(n - 1, -1, -1):
            held[i] = max(cool[i + 1] + prices[i], held[i + 1])
            free[i] = max(held[i + 1] - prices[i], free[i + 1])
            cool[i] = free[i + 1]

        return free[0]
```

> The three-state formulation (free, held, cool) makes the cooldown transition explicit. Selling transitions from `held` to `cool`, and `cool` always transitions to `free` the next day. This avoids the `i+2` index jump from the top-down version.

### Complexity

- **Time:** O(n). There are 2n unique states (n days x 2 buying states), each computed once.
- **Space:** O(n) for the memoization cache or the state arrays. Reducible to O(1) by keeping only the last two index values.

### Key concepts to review

- [[Dynamic Programming]] - state-machine DP with buying/selling/cooldown states.
- [[Memoization]] - an explicit dictionary on `(i, buying)` converts the recursive formulation directly to O(n) time.
- [[0.GreedyGuide|Greedy]] - pure greedy (always buy low, sell high) breaks with the cooldown constraint.
- [[04.CoinChange2]] - another state-space DP where iteration order matters.

### Common pitfalls

- Forgetting to jump to `i + 2` (not `i + 1`) after a sell, missing the mandatory cooldown day.
- Accessing `prices[i + 1]` or `prices[i + 2]` without bounds checking (the base case `i >= n` handles this).
- Mixing up the buying and selling states when converting top-down to bottom-up.
- Not returning 0 when profit would be negative (the cooldown option naturally handles this by doing nothing).
