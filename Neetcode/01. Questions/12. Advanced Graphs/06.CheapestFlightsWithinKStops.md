# [787. Cheapest Flights Within K Stops](https://leetcode.com/problems/cheapest-flights-within-k-stops/)

There are `n` cities connected by directed flights. Each entry `flights[i] = [from_i, to_i, price_i]` describes a flight from `from_i` to `to_i` with the given price.

Given `src`, `dst`, and `k`, return the cheapest price from `src` to `dst` using at most `k` stops. Return `-1` when no valid route exists.

**Example 1:**

![[cheapest-flights-example.svg]]

```text
Input: n = 4, flights = [[0,1,100],[1,2,100],[2,0,100],[1,3,600],[2,3,200]], src = 0, dst = 3, k = 1
Output: 700
Explanation:
The cheapest valid route is 0 -> 1 -> 3, which costs 100 + 600 = 700.
The cheaper route 0 -> 1 -> 2 -> 3 is invalid because it uses 2 stops.
```

**Example 2:**

![[cheapest-flights-example-2.svg]]

```text
Input: n = 3, flights = [[0,1,100],[1,2,100],[0,2,500]], src = 0, dst = 2, k = 1
Output: 200
Explanation:
The route 0 -> 1 -> 2 costs 200 and uses 1 stop.
```

**Example 3:**

![[cheapest-flights-example-3.svg]]

```text
Input: n = 3, flights = [[0,1,100],[1,2,100],[0,2,500]], src = 0, dst = 2, k = 0
Output: 500
Explanation:
With no stops, only the direct flight from city 0 to city 2 is valid.
```

Constraints:

- `1 <= n <= 100`
- `0 <= flights.length <= n * (n - 1) / 2`
- `flights[i].length == 3`
- `0 <= from_i, to_i < n`
- `from_i != to_i`
- `1 <= price_i <= 10^4`
- There are no duplicate flights between the same two cities.
- `0 <= src, dst, k < n`
- `src != dst`
---

## Solution

### Intuition

A route with `k` stops can use at most `k + 1` flights. We need the cheapest price to each city after every allowed number of flights.

A single cheapest-cost value per city is not enough for ordinary [[Dijkstra]]. Reaching a city cheaply after using many flights may leave no legal way to continue. Dijkstra can still work if its state also tracks the number of flights used, but bounded [[Bellman-Ford]] models the limit directly. Each pass allows routes to use at most one additional flight.

### Stops and flights

A stop is a city between the source and destination. The number of flights is therefore one more than the number of stops.

### Approach: bounded Bellman-Ford

Let `prices[v]` be the cheapest known price to city `v` using at most the number of flights covered by the completed passes.

For each of the `k + 1` allowed flights:

1. Copy `prices` into `next_prices`.
2. Check every flight `from -> to`.
3. Read the cost to `from` from the previous pass.
4. Write any cheaper cost to `next_prices[to]`.
5. Replace `prices` only after the full pass finishes.

Checking whether an edge produces a cheaper destination cost is called **relaxing** that edge.

```python
class Solution:
    def findCheapestPrice(self, n: int, flights: list[list[int]],
                          src: int, dst: int, k: int) -> int:
        INF = float("inf")
        # prices[i] is the cheapest cost within the completed flight budget.
        prices = [INF] * n
        prices[src] = 0

        for _ in range(k + 1):  # k stops allow at most k + 1 flights
            # Read the previous pass and write this pass into a separate copy.
            next_prices = prices.copy()
            for frm, to, price in flights:
                if prices[frm] != INF and prices[frm] + price < next_prices[to]:
                    next_prices[to] = prices[frm] + price
            prices = next_prices

        return prices[dst] if prices[dst] != INF else -1
```

### Why the snapshot matters

Without a copy, one pass can reuse values that it just wrote. In Example 1, the first pass could incorrectly chain all of these flights:

- `0 -> 1` saves `100`.
- `1 -> 2` immediately reads that new value and saves `200`.
- `2 -> 3` immediately reads `200` and saves `400`.

That route uses 2 stops, so it is illegal when `k = 1`. Reading from `prices` and writing to `next_prices` prevents the chain. Each pass can add at most one flight.

### Why it works

- Before any pass, only `src` has a known cost. This covers routes using 0 flights.
- Suppose `prices[v]` is correct for every route using at most `r` flights.
- The next pass reads those values and tries every possible final flight `u -> v`.
- Writing into a separate snapshot creates the cheapest routes using at most `r + 1` flights without creating longer routes in the same pass.
- After `k + 1` passes, every route allowed by the stop limit has been considered.
- Routes using more than `k + 1` flights never enter the result.

The cheapest route within one stop is `0 -> 1 -> 3`, with a total price of `700`.

### Complexity

- **Time:** `O((k + 1) * E)`. Each of the `k + 1` passes checks all `E` flights.
- **Space:** `O(n)`. `prices` and `next_prices` each store one cost per city.

### Key concepts to review

- [[Bellman-Ford]]: limit the number of passes to enforce the flight budget
- [[Dynamic Programming]]: each completed pass stores answers for one larger edge budget
- [[Graph]]: represent each flight as a directed weighted edge
- [[Dijkstra]]: an alternative when the state includes both city and flights used
- [[03.NetworkDelayTime]]: standard Dijkstra without a stop limit

### Common pitfalls

- **Updating `prices` in place:** One pass may chain multiple flights and exceed the stop limit.
- **Running only `k` passes:** `k` stops allow `k + 1` flights.
- **Writing `next_prices = prices`:** This creates an alias. Use a real copy such as `prices.copy()`.
- **Reading from `next_prices`:** Every relaxation must read its starting cost from the previous pass in `prices`.
- **Ignoring unreachable cities:** Check that `prices[frm]` is finite before adding the flight price.
