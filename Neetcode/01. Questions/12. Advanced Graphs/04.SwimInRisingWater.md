# 778. Swim in Rising Water

You are given an n x n integer matrix grid where each value grid[i][j] represents the elevation at point (i, j). At time t, the depth of the water everywhere is t. You can swim from a square to an adjacent 4-directional square if both elevations are at most t. Return the least time until you can reach (n-1, n-1) from (0, 0).

**Example 1:**

![[swim-in-rising-water-example.svg]]

```text
Input: grid = [[0,2],[1,3]]
Output: 3
```

**Example 2:**

```text
Input: grid = [[0,1,2,3,4],[24,23,22,21,5],[12,13,14,15,16],[11,17,18,19,20],[10,9,8,7,6]]
Output: 16
```

Constraints:
- n == grid.length == grid[i].length
- 1 <= n <= 50
- 0 <= grid[i][j] < n^2
- Each value grid[i][j] is unique

---

## Solution

### Intuition
We want the path from (0,0) to (n-1, n-1) that minimizes the maximum elevation encountered, because we must wait until t equals that maximum elevation. This is a minimax path problem, solvable with a modified [[Dijkstra|Dijkstra's Algorithm]] where the "distance" to a cell is the maximum elevation seen on the path to it rather than the sum of weights.

### Approach: Modified Dijkstra's (Minimax Path)
Use a min-heap of `(max_elevation_so_far, row, col)`. At each step, pop the cell with the lowest maximum-elevation cost, expand to unvisited neighbors, and push `(max(current_cost, neighbor_elevation), nr, nc)`. The first time we reach (n-1, n-1), the popped cost is the answer.

```python
import heapq

class Solution:
    def swimInWater(self, grid: list[list[int]]) -> int:
        n = len(grid)
        visited: set[tuple[int, int]] = set()
        # WHY: heap stores (max_elevation_on_path, row, col)
        heap: list[tuple[int, int, int]] = [(grid[0][0], 0, 0)]
        directions = [(0, 1), (0, -1), (1, 0), (-1, 0)]

        while heap:
            t, r, c = heapq.heappop(heap)
            if (r, c) in visited:
                continue
            visited.add((r, c))
            if r == n - 1 and c == n - 1:
                return t  # WHY: first arrival is optimal (Dijkstra's guarantee)
            for dr, dc in directions:
                nr, nc = r + dr, c + dc
                if 0 <= nr < n and 0 <= nc < n and (nr, nc) not in visited:
                    # WHY: max because we wait until water rises to neighbor's elevation
                    heapq.heappush(heap, (max(t, grid[nr][nc]), nr, nc))

        return -1  # unreachable (won't happen per constraints)
```

> The key insight is replacing edge-weight summation with a max operation. Moving to a neighbor costs `max(current_t, grid[nr][nc])` because we must wait for water to reach the higher of the two elevations.

Reached (1,1) with t=3. Output: `3`

### Complexity
- **Time:** O(n^2 log n). Each of the n^2 cells is processed once; each heap operation is O(log(n^2)) = O(log n).
- **Space:** O(n^2). Heap and visited set store up to n^2 entries.

### Key concepts to review
- [[Dijkstra|Dijkstra's Algorithm]] - minimax variant: replace sum with max for path cost
- [[Heap]] - min-heap ensures we always explore the lowest-bottleneck path first
- [[Graph]] - implicit grid graph with 4-directional adjacency
- [[0.BinarySearchGuide|Binary Search]] - alternative approach: binary search on answer t, check reachability with BFS
- [[03.NetworkDelayTime]] - standard Dijkstra's for comparison

### Common pitfalls
- Using sum of elevations instead of max - this gives the wrong cost metric entirely.
- Forgetting the visited check after popping - stale heap entries with higher costs would overwrite optimal results.
- Checking bounds after pushing to heap instead of before - causes index-out-of-range errors.
- Confusing "time t" with "elevation" - they are the same value; t is the water level, and grid values are elevations.
