# 15. 3Sum

Given an integer array nums, return all the triplets [nums[i], nums[j], nums[k]] such that i != j, i != k, and j != k, and nums[i] + nums[j] + nums[k] == 0.

Notice that the solution set must not contain duplicate triplets.

 

**Example 1:**
```
Input: nums = [-1,0,1,2,-1,-4]
Output: [[-1,-1,2],[-1,0,1]]
```
**Example 2:**
```
Input: nums = []
Output: []
```
**Example 3:**
```
Input: nums = [0]
Output: []
```

Constraints:

- 0 <= nums.length <= 3000
- -10<sup>5</sup> <= nums[i] <= 10<sup>5</sup>

---

## Solution

### Intuition
Fix one number, then the problem reduces to finding two others that sum to its negation, which is exactly [[02.TwoSumII]] on a sorted array. [[Sorting]] first does double duty: it enables the converging [[0.TwoPointerGuide|Two Pointer]] scan and makes duplicate triplets easy to skip because equal values sit adjacent.

### Approach 1: Brute force (for contrast)
```python
# Check every triple
for i in range(n):
    for j in range(i + 1, n):
        for k in range(j + 1, n):
            if nums[i] + nums[j] + nums[k] == 0:
                ...  # plus dedup work
```
This is O(n^3) and still needs extra effort to remove duplicates, too slow for n up to 3000.

### Approach 2: Sort plus two pointers
Sort the array. Iterate `i` as the fixed first element, skipping repeats. For each `i`, run two pointers `left`/`right` over the remainder seeking `nums[left] + nums[right] == -nums[i]`. After recording a hit, advance both pointers past any duplicates.

```python
from typing import List

class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        result: List[List[int]] = []
        for i in range(len(nums) - 2):
            if nums[i] > 0:
                break                      # smallest is positive -> no zero sum possible
            if i > 0 and nums[i] == nums[i - 1]:
                continue                   # skip duplicate anchors
            left, right = i + 1, len(nums) - 1
            while left < right:
                total = nums[i] + nums[left] + nums[right]
                if total == 0:
                    result.append([nums[i], nums[left], nums[right]])
                    left += 1
                    right -= 1
                    # jump over duplicate seconds/thirds to keep triplets unique
                    while left < right and nums[left] == nums[left - 1]:
                        left += 1
                    while left < right and nums[right] == nums[right + 1]:
                        right -= 1
                elif total < 0:
                    left += 1
                else:
                    right -= 1
        return result
```

> Deduplication must happen at both the anchor level (`i`) and after each match (the inner while loops). Skip only one and you will emit repeated triplets such as two copies of `[-1,-1,2]`.

### Walkthrough
Tracing sorted `nums = [-4,-1,-1,0,1,2]`, anchor `i = 1` (value -1, target for pair = 1):

| left | right | nums[left]+nums[right] | total w/ anchor | action |
|------|-------|------------------------|-----------------|--------|
| 2 | 5 | -1+2=1 | 0 | record [-1,-1,2]; move both, skip dup |
| 3 | 4 | 0+1=1 | 0 | record [-1,0,1]; move both |
| 4 | 3 | - | - | left >= right, stop |

Final output for the full run: **`[[-1,-1,2], [-1,0,1]]`**.

### Complexity
- **Time:** O(n^2). Sorting is O(n log n), then each of n anchors runs an O(n) two-pointer scan.
- **Space:** O(1) extra (or O(n) depending on the sort), ignoring the output list.

### Key concepts to review
- [[0.TwoPointerGuide|Two Pointer]] - the inner scan converges on the pair summing to the anchor's negation.
- [[Sorting]] - prerequisite that enables both the scan and adjacent-duplicate skipping.
- [[02.TwoSumII]] - the exact subproblem each anchor reduces to.

### Common pitfalls
- Forgetting to skip duplicate anchors or duplicate pair members, producing repeated triplets.
- Using a set of tuples to dedup instead of pointer skips (works but wastes memory and time).
- Not advancing both pointers after a match, causing an infinite loop or missed solutions.
