# 621. Task Scheduler


Given a characters array tasks, representing the tasks a CPU needs to do, where each letter represents a different task. Tasks could be done in any order. Each task is done in one unit of time. For each unit of time, the CPU could complete either one task or just be idle.

However, there is a non-negative integer n that represents the cooldown period between two same tasks (the same letter in the array), that is that there must be at least n units of time between any two same tasks.

Return the least number of units of times that the CPU will take to finish all the given tasks.

 

**Example 1:**

![[task-scheduler-example.svg]]

```text
Input: tasks = ["A","A","A","B","B","B"], n = 2
Output: 8
Explanation: 
A -> B -> idle -> A -> B -> idle -> A -> B
There is at least 2 units of time between any two same tasks.
```

**Example 2:**

```text
Input: tasks = ["A","A","A","B","B","B"], n = 0
Output: 6
Explanation: On this case any permutation of size 6 would work since n = 0.
["A","A","A","B","B","B"]
["A","B","A","B","A","B"]
["B","B","B","A","A","A"]
...
And so on.
```

**Example 3:**

```text
Input: tasks = ["A","A","A","A","A","A","B","C","D","E","F","G"], n = 2
Output: 16
Explanation: 
One possible solution is
A -> B -> C -> A -> D -> E -> A -> F -> G -> A -> idle -> idle -> A -> idle -> idle -> A
```

Constraints:

- 1 <= task.length <= 104
- tasks[i] is upper-case English letter.
- The integer n is in the range [0, 100].

## Solution

### Intuition
The most frequent task is the bottleneck. Arrange it into slots of size `n+1` (the task itself plus n cooldown slots). Each "frame" between two occurrences of the most frequent task has `n` slots filled by other tasks or idle time. The key insight: if there are enough other tasks to fill all the slots, no idle time is needed and the answer is simply `len(tasks)`.

### Approach
Count task frequencies. Let `max_freq` be the highest frequency and `max_count` the number of tasks sharing that frequency. The minimum time is the larger of `len(tasks)` (enough tasks to fill all frames) and the formula `(max_freq - 1) * (n + 1) + max_count` (the frame-based schedule with idle slots).

```python
from collections import Counter


class Solution:
    def leastInterval(self, tasks: list[str], n: int) -> int:
        freq = Counter(tasks)
        max_freq = max(freq.values())
        # count how many tasks share the maximum frequency
        max_count = sum(1 for f in freq.values() if f == max_freq)

        # frame-based formula: (max_freq-1) full frames + last partial frame
        frame_schedule = (max_freq - 1) * (n + 1) + max_count

        # if tasks are dense enough, no idle time is needed
        return max(len(tasks), frame_schedule)
```

> The formula `(max_freq - 1) * (n + 1) + max_count` imagines arranging the most frequent task in rows of `n+1` slots. Other tasks fill in left-to-right. If there are leftover tasks that overflow the grid, `len(tasks)` takes over because those extra tasks just extend the schedule without idle time.

### Walkthrough
tasks = ["A","A","A","B","B","B"], n=2.

- freq: A=3, B=3. max_freq=3, max_count=2.
- frame_schedule = (3-1)*(2+1) + 2 = 2*3 + 2 = 8.
- len(tasks) = 6.
- Result: max(6, 8) = 8. Schedule: A B idle A B idle A B.

Each full frame has `n + 1 = 3` slots. The final frame only needs one slot for each task tied at the maximum frequency:

```text
time:       1  2  3 | 4  5  6 | 7  8
schedule:   A  B  _ | A  B  _ | A  B
frame:      <---1---> <---2--->   final

_ = idle
```

There are two slots between each pair of A tasks and each pair of B tasks. No other task can fill slots 3 and 6, so the two idle units are required.

When enough other tasks exist, they fill or extend the frames and `len(tasks)` becomes the answer. For `tasks = [A,A,A,B,B,B,C,C,D]` and `n = 2`:

```text
time:       1  2  3 | 4  5  6 | 7  8  9
schedule:   A  B  C | A  B  D | A  B  C
```

Here the frame formula gives 8, but all 9 tasks run without idle time, so the answer is `max(9, 8) = 9`.

### Complexity
- **Time:** O(N) where N is the number of tasks. Counting frequencies is O(N), and the formula is O(1).
- **Space:** O(1) since there are at most 26 distinct task types.

### Key concepts to review
- [[0.GreedyGuide|Greedy]] - always schedule the most frequent remaining task first to minimize idle time.
- [[Frequency Counting]] - the frequency of each task drives the entire formula.
- [[Heap]] - an alternative simulation approach: use a max-heap to always pick the most frequent available task each cycle. See siblings [[06.DesignTwitter]] and [[07.FindMedianFromDataStream]].

### Common pitfalls
- Forgetting `max(len(tasks), frame_schedule)`: when tasks are dense, the frame formula underestimates.
- Miscounting `max_count`: it is the number of tasks with frequency equal to `max_freq`, not the frequency itself.
- Confusing the cooldown period n with the frame size (n+1): the frame includes the task execution plus n waiting slots.
- The formula only requires the max frequency and max count, not the full sorted list of frequencies.
