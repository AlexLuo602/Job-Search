# 355. Design Twitter

Design a simplified version of Twitter where users can post tweets, follow/unfollow another user, and see the 10 most recent tweets in their news feed.

Implement the Twitter class:
- Twitter() — initializes the object.
- void postTweet(int userId, int tweetId) — composes a new tweet.
- List\<Integer> getNewsFeed(int userId) — retrieves the 10 most recent tweet IDs in the user's news feed (own + followed users), ordered from most to least recent.
- void follow(int followerId, int followeeId)
- void unfollow(int followerId, int followeeId)

**Example 1:**

```text
Input:
["Twitter","postTweet","getNewsFeed","follow","postTweet","getNewsFeed","unfollow","getNewsFeed"]
[[],[1,5],[1],[1,2],[2,6],[1],[1,2],[1]]
Output: [null,null,[5],null,null,[6,5],null,[5]]
```

Constraints:
- 1 <= userId, followerId, followeeId <= 500
- 0 <= tweetId <= 10^4
- All tweets have unique IDs
- At most 3 * 10^4 calls will be made

---

## Solution

### Intuition
The news feed is a merge of sorted tweet lists from multiple users, which is exactly the k-way merge problem solved by a [[Heap]]. Each user's tweets are stored in reverse-chronological order (newest first). A global timestamp counter gives each tweet a sortable age. The key insight: a max-heap over the head of each relevant user's tweet list gives the top 10 in O((U + 10) log U) time where U is the number of followed users.

### Approach
Store tweets per user as a list of `(timestamp, tweetId)` pairs (append-only, so newest is at the end). Store follow relationships in a set per user. For `getNewsFeed`, push the last (newest) tweet of each relevant user into a max-heap. Each pop yields the next most recent tweet, then push that user's next tweet to continue the merge.

```python
import heapq
from collections import defaultdict


class Twitter:

    def __init__(self) -> None:
        self.time: int = 0
        # userId -> list of (timestamp, tweetId), oldest first
        self.tweets: dict[int, list[tuple[int, int]]] = defaultdict(list)
        # followerId -> set of followeeIds
        self.follows: dict[int, set[int]] = defaultdict(set)

    def postTweet(self, userId: int, tweetId: int) -> None:
        self.tweets[userId].append((self.time, tweetId))
        self.time += 1  # global monotonic timestamp

    def getNewsFeed(self, userId: int) -> list[int]:
        # collect all relevant users (self + followed)
        users = self.follows[userId] | {userId}

        # max-heap: negate timestamp for min-heap simulation
        # entry: (-timestamp, tweetId, userId, tweet_index)
        heap: list[tuple[int, int, int, int]] = []
        for uid in users:
            tweets = self.tweets[uid]
            if tweets:
                idx = len(tweets) - 1  # start from newest
                ts, tid = tweets[idx]
                heapq.heappush(heap, (-ts, tid, uid, idx))

        result: list[int] = []
        while heap and len(result) < 10:
            neg_ts, tid, uid, idx = heapq.heappop(heap)
            result.append(tid)
            if idx > 0:  # push next older tweet from the same user
                next_idx = idx - 1
                ts, next_tid = self.tweets[uid][next_idx]
                heapq.heappush(heap, (-ts, next_tid, uid, next_idx))

        return result

    def follow(self, followerId: int, followeeId: int) -> None:
        self.follows[followerId].add(followeeId)

    def unfollow(self, followerId: int, followeeId: int) -> None:
        self.follows[followerId].discard(followeeId)
```

> Using a monotonic `self.time` counter (not wall-clock time) guarantees unique, sortable timestamps across all users. Negating the timestamp converts Python's min-heap into an effective max-heap for recency ordering.

### Complexity
- **Time:** `postTweet` O(1). `getNewsFeed` O(U log U + 10 log U) where U is the number of followed users. `follow`/`unfollow` O(1).
- **Space:** O(T + F) where T is total tweets and F is total follow relationships.

### Key concepts to review
- [[Heap]] - k-way merge of sorted per-user tweet lists. See sibling [[07.FindMedianFromDataStream]] for another multi-heap pattern.
- [[Hash Map]] - `defaultdict` for tweets and follows storage.
- [[Linked List]] - conceptually each user's tweet list acts as a sorted linked list in the merge.

### Common pitfalls
- Always include the user in their own news feed (union `{userId}` with followed set).
- Use `discard` not `remove` in `unfollow` to avoid KeyError when the user is not currently followed.
- The heap entry needs the user's tweet index to find the next older tweet; without it you cannot continue the merge.
- Forgetting to negate the timestamp means the heap returns oldest tweets first rather than newest.
- **Optional optimization:** if `U` could be unbounded (e.g. a real social graph, not this problem's `U ≤ 500`), cap each user's stored tweets and the scan heap at size 10 to drop the `log U` factor to `O(1)`. See the attempt note [[Design Twitter]] for the two-phase version. Not worth the added invariant here since `log U ≤ 9` at this problem's scale.
