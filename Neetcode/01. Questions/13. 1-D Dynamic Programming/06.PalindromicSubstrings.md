# [647. Palindromic Substrings](https://leetcode.com/problems/palindromic-substrings/)

Given a string s, return the number of palindromic substrings in it.

A string is a palindrome when it reads the same backward as forward.

A substring is a contiguous sequence of characters within the string.

 

**Example 1:**
```
Input: s = "abc"
Output: 3
Explanation: Three palindromic strings: "a", "b", "c".
```
**Example 2:**
```
Input: s = "aaa"
Output: 6
Explanation: Six palindromic strings: "a", "a", "a", "aa", "aa", "aaa".
```

Constraints:

- 1 <= s.length <= 1000
- s consists of lowercase English letters.

---

## Solution

### Intuition
Every palindrome has a center, so we can count palindromic substrings by expanding outward from every possible center and incrementing a counter for each valid expansion. This mirrors the expand-around-center approach in [[05.LongestPalindromicSubstring]], but instead of tracking the longest we accumulate a count. A 2D [[Dynamic Programming]] table is an alternative but costs O(n^2) space without benefit here.

### Approach: Center expansion

For each center, expand and count each valid palindromic substring directly.

```python
class Solution:
    def countSubstrings(self, s: str) -> int:
        count = 0

        def expand(left: int, right: int) -> None:
            nonlocal count
            while left >= 0 and right < len(s) and s[left] == s[right]:
                count += 1   # every valid (left, right) pair is a palindrome
                left -= 1
                right += 1

        for i in range(len(s)):
            expand(i, i)      # odd-length: single character center
            expand(i, i + 1)  # even-length: gap between i and i+1

        return count
```

> Each single character is itself a palindrome, so `expand(i, i)` always increments `count` at least once before any comparison fails. The total starting count is therefore at least `len(s)`.

### Complexity
- **Time:** O(n^2). n centers, each expanding up to O(n) steps.
- **Space:** O(1). Only the counter and two index variables.

### Key concepts to review
- [[0.TwoPointerGuide|Two Pointer]] - the expand-around-center technique uses two outward-moving pointers.
- [[Dynamic Programming]] - 2D dp[i][j] alternative for systematic subproblem caching.
- [[05.LongestPalindromicSubstring]] - same expansion logic, different aggregation.

### Common pitfalls
- Forgetting the even-length center `expand(i, i+1)`, which misses palindromes like "aa" or "abba".
- Initializing count to `len(s)` and only expanding (skipping single-character counts inside the loop) is fragile if the string is empty.
- Counting the center match before the loop guard, which can double-count boundary-edge cases.
- Confusing substring count with subsequence count (subsequences need not be contiguous).
