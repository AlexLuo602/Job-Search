# Dynamic Programming Guide

> **Core idea:** [[Dynamic Programming]] trades space for time by storing answers to subproblems so they're never recomputed. Every DP solution is the same four-step loop: define what `dp[i]` means → write the recurrence → set base cases → fill in the right order.

## ⚡ Cheatsheet

| Pattern                | Reach for it when…                                                                         | Mechanism                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| Min/max path to target | "fewest coins", "minimum cost to reach X"                                                  | `dp[i] = min(dp[i - opt] + 1)` over all options                                      |
| Count distinct ways    | "how many ways", "number of paths"                                                         | `dp[i] += dp[i - opt]` for each option                                               |
| Take or skip           | "non-adjacent", "at most one per row"; boolean 0/1 knapsack for "can you hit a target sum" | `dp[i] = max(take, skip)`; reachable-sums set for the knapsack subpattern            |
| Sequence DP            | "longest subsequence ending here", "can this prefix be built"                              | `dp[i]` from compatible earlier positions `j < i`, or from an earlier valid boundary |
| Palindrome checks      | "longest palindromic substring"                                                            | Center expansion first; interval DP `(l, r)` when substructure demands it            |

## How to think about it

DP buys you polynomial time on problems whose naive recursion is exponential. It works when two conditions hold:

- **Optimal substructure**: The best answer to the whole problem is built from best answers to sub-problems.
- **Overlapping sub-problems**: The same sub-problems recur many times in the recursive tree (so caching pays off).

When you see "minimum / maximum over all ways" or "count distinct paths", that's the signal. The cost is O(states × transitions) time and O(states) space.

The one discipline that prevents most DP bugs:

> **Write `dp[i]` in one English sentence before touching the code.** If you can't state it precisely, you don't have the algorithm yet.

## The universal four-step flow

Every DP problem follows the same loop, regardless of pattern:

1. **Define state.** What does `dp[i]` (or `dp[i][j]`) represent? Write it out: *"the minimum coins needed to make amount `i`"*.
2. **Write the recurrence.** Express `dp[i]` in terms of strictly smaller states. Work a small example by hand first.
3. **Set base cases.** What are the trivially solved sub-problems? Usually `dp[0]` or `dp[i][0]`, `dp[0][j]`.
4. **Choose fill order.** Bottom-up: make sure every state you reference is already filled when you get there.

## [[Memoization]] vs. [[Tabulation]]

Both are DP. They differ in *how* you cache:

**Top-down (memoization):** write the natural recursion, add a cache. Good for getting correctness fast. Mirrors the recurrence directly.

```python
def climb_stairs(n: int) -> int:
    memo = {}

    def dp(i: int) -> int:
        if i in memo:
            return memo[i]
        if i <= 1:
            return 1  # dp(0) = dp(1) = 1: one way to stand still, one way up one step

        memo[i] = dp(i - 1) + dp(i - 2)
        return memo[i]

    return dp(n)
```

**Bottom-up (tabulation):** fill a table iteratively in dependency order. Avoids Python's recursion limit. Easier to space-optimize.

```python
def climb_stairs(n: int) -> int:
    if n <= 1:
        return 1
    dp = [0] * (n + 1)
    dp[0], dp[1] = 1, 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]
```

**Prefer top-down** to verify your recurrence. **Convert to bottom-up** when you need to space-optimize or avoid recursion depth errors.

## Space optimization: rolling variables

### Problem: compute `fib(5)` without storing the full table

Fibonacci uses the recurrence `fib(i) = fib(i - 1) + fib(i - 2)`. A bottom-up table for `fib(5)` would store `[0, 1, 1, 2, 3, 5]`, but each new value only reads the two values immediately before it. We can keep those two live values as `prev2` and `prev1`, compute the next value, then move both variables forward.

```python
def fib(n: int) -> int:
    if n <= 1:
        return n

    prev2, prev1 = 0, 1
    for _ in range(2, n + 1):
        prev2, prev1 = prev1, prev2 + prev1

    return prev1
```

This still takes O(n) time, but the extra space drops from O(n) for the table to O(1) for two variables.

## The core patterns

### Min/max path to target

`dp[i]` = minimum (or maximum) cost to reach value `i`. At each state, try every option and take the best:

```python
# [[08.CoinChange|CoinChange]]: fewest coins to make amount
def coinChange(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1
```

Key signal: [[0.GreedyGuide|greedy]] fails here. `coins = [1, 5, 11]`, `amount = 15`. Greedy picks 11+1+1+1+1 = 5 coins. DP finds 5+5+5 = 3.

### Count distinct ways

`dp[i]` = number of distinct ways to reach value `i`. Same structure, but **sum** instead of **min**:

```python
# [[07.DecodeWays|DecodeWays]]: count decodings of digit string
def numDecodings(s):
    n = len(s)
    dp = [0] * (n + 1)
    dp[0] = 1
    dp[1] = 0 if s[0] == '0' else 1
    for i in range(2, n + 1):
        one = int(s[i-1])
        two = int(s[i-2:i])
        if one != 0:
            dp[i] += dp[i - 1]
        if 10 <= two <= 26:
            dp[i] += dp[i - 2]
    return dp[n]
```

### Take or skip (decision DP)

At each position, decide: take this item (incurring a constraint) or skip it. `dp[i]` = best result starting from index `i`:

```python
# [[03.HouseRobber|HouseRobber]]: max loot from non-adjacent houses
def rob(nums):
    prev2, prev1 = 0, 0
    for num in nums:
        prev2, prev1 = prev1, max(prev1, prev2 + num)
    return prev1
```

The constraint (can't rob adjacent) is encoded in skipping from `prev2` (two back) vs. `prev1` (one back). [[04.HouseRobberII|HouseRobberII]] wraps this in two passes (exclude first house, exclude last house) to handle the circular constraint.

Take or skip describes the **decision**, not the complete state shape. House Robber only needs a position because adjacency is the constraint. When the decision must also track a numeric target or capacity, the pattern becomes a knapsack subpattern.

#### Subpattern: Boolean 0/1 knapsack

Boolean 0/1 knapsack adds three specific rules to take or skip:

- **Boolean:** each state answers whether a target value is reachable.
- **0/1:** each item can be taken zero or one time.
- **Knapsack:** the state includes a numeric target or remaining capacity.

A full state can be written as `dp[i][total]`: whether `total` is reachable using the first `i` items. The transition still makes the same choice:

```text
dp[i][total] = dp[i - 1][total]                         # skip
               or dp[i - 1][total - nums[i - 1]]       # take once
```

[[12.PartitionEqualSubsetSum|PartitionEqualSubsetSum]] is an example of this subpattern. Its target is half of the array's total sum. The optimized 1-D version below iterates right to left so the current number cannot be reused during the same pass:

```python
# [[12.PartitionEqualSubsetSum|PartitionEqualSubsetSum]]
def canPartition(nums):
    total = sum(nums)
    if total % 2:
        return False
    target = total // 2
    dp = [False] * (target + 1)
    dp[0] = True
    for num in nums:
        for j in range(target, num - 1, -1):   # right-to-left: each item at most once
            dp[j] = dp[j] or dp[j - num]
    return dp[target]
```

**Why reverse?** Going left-to-right would let you "use" the same `num` twice in the same pass (unbounded knapsack). Right-to-left ensures `dp[j - num]` still reflects the state *before* adding `num`.

### Sequence DP

Sequence DP processes an array or string by position. The two subpatterns below are named after how each state connects to an earlier state.

#### Subpattern: Extend from a compatible earlier position

Use this subpattern when the answer is built by extending a valid sequence with the current item. Unlike take or skip, each state asks which earlier compatible state should come immediately before the current index.

- **State:** `dp[i]` = best valid subsequence that ends exactly at index `i`.
- **Transition:** scan every `j < i`. If item `j` can precede item `i`, extend `dp[j]` into `dp[i]`.
- **Final answer:** take `max(dp)`, because the best sequence may end at any index.

The typical recurrence is:

```text
dp[i] = best(dp[j] + contribution(i)) for every compatible j < i
```

This state shape also appears in longest divisible subsets, maximum-sum increasing subsequences, and other longest-chain problems.

##### Example: [[11.LongestIncreasingSubsequence|Longest Increasing Subsequence]]

For LIS, index `j` is compatible with index `i` when `nums[j] < nums[i]`. Each value starts as a length-1 subsequence containing only itself.

###### Top-down [[Memoization|memoization]]

`best_ending_at(i)` returns the LIS length that must end at index `i`. The dictionary saves each completed state:

```python
def lengthOfLIS(nums):
    memo = {}

    def best_ending_at(i):
        if i in memo:
            return memo[i]

        best = 1
        for j in range(i):
            if nums[j] < nums[i]:
                best = max(best, best_ending_at(j) + 1)

        memo[i] = best
        return best

    if not nums:
        return 0
    return max(best_ending_at(i) for i in range(len(nums)))
```

###### Bottom-up [[Tabulation|tabulation]]

`dp[i]` stores the same state after all compatible earlier positions have been processed:

```python
def lengthOfLIS(nums):
    if not nums:
        return 0

    dp = [1] * len(nums)
    for i in range(1, len(nums)):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)

    return max(dp)
```

Both versions take O(n^2) time because every `i` may scan all earlier indices. Both store O(n) states.

##### Faster alternative for LIS: patience sorting

LIS also has an O(n log n) solution that maintains the smallest possible tail for each subsequence length using [[0.BinarySearchGuide|Binary Search]]:

```python
import bisect

def lengthOfLIS_fast(nums):
    tails = []
    for num in nums:
        pos = bisect.bisect_left(tails, num)
        if pos == len(tails):
            tails.append(num)
        else:
            tails[pos] = num
    return len(tails)
```

`tails` is not necessarily an actual subsequence. Only `len(tails)` is guaranteed to equal the LIS length.
#### Subpattern: Build from an earlier valid boundary

Use this subpattern when each state answers whether the prefix ending at position `i` can be reached or completed from an earlier valid boundary.

##### Example: [[10.WordBreak|Word Break]]

For Word Break, `dp[i]` means the first `i` characters can be segmented. For each position, scan backward and check whether a dictionary word starts at an earlier reachable boundary and ends at `i`:

```python
# [[10.WordBreak|WordBreak]]
def wordBreak(s, wordDict):
    words = set(wordDict)
    n = len(s)
    dp = [False] * (n + 1)
    dp[0] = True
    for i in range(1, n + 1):
        for j in range(i):
            if dp[j] and s[j:i] in words:
                dp[i] = True
                break
    return dp[n]
```

### Palindrome checks: center expansion vs. interval DP

Two equivalent approaches for palindromic-substring problems. Expanding from each center needs no DP table, only the answer substring, and is cleaner. A 2-D DP table (`dp[i][j]` = is `s[i..j]` a palindrome) works but costs O(n²) space. [[05.LongestPalindromicSubstring|Longest Palindromic Substring]] is the standard example. For interview, expansion is preferred:

```python
# [[05.LongestPalindromicSubstring|LongestPalindromicSubstring]]: center expansion
def longestPalindrome(s):
    res = ""
    for center in range(len(s)):
        for l, r in [(center, center), (center, center + 1)]:  # odd, even
            while l >= 0 and r < len(s) and s[l] == s[r]:
                if r - l + 1 > len(res):
                    res = s[l:r+1]
                l -= 1; r += 1
    return res
```

[[06.PalindromicSubstrings|PalindromicSubstrings]] (count all palindromic substrings) uses the exact same expansion. Just increment a counter instead of tracking the longest.

## How to approach a new problem

1. **Ask: does the answer for a bigger input depend on answers to smaller inputs?** If yes, DP is likely. If you can make a locally greedy choice and it's always safe, try Greedy first.
2. **Name your state.** Write one sentence: "dp[i] is ___." If you need two dimensions (position + constraint, or two string indices), that's fine. Name both.
3. **Write the recurrence from a concrete example.** Pick a small input (3-4 elements), draw the values by hand, and see the pattern.
4. **Handle base cases explicitly.** What is `dp[0]`? What if the string is empty? Test your base cases before your loop.
5. **Decide fill order.** For 1-D: usually left to right. For knapsack with bounded items: right to left. For 2-D: depends on which cells the recurrence reads. Row by row, or by increasing interval length.
6. **Check if you can space-optimize.** Does `dp[i]` only depend on `dp[i-1]` and `dp[i-2]`? Roll to two variables. Does the 2-D table only read the previous row? Roll to one row.
7. **Test n = 0, n = 1, and the smallest non-trivial case.** Almost every DP bug lives in the base cases or off-by-one on array sizing.

## Worked example: Max Product Subarray

[[09.MaxProductSubArray|MaxProductSubArray]] is an interesting case because multiplying negatives can flip a minimum into a maximum. A standard [[Kadane's Algorithm|Kadane-style]] running-max scan breaks. You need to extend it to track both the running max *and* running min:

```python
def maxProduct(nums):
    res = max(nums)
    cur_min = cur_max = 1
    for n in nums:
        if n == 0:
            cur_min = cur_max = 1
            continue
        candidates = (n, cur_max * n, cur_min * n)
        cur_max = max(candidates)
        cur_min = min(candidates)
        res = max(res, cur_max)
    return res
```

Why track `cur_min`? A large negative minimum times the next negative number becomes a large positive maximum. Without `cur_min`, you'd miss that flip. Reset both to 1 on a zero because any product spanning zero is zero.

## When DP is the wrong tool

- **Greedy works.** If a provably-safe local choice exists at every step, Greedy is simpler and faster. DP builds a full table when one pass suffices.
- **No overlapping sub-problems.** [[Divide and Conquer|Divide-and-conquer]] (merge sort, binary search) splits into non-overlapping halves. Memoization adds overhead for zero gain.
- **No optimal substructure.** Longest *simple* path in a general graph can't be decomposed: the best A→B path might block vertices needed for B→C. This is NP-hard.
- **You need all valid solutions, not just the count.** DP compresses results to a number. Use [[0.BacktrackingGuide|Backtracking]] to enumerate every solution explicitly.
- **Shortest path in a weighted graph.** Use [[Dijkstra]] or [[BFS]]. DP on a DAG is the exception.
- **[[0.SlidingWindowGuide|Sliding window]] is enough.** Contiguous-subarray constraints with a linear scan are O(n) via sliding window. DP would be O(n²) for no reason.

## 🐍 Python Tricks

Idioms that keep 1-D DP code short and bug-free. General syntax: [[Python Cheatsheet]].

**Use an explicit dictionary so the cache key, lookup, and write remain visible.**
```python
memo = {}

def dp(i):
    if i in memo:
        return memo[i]

    memo[i] = solve_smaller_states(i)
    return memo[i]
```

**Bump the recursion limit before deep top-down DP. Python's default (1000) caps you around `n≈1000`.**
```python
import sys
sys.setrecursionlimit(10**6)
```

**Rolling state updates in one tuple-assignment line. No temp variable, and both reads happen before either write.**
```python
prev2, prev1 = prev1, max(prev1, prev2 + num)   # HouseRobber
```

**`float('inf')` as the "unreached" sentinel for min-DP. Cleaner than `-1` or `None`, and comparisons just work.**
```python
dp = [float('inf')] * (amount + 1)
dp[0] = 0
# ...
return dp[amount] if dp[amount] != float('inf') else -1
```

**`max()`/`min()` over a tuple of candidates beats a chain of `if`/`elif`. Build the tuple once, ask for both directions.**
```python
candidates = (n, cur_max * n, cur_min * n)
cur_max, cur_min = max(candidates), min(candidates)
```

**`dp = nums[:]` copy-initializes a 1-D table when `dp[i]` always has "just `nums[i]` alone" as a fallback.**
```python
dp = nums[:]
for i in range(1, len(nums)):
    dp[i] = max(dp[i], dp[i-1] + nums[i])
```

**Iterate the capacity loop backwards (`range(target, num-1, -1)`) to cap each item at one use without a second dimension.**
```python
for num in nums:
    for j in range(target, num - 1, -1):   # right-to-left: dp[j-num] is still last round's value
        dp[j] = dp[j] or dp[j - num]
```
