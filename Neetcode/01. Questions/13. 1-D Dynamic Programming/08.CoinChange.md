# [322. Coin Change](https://leetcode.com/problems/coin-change/)


You are given an integer array coins representing coins of different denominations and an integer amount representing a total amount of money.

Return the fewest number of coins that you need to make up that amount. If that amount of money cannot be made up by any combination of the coins, return -1.

You may assume that you have an infinite number of each kind of coin.

 

**Example 1:**
```
Input: coins = [1,2,5], amount = 11
Output: 3
Explanation: 11 = 5 + 5 + 1
```
**Example 2:**
```
Input: coins = [2], amount = 3
Output: -1
```
**Example 3:**
```
Input: coins = [1], amount = 0
Output: 0
``` 

Constraints:

- 1 <= coins.length <= 12
- 1 <= coins[i] <= 2<sup>31</sup> - 1
- 0 <= amount <= 10<sup>4</sup>

---

## Solution

### Intuition
`dp[a]` = minimum number of coins to make amount `a`. For each amount, try every coin: if `coin <= a`, then `dp[a] = min(dp[a], 1 + dp[a - coin])`. This is an unbounded knapsack pattern because coins can be reused. [[0.GreedyGuide|Greedy]] (always take the largest coin) fails on inputs like `coins=[1,3,4], amount=6` where greedy picks 4+1+1 but the optimum is 3+3.

### State definition and recurrence

**State:** `dp[a]` = minimum coins to make amount `a`.

**Recurrence:** `dp[a] = min(1 + dp[a - coin])` for each coin where `coin <= a`.

**Base case:** `dp[0] = 0` (zero coins needed for amount zero).

### Approach 1: Top-down memoization

Recursion tries each coin from the current remaining amount. The cache prevents revisiting the same amount.

```python
class Solution:
    def coinChange(self, coins: list[int], amount: int) -> int:
        memo = {}

        def dp(remaining: int) -> int:
            if remaining == 0:
                return 0
            if remaining < 0:
                return float('inf')
            if remaining in memo:
                return memo[remaining]

            best = float('inf')
            for coin in coins:
                best = min(best, 1 + dp(remaining - coin))

            memo[remaining] = best
            return best

        result = dp(amount)
        return result if result != float('inf') else -1
```

### Approach 2: Bottom-up tabulation

Build the dp table from amount 0 to `amount`. Each cell reads only smaller amounts, which are already complete.

```python
class Solution:
    def coinChange(self, coins: list[int], amount: int) -> int:
        dp = [amount + 1] * (amount + 1)
        dp[0] = 0

        for i in range(1, amount + 1):
            for coin in coins:
                if coin <= i:
                    dp[i] = min(dp[i], 1 + dp[i - coin])

        return dp[amount] if dp[amount] <= amount else -1
```

> `amount + 1` as the sentinel is safe because you can never need more than `amount` coins (even if every coin is denomination 1). After the loops, any value still equal to `amount + 1` means the target was unreachable.

### Complexity
- **Time:** O(amount * len(coins)). Two nested loops in either approach.
- **Space:** O(amount). The dp array or memo has at most `amount + 1` entries.

### Key concepts to review
- [[Dynamic Programming]] - unbounded knapsack variant where items (coins) can be reused.
- [[0.GreedyGuide|Greedy]] - fails here. Included for contrast since it works for canonical coin sets.
- [[Memoization]] - top-down alternative shown in Approach 1.
- [[12.PartitionEqualSubsetSum]] - related 0/1 knapsack where items cannot be reused.

### Common pitfalls
- Initializing `dp` with `float('inf')` works but then the final check must be `dp[amount] == float('inf')`.
- Forgetting the `coin <= i` guard causes an index error on `dp[i - coin]` when `coin > i`.
- Iterating coins in the outer loop and amounts in the inner loop gives a 0/1 knapsack (each coin used at most once), which is wrong here.
- Returning `dp[amount]` without checking for the sentinel returns garbage when the amount is unreachable.
