# [70. Climbing Stairs](https://leetcode.com/problems/climbing-stairs/)

You are climbing a staircase. It takes n steps to reach the top.

Each time you can either climb 1 or 2 steps. In how many distinct ways can you climb to the top?

 

**Example 1:**
```
Input: n = 2
Output: 2
Explanation: There are two ways to climb to the top.
1. 1 step + 1 step
2. 2 steps
```
**Example 2:**
```
Input: n = 3
Output: 3
Explanation: There are three ways to climb to the top.
1. 1 step + 1 step + 1 step
2. 1 step + 2 steps
3. 2 steps + 1 step
```

Constraints:

- 1 <= n <= 45

---

## Solution

### Intuition
The number of ways to reach step `i` equals the number of ways to reach step `i-1` (take one step) plus the number of ways to reach step `i-2` (take two steps). This is exactly the [[Recursion|Fibonacci]] recurrence. Brute-force recursion recomputes overlapping subproblems exponentially, while [[Dynamic Programming]] resolves each sub-answer once.

**State definition:** `dp[i]` = number of distinct ways to climb `i` stairs.

**Recurrence:** `dp[i] = dp[i-1] + dp[i-2]`

**Base cases:** `dp[0] = 1` (one way to stay at the ground), `dp[1] = 1` (one way to reach step 1).

### Approach 1: Top-down memoization

Cache the recursive Fibonacci calls to avoid re-solving the same subproblems.

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        memo = {}

        def dp(i: int) -> int:
            if i <= 1:
                return 1
            if i in memo:
                return memo[i]
            memo[i] = dp(i - 1) + dp(i - 2)
            return memo[i]

        return dp(n)
```

> Without the cache, `dp(n)` branches into `dp(n-1)` and `dp(n-2)`, each of which branches again, producing O(2^n) total calls. The cache ensures each value of `i` is computed once, collapsing the tree to O(n) calls.

### Approach 2: Bottom-up tabulation

Build the answer iteratively from the base cases. Because `dp[i]` depends only on the two previous values, two rolling variables replace the full array.

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        # one = dp[i+1], two = dp[i+2]
        one, two = 1, 1  # base: dp[0]=1, dp[1]=1

        for _ in range(n - 1):
            one, two = one + two, one  # roll forward

        return one
```

> `one` starts as `dp[1] = 1` and `two` as `dp[0] = 1` (the empty path). After `n-1` iterations, `one` holds `dp[n]`. Python's simultaneous assignment avoids a temporary variable.

### Complexity
- **Time:** O(n) for both approaches. Memoization makes O(n) cached calls. Tabulation runs one pass of `n-1` iterations.
- **Space:** Memoization uses O(n) for the cache and call stack. Tabulation uses O(1) with rolling variables.

### Key concepts to review
- [[Dynamic Programming]] - overlapping subproblems solved bottom-up or top-down.
- [[Memoization]] - top-down cache to avoid redundant recursive work.
- [[Space-Time Tradeoff]] - full dp array vs. two rolling variables.
- [[02.MinCostClimbingStair]] - direct extension: each stair now has a cost.

### Common pitfalls
- Off-by-one: initializing `one = 0` instead of `1` misses the "step directly to top" case.
- Iterating `n` times instead of `n-1` shifts the answer by one Fibonacci number.
- Using a full array when only the last two values are ever read.
- Confusing `n=1` edge case: the loop runs 0 times and `one = 1` is returned correctly.
