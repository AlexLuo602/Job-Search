# [91. Decode Ways](https://leetcode.com/problems/decode-ways/)


A message containing letters from A-Z can be encoded into numbers using the following mapping:

'A' -> "1"

'B' -> "2"

...

'Z' -> "26"

To decode an encoded message, all the digits must be grouped then mapped back into letters using the reverse of the mapping above (there may be multiple ways). For example, "11106" can be mapped into:

`"AAJF" with the grouping (1 1 10 6)`

`"KJF" with the grouping (11 10 6)`

Note that the grouping (1 11 06) is invalid because "06" cannot be mapped into 'F' since "6" is different from "06".

Given a string s containing only digits, return the number of ways to decode it.

The test cases are generated so that the answer fits in a 32-bit integer.

 

**Example 1:**
```
Input: s = "12"
Output: 2
Explanation: "12" could be decoded as "AB" (1 2) or "L" (12).
```
**Example 2:**
```
Input: s = "226"
Output: 3
Explanation: "226" could be decoded as "BZ" (2 26), "VF" (22 6), or "BBF" (2 2 6).
```
**Example 3:**
```
Input: s = "06"
Output: 0
Explanation: "06" cannot be mapped to "F" because of the leading zero ("6" is different from "06").
```

Constraints:

- 1 <= s.length <= 100
- s contains only digits and may contain leading zero(s).

---

## Solution

### Intuition
`dp[i]` = number of ways to decode `s[i:]`. At position `i`, we can take one character (if it is not '0') and add `dp[i+1]`, or take two characters (if they form a number in 10-26) and add `dp[i+2]`. The overlapping subproblems are the shared suffix counts. [[Dynamic Programming]] resolves each suffix once. Brute-force recursion revisits them exponentially. The recurrence follows the same Fibonacci-like two-lookback pattern as [[01.ClimbingStairs]], with validity constraints on zero digits and two-digit ranges.

### State definition and recurrence

**State:** `dp[i]` = number of ways to decode `s[i:]`.

**Recurrence:**
- If `s[i] == '0'`: `dp[i] = 0` (no valid decoding starts with '0').
- Otherwise: `dp[i] = dp[i+1]` (take one digit).
- If `10 <= int(s[i:i+2]) <= 26`: `dp[i] += dp[i+2]` (take two digits).

**Base cases:** `dp[n] = 1` (empty suffix has exactly one decoding: the empty string). `dp[n+1] = 0` (sentinel for two-digit lookback).

### Approach 1: Top-down memoization

Recursion mirrors the recurrence directly. The cache prevents revisiting the same suffix.

```python
class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)
        memo = {}

        def dp(i: int) -> int:
            if i == n:
                return 1  # empty suffix
            if i in memo:
                return memo[i]
            if s[i] == '0':
                memo[i] = 0
                return 0

            ways = dp(i + 1)  # single-digit decode
            if i + 1 < n and int(s[i:i + 2]) <= 26:
                ways += dp(i + 2)  # two-digit decode

            memo[i] = ways
            return ways

        return dp(0)
```

### Approach 2: Bottom-up tabulation

Build right-to-left so each state is available when needed. Then reduce to three rolling variables.

```python
class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)
        dp = [0] * (n + 1)
        dp[n] = 1

        for i in range(n - 1, -1, -1):
            if s[i] != '0':
                dp[i] += dp[i + 1]
                if i + 1 < n and int(s[i:i + 2]) <= 26:
                    dp[i] += dp[i + 2]

        return dp[0]
```

Space-optimized with rolling variables:

```python
class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)
        prev, prev2 = 1, 0  # dp[n]=1, dp[n+1]=0

        for i in range(n - 1, -1, -1):
            curr = 0
            if s[i] != '0':
                curr += prev
                if i + 1 < n and int(s[i:i + 2]) <= 26:
                    curr += prev2
            prev2, prev = prev, curr

        return prev
```

> `dp[n] = 1` is the sentinel "empty string has exactly one decoding." The two-digit check `int(s[i:i+2]) <= 26` also rules out leading-zero pairs like "06" because the `s[i] == '0'` guard blocks that branch earlier.

### Complexity
- **Time:** O(n). Single pass in either direction.
- **Space:** O(n) for the full dp array. O(1) with rolling variables.

### Key concepts to review
- [[Dynamic Programming]] - right-to-left tabulation matching the natural recursive structure.
- [[Memoization]] - top-down alternative caches `decode(i)` results.
- [[Space-Time Tradeoff]] - full dp array vs. three rolling variables.
- [[01.ClimbingStairs]] - same Fibonacci-like recurrence with simpler constraints.

### Common pitfalls
- Forgetting to check `s[i] != '0'` before adding `dp[i+1]`, which would count '0' as a valid single-digit decode.
- Using `s[i] == '1' or (s[i] == '2' and s[i+1] <= '6')` for the two-digit check is equivalent but must also guard `i+1 < n`.
- Off-by-one: the loop must go to `i = 0` inclusive, so `range(n-1, -1, -1)` not `range(n-1, 0, -1)`.
- Returning `dp[1]` instead of `dp[0]` in the array version.
