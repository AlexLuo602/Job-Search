# [746. Min Cost Climbing Stairs](https://leetcode.com/problems/min-cost-climbing-stairs/)


You are given an integer array cost where cost[i] is the cost of ith step on a staircase. Once you pay the cost, you can either climb one or two steps.

You can either start from the step with index 0, or the step with index 1.

Return the minimum cost to reach the top of the floor.

 

**Example 1:**
```
Input: cost = [10,15,20]
Output: 15
Explanation: You will start at index 1.
- Pay 15 and climb two steps to reach the top.
The total cost is 15.
```
**Example 2:**
```
Input: cost = [1,100,1,1,1,100,1,1,100,1]
Output: 6
Explanation: You will start at index 0.
- Pay 1 and climb two steps to reach index 2.
- Pay 1 and climb two steps to reach index 4.
- Pay 1 and climb two steps to reach index 6.
- Pay 1 and climb one step to reach index 7.
- Pay 1 and climb two steps to reach index 9.
- Pay 1 and climb one step to reach the top.
The total cost is 6.
```

Constraints:

- 2 <= cost.length <= 1000
- 0 <= cost[i] <= 999

---

## Solution

### Intuition
`dp[i]` is the minimum cost to reach stair `i`. From stair `i` you can arrive from `i-1` (paying `cost[i-1]`) or from `i-2` (paying `cost[i-2]`), so `dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])`. The "top" is one step beyond the last stair, so we build up to index `len(cost)`. [[Dynamic Programming]] avoids re-solving the same prefix choices that a greedy approach would get wrong on tricky cost sequences.

**State definition:** `dp[i]` = minimum cost to reach stair `i`.

**Recurrence:** `dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])`

**Base cases:** `dp[0] = 0`, `dp[1] = 0` (you can start at index 0 or 1 for free).

### Approach 1: Top-down memoization

Recursively compute the cheapest path to the top, caching each stair's answer.

```python
class Solution:
    def minCostClimbingStairs(self, cost: list[int]) -> int:
        memo = {}

        def dp(i: int) -> int:
            if i <= 1:
                return 0  # start at index 0 or 1 for free
            if i in memo:
                return memo[i]
            memo[i] = min(dp(i - 1) + cost[i - 1],
                          dp(i - 2) + cost[i - 2])
            return memo[i]

        return dp(len(cost))  # "top" is one past the last stair
```

> The top floor is index `len(cost)`, not `len(cost) - 1`. Calling `dp(len(cost))` asks for the cheapest way to get one step past the last stair.

### Approach 2: Bottom-up tabulation

Build the answer iteratively. Because each state depends only on the two previous values, two rolling variables replace the full array.

```python
class Solution:
    def minCostClimbingStairs(self, cost: list[int]) -> int:
        # prev2 = min cost to reach i-2, prev1 = min cost to reach i-1
        prev2, prev1 = 0, 0  # can start at index 0 or 1 for free

        # build dp from index 2 up to len(cost) (the "top")
        for i in range(2, len(cost) + 1):
            curr = min(prev1 + cost[i - 1], prev2 + cost[i - 2])
            prev2, prev1 = prev1, curr

        return prev1
```

> The top floor is at index `len(cost)`, one past the last step. Initializing `prev2 = prev1 = 0` captures the fact that we may start at index 0 or 1 at zero cost.

### Complexity
- **Time:** O(n) for both approaches. Each stair is computed once.
- **Space:** Memoization uses O(n) for cache and stack. Tabulation uses O(1) with two rolling variables.

### Key concepts to review
- [[Dynamic Programming]] - optimal substructure: cheapest way to reach `i` depends only on the two preceding states.
- [[Memoization]] - top-down cache to avoid redundant recursive work.
- [[Space-Time Tradeoff]] - full array vs. two variables.
- [[01.ClimbingStairs]] - same Fibonacci-style recurrence but without costs.

### Common pitfalls
- Forgetting the top is at index `len(cost)`, not `len(cost) - 1`.
- Initializing `prev2 = cost[0], prev1 = cost[1]` conflates reaching a step with paying its cost immediately.
- Modifying the input array in-place works but is surprising and can fail read-only inputs.
- Using `min(cost[0], cost[1])` as the final answer only works if you track costs differently.
