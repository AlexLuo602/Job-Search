# [213. House Robber II](https://leetcode.com/problems/house-robber-ii/)


You are a professional robber planning to rob houses along a street. Each house has a certain amount of money stashed. All houses at this place are arranged in a circle. That means the first house is the neighbor of the last one. Meanwhile, adjacent houses have a security system connected, and it will automatically contact the police if two adjacent houses were broken into on the same night.

Given an integer array nums representing the amount of money of each house, return the maximum amount of money you can rob tonight without alerting the police.

 

**Example 1:**
```
Input: nums = [2,3,2]
Output: 3
Explanation: You cannot rob house 1 (money = 2) and then rob house 3 (money = 2), because they are adjacent houses.
```
**Example 2:**
```
Input: nums = [1,2,3,1]
Output: 4
Explanation: Rob house 1 (money = 1) and then rob house 3 (money = 3).
Total amount you can rob = 1 + 3 = 4.
```
**Example 3:**
```
Input: nums = [1,2,3]
Output: 3
```

Constraints:

- 1 <= nums.length <= 100
- 0 <= nums[i] <= 1000

---

## Solution

### Intuition
The circular constraint means house 0 and house `n-1` cannot both be robbed. Any valid selection must exclude at least one of the two endpoints. We can break the circle by running the linear [[03.HouseRobber]] recurrence twice on overlapping ranges and returning the better result:

- **Range A:** `nums[0..n-2]` (exclude the last house)
- **Range B:** `nums[1..n-1]` (exclude the first house)

Every valid circular selection fits inside at least one of these two ranges. The recurrence, base cases, and rolling-variable optimization are identical to [[03.HouseRobber]], so this note focuses on the two-range reduction rather than re-deriving the DP.

### Approach: Two linear passes

Factor out a helper that runs the space-optimized linear House Robber on a slice, then call it twice.

```python
class Solution:
    def rob(self, nums: list[int]) -> int:
        if len(nums) == 1:
            return nums[0]

        def rob_linear(houses: list[int]) -> int:
            prev2, prev1 = 0, 0
            for num in houses:
                prev2, prev1 = prev1, max(prev1, num + prev2)
            return prev1

        # either skip the last house or skip the first house
        return max(rob_linear(nums[:-1]), rob_linear(nums[1:]))
```

> The single-element guard is necessary because `nums[:-1]` on a length-1 list yields an empty slice, returning 0 instead of `nums[0]`. For longer inputs, both ranges overlap in `nums[1..n-2]`, which is correct because the DP naturally considers skipping any interior house.

### Complexity
- **Time:** O(n). Two linear passes, each O(n).
- **Space:** O(1). No extra arrays. Python slices are O(n) memory but the helper itself is O(1) state.

### Key concepts to review
- [[Dynamic Programming]] - linear subproblem reuse across two passes.
- [[03.HouseRobber]] - the linear recurrence this problem reduces to.
- [[Space-Time Tradeoff]] - rolling variables keep each pass O(1) space.

### Common pitfalls
- Forgetting the `len(nums) == 1` guard, which causes `rob_linear([])` to return 0.
- Running only one pass on `nums[0..n-2]` and missing configurations where the first house is skipped.
- Slicing `nums[:-1]` and `nums[1:]` creates new list objects in Python, adding O(n) memory. Pass indices instead for strict O(1) space.
- Returning `max(nums[0], rob_linear(nums[1:]))` without symmetrically handling the other endpoint.
