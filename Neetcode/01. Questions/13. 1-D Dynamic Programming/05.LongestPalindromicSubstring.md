# 5. Longest Palindromic Substring


Given a string s, return the longest palindromic substring in s.

 
**Example 1:**
```
Input: s = "babad"
Output: "bab"
Explanation: "aba" is also a valid answer.
```
**Example 2:**
```
Input: s = "cbbd"
Output: "bb"
``` 

Constraints:

- 1 <= s.length <= 1000
- s consist of only digits and English letters.

---

## Solution

### Intuition
Every palindrome has a center: one character for odd length, the gap between two characters for even length. Expanding outward from each possible center and tracking the widest palindrome found avoids the O(n^3) brute-force of checking every substring. A 2D [[Dynamic Programming]] table also works in O(n^2) time and space, but center expansion achieves the same time with O(1) extra space, and it exposes the palindrome structure directly instead of hiding it behind table mechanics. That is why this note teaches center expansion as the single primary approach (the [[0.1DDynamicProgrammingGuide|guide's palindrome section]] covers when interval DP becomes necessary).

### Approach: Center expansion

For each index, expand outward for both odd-length and even-length palindromes, recording the best start and end indices.

```python
class Solution:
    def longestPalindrome(self, s: str) -> str:
        res_start, res_end = 0, 0  # inclusive indices of the best palindrome

        def expand(left: int, right: int) -> None:
            nonlocal res_start, res_end
            # expand while characters match
            while left >= 0 and right < len(s) and s[left] == s[right]:
                if right - left > res_end - res_start:
                    res_start, res_end = left, right
                left -= 1
                right += 1

        for i in range(len(s)):
            expand(i, i)      # odd-length center
            expand(i, i + 1)  # even-length center (gap between i and i+1)

        return s[res_start:res_end + 1]
```

> `res_end + 1` in the slice because Python's `s[a:b]` excludes `b`. The comparison `right - left > res_end - res_start` uses lengths without a separate variable, staying concise.

### Complexity
- **Time:** O(n^2). For each of n centers, expansion is at most O(n).
- **Space:** O(1). Only a constant number of index variables. The returned string slice is not counted as auxiliary space.

### Key concepts to review
- [[Dynamic Programming]] - 2D table alternative: `dp[i][j] = (s[i]==s[j] and dp[i+1][j-1])`.
- [[0.TwoPointerGuide|Two Pointer]] - the expand-around-center technique is essentially two pointers moving outward.
- [[06.PalindromicSubstrings]] - same expand pattern but counts all palindromes instead of returning the longest.

### Common pitfalls
- Forgetting to handle even-length palindromes with a separate `expand(i, i+1)` call.
- Using `s[res_start:res_end]` (forgetting `+1`) and returning a substring one character short.
- Updating `res_start/res_end` after expanding instead of inside the loop, missing shorter palindromes found during the outward walk.
- Off-by-one when comparing lengths: `right - left + 1` vs. `right - left` depending on whether both endpoints are inclusive.
