# [416. Partition Equal Subset Sum](https://leetcode.com/problems/partition-equal-subset-sum/)


Given a non-empty array nums containing only positive integers, find if the array can be partitioned into two subsets such that the sum of elements in both subsets is equal.

 
**Example 1:**
```
Input: nums = [1,5,11,5]
Output: true
Explanation: The array can be partitioned as [1, 5, 5] and [11].
```
**Example 2:**
```
Input: nums = [1,2,3,5]
Output: false
Explanation: The array cannot be partitioned into equal sum subsets.
```

Constraints:

- 1 <= nums.length <= 200
- 1 <= nums\[i\] <= 100

---

## Solution

### Intuition
Two equal-sum subsets means each has sum `total / 2`. So the problem reduces to: can we pick a subset of `nums` that sums to `target = total // 2`? This is the classic 0/1 knapsack (each element used at most once). [[Dynamic Programming]] builds reachable sums incrementally.

### State definition and recurrence

**State:** `dp[s]` = True if a subset summing to `s` is achievable using elements seen so far.

**Recurrence:** For each num, `dp[s] = dp[s] or dp[s - num]` (either we already reached `s`, or we reached `s - num` and now include `num`).

**Base case:** `dp[0] = True` (empty subset sums to 0).

**Key constraint:** Iterating sums right-to-left ensures each element is used at most once (0/1 knapsack). Left-to-right would allow reuse (unbounded knapsack), which is wrong here.

### Approach 1: Top-down memoization

Recursion decides for each element: include it or skip it. The cache key is `(index, remaining_sum)`.

```python
class Solution:
    def canPartition(self, nums: list[int]) -> bool:
        total = sum(nums)
        if total % 2 != 0:
            return False

        target = total // 2
        n = len(nums)
        memo = {}

        def dp(i: int, remaining: int) -> bool:
            if remaining == 0:
                return True
            if i == n or remaining < 0:
                return False
            if (i, remaining) in memo:
                return memo[(i, remaining)]

            # take nums[i] or skip it
            result = dp(i + 1, remaining - nums[i]) or dp(i + 1, remaining)
            memo[(i, remaining)] = result
            return result

        return dp(0, target)
```

### Approach 2: Bottom-up tabulation

1D boolean dp array updated in-place right-to-left (prevents using the same element twice).

```python
class Solution:
    def canPartition(self, nums: list[int]) -> bool:
        total = sum(nums)
        if total % 2 != 0:
            return False

        target = total // 2
        dp = [False] * (target + 1)
        dp[0] = True

        for num in nums:
            for s in range(target, num - 1, -1):
                dp[s] = dp[s] or dp[s - num]

        return dp[target]
```

> Iterating `s` from `target` down to `num` ensures that when we set `dp[s] = True` via `dp[s - num]`, the source still reflects the state before the current `num` was considered. A left-to-right sweep would allow using `num` multiple times, turning this into an unbounded knapsack.

### Complexity
- **Time:** O(n * target) where target = total/2. Both approaches visit at most n * target states.
- **Space:** O(target) for the 1D dp array. O(n * target) for the memoization cache in the worst case.

### Key concepts to review
- [[Dynamic Programming]] - 0/1 knapsack: each item used at most once, so we sweep right-to-left.
- [[Memoization]] - top-down alternative shown in Approach 1.
- [[08.CoinChange]] - unbounded knapsack (coins reused). Compare loop direction: left-to-right for unbounded, right-to-left for 0/1.
- [[Space-Time Tradeoff]] - 1D rolling array reduces a 2D (n x target) table to O(target) space.

### Common pitfalls
- Iterating sums left-to-right in the inner loop turns 0/1 knapsack into unbounded knapsack, giving wrong answers.
- Forgetting the odd-total early return causes the algorithm to target a non-integer, producing incorrect results.
- Starting the inner loop at `target` but ending at 0 instead of `num - 1` checks `dp[s - num]` at negative indices (Python wraps around silently).
- Initializing dp with all True instead of only dp\[0\] = True overstates achievable sums.
