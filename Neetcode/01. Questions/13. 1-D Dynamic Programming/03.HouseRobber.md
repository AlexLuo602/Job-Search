# [198. House Robber](https://leetcode.com/problems/house-robber/)

You are a professional robber planning to rob houses along a street. Each house has a certain amount of money stashed, the only constraint stopping you from robbing each of them is that adjacent houses have security systems connected and it will automatically contact the police if two adjacent houses were broken into on the same night.

Given an integer array nums representing the amount of money of each house, return the maximum amount of money you can rob tonight without alerting the police.

 

**Example 1:**
```
Input: nums = [1,2,3,1]
Output: 4
Explanation: Rob house 1 (money = 1) and then rob house 3 (money = 3).
Total amount you can rob = 1 + 3 = 4.
```
**Example 2:**
```
Input: nums = [2,7,9,3,1]
Output: 12
Explanation: Rob house 1 (money = 2), rob house 3 (money = 9) and rob house 5 (money = 1).
Total amount you can rob = 2 + 9 + 1 = 12.
```

Constraints:

- 1 <= nums.length <= 100
- 0 <= nums[i] <= 400

---

## Solution

### Intuition
At each house `i`, we either skip it (best loot up to `i-1`) or rob it (best loot up to `i-2` plus `nums[i]`). A greedy "always rob the richest adjacent pair" fails because local optima do not compose globally, but [[Dynamic Programming]] builds the optimal answer from overlapping subproblems.

**State definition:** `dp[i]` = maximum money robbable from the first `i` houses.

**Recurrence:** `dp[i] = max(dp[i-1], nums[i] + dp[i-2])`

**Base cases:** `dp[-1] = 0` (no houses), `dp[0] = nums[0]`.

### Approach 1: Top-down memoization

Recursively compute the best loot up to each house, caching results to avoid repeated work.

```python
class Solution:
    def rob(self, nums: list[int]) -> int:
        memo = {}

        def dp(i: int) -> int:
            if i < 0:
                return 0
            if i in memo:
                return memo[i]
            memo[i] = max(dp(i - 1), nums[i] + dp(i - 2))
            return memo[i]

        return dp(len(nums) - 1)
```

> The call `dp(len(nums) - 1)` asks for the maximum loot considering all houses. Each index is computed once and cached, collapsing the recursion tree from exponential to linear.

### Approach 2: Bottom-up tabulation

The full O(n) table reduces to two rolling variables because `dp[i]` only looks back two steps.

```python
class Solution:
    def rob(self, nums: list[int]) -> int:
        # prev2 = dp[i-2], prev1 = dp[i-1]
        prev2, prev1 = 0, 0

        for num in nums:
            # either skip current house or rob it
            curr = max(prev1, num + prev2)
            prev2, prev1 = prev1, curr

        return prev1
```

> Starting both rolling variables at 0 handles the base cases cleanly: `dp[-1] = 0` (no houses yet) and `dp[0] = nums[0]` emerges naturally on the first iteration without special-casing.

### Complexity
- **Time:** O(n) for both approaches. Each house is evaluated once.
- **Space:** Memoization uses O(n) for cache and stack. Tabulation uses O(1) with two rolling variables.

### Key concepts to review
- [[Dynamic Programming]] - each house decision depends on overlapping subproblems.
- [[Memoization]] - top-down recursive cache.
- [[Space-Time Tradeoff]] - rolling variables vs. full dp array.
- [[04.HouseRobberII]] - circular variant requiring two linear passes.

### Common pitfalls
- Special-casing `len(nums) == 1`: not needed when both rolling variables start at 0.
- Initializing `prev1 = nums[0]` and `prev2 = 0` and starting the loop at index 1 is valid but more fragile.
- Forgetting that `prev2` must capture `dp[i-2]` before updating, which Python's simultaneous assignment handles correctly.
- Returning `prev2` instead of `prev1` after the loop.
