# [152. Maximum Product Subarray](https://leetcode.com/problems/maximum-product-subarray/)


Given an integer array nums, find a contiguous non-empty subarray within the array that has the largest product, and return the product.

The test cases are generated so that the answer will fit in a 32-bit integer.

A subarray is a contiguous subsequence of the array.

 

**Example 1:**
```
Input: nums = [2,3,-2,4]
Output: 6
Explanation: [2,3] has the largest product 6.
```
**Example 2:**
```
Input: nums = [-2,0,-1]
Output: 0
Explanation: The result cannot be 2, because [-2,-1] is not a subarray.
```

Constraints:

- 1 <= nums.length <= 2 * 10<sup>4</sup>
- -10 <= nums[i] <= 10
- The product of any prefix or suffix of nums is guaranteed to fit in a 32-bit integer.

---

## Solution

### Intuition
Unlike the maximum-sum subarray ([[Kadane's Algorithm]]), products can flip sign: a large negative current minimum becomes a large positive maximum when multiplied by another negative. So we must track both `cur_max` and `cur_min` at every position. When we see a zero the running products reset to 1 (by including the zero and "restarting"). This is a [[Dynamic Programming]] approach where `dp_max[i]` and `dp_min[i]` each depend only on the previous state.

Tracking both extremes matters because multiplying by a negative can turn the previous minimum into the next maximum. The walkthrough shows this sign flip at `num = -2`.

### Approach: Optimal DP

Carry two running values (max and min ending at current position) and update the global answer each step.

```python
class Solution:
    def maxProduct(self, nums: list[int]) -> int:
        cur_max = cur_min = 1
        result = max(nums)  # handles all-negative arrays

        for num in nums:
            if num == 0:
                # zero resets both running products
                cur_max, cur_min = 1, 1
                continue

            # compute candidates before overwriting cur_max
            candidates = (num * cur_max, num * cur_min, num)
            cur_max = max(candidates)
            cur_min = min(candidates)
            result = max(result, cur_max)

        return result
```

> Multiplying the previous `cur_min` by a negative `num` can produce the new `cur_max`, so we must compute all three candidates from the same previous values before updating either variable. Grouping them in a tuple avoids the stale-read bug.

### Complexity
- **Time:** O(n). Single pass through `nums`.
- **Space:** O(1). Two rolling variables and the global result.

### Key concepts to review
- [[Kadane's Algorithm]] - conceptual ancestor: tracks running max ending here. This problem extends it to track running min as well.
- [[Dynamic Programming]] - each position's optimal value depends only on the previous state.
- [[Space-Time Tradeoff]] - O(1) rolling variables replace O(n) dp arrays.

### Common pitfalls
- Overwriting `cur_max` before computing `cur_min` causes a stale-read bug. Always compute all candidates from the same previous values.
- Initializing `result = 0` fails on all-negative arrays where the answer is negative. Use `max(nums)` instead.
- Forgetting the zero reset: without `continue`, zero multiplied into `cur_max` correctly becomes 0, but the next element would multiply by 0 rather than starting fresh.
- Not including the bare `num` as a candidate, which misses subarrays of length 1 after a reset.
