# [208. Implement Trie (Prefix Tree)](https://leetcode.com/problems/implement-trie-prefix-tree/)


A trie (pronounced as "try") or prefix tree is a tree data structure used to efficiently store and retrieve keys in a dataset of strings. There are various applications of this data structure, such as autocomplete and spellchecker.

Implement the Trie class:

- `Trie()` Initializes the trie object.
- `void insert(String word)` Inserts the string word into the trie.
- `boolean search(String word)` Returns true if the string word is in the trie (i.e., was inserted before), and false otherwise.
- `boolean startsWith(String prefix)` Returns true if there is a previously inserted string word that has the prefix prefix, and false otherwise.

**Example 1:**

![[trie-implement-example.svg]]

```text
Input
["Trie", "insert", "search", "search", "startsWith", "insert", "search"]
[[], ["apple"], ["apple"], ["app"], ["app"], ["app"], ["app"]]
Output
[null, null, true, false, true, null, true]

Explanation
Trie trie = new Trie();
trie.insert("apple");
trie.search("apple");   // return True
trie.search("app");     // return False
trie.startsWith("app"); // return True
trie.insert("app");
trie.search("app");     // return True
```

Constraints:

- 1 <= word.length, prefix.length <= 2000
- word and prefix consist only of lowercase English letters.
- At most 3 * 10<sup>4</sup> calls in total will be made to insert, search, and startsWith.

---

## Solution

### Intuition
A [[0.TrieGuide|Trie]] stores characters edge-by-edge from a root node, so every path from root to a marked node spells a valid word. The key insight is that `search` checks for a terminal marker at the end of the path, while `startsWith` only needs the path to exist. Using a dictionary of children (rather than a fixed 26-element array) keeps the Python implementation clean.

### Approach
Each `TrieNode` holds a dictionary mapping characters to child nodes and a boolean `is_end` flag. Insert walks the trie character by character, creating nodes as needed. Search and startsWith both walk the same path and differ only in what they return at the end.

```python
class TrieNode:
    def __init__(self) -> None:
        self.children: dict[str, "TrieNode"] = {}
        self.is_end: bool = False


class Trie:

    def __init__(self) -> None:
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        curr = self.root
        for ch in word:
            if ch not in curr.children:
                curr.children[ch] = TrieNode()  # create node on demand
            curr = curr.children[ch]
        curr.is_end = True  # mark word boundary

    def search(self, word: str) -> bool:
        curr = self.root
        for ch in word:
            if ch not in curr.children:
                return False
            curr = curr.children[ch]
        return curr.is_end  # must reach a true end marker

    def startsWith(self, prefix: str) -> bool:
        curr = self.root
        for ch in prefix:
            if ch not in curr.children:
                return False
            curr = curr.children[ch]
        return True  # path exists, regardless of end marker
```

> `startsWith` is strictly weaker than `search`: it returns `True` whenever `search` would, plus cases where the prefix is not a complete word. This is why the two methods share the same traversal logic but differ only in the final check.

### Walkthrough
Insert "apple", then insert "app".

| Action | Path traversed | is\_end set? |
|---|---|---|
| insert("apple") | a-p-p-l-e | e.is\_end = True |
| insert("app") | a-p-p | p.is\_end = True |
| search("app") | a-p-p | p.is\_end = True -> True |
| search("ap") | a-p | p.is\_end = False -> False |
| startsWith("ap") | a-p | path exists -> True |

### Complexity
- **Time:** O(m) per operation, where m is the word or prefix length. Each character is visited once.
- **Space:** O(m * n) total, where n is the number of inserted words. In the worst case (no shared prefixes) every character creates a new node.

### Key concepts to review
- [[0.TrieGuide|Trie]] - the core data structure. See siblings [[02.DesignAddandSearchWordDataStructure]] and [[03.WordSearchII]].
- [[Hash Map]] - used here as the children dictionary, giving O(1) child lookup.
- [[DFS|Depth-First Search]] - insert and search are both iterative DFS walks down a single path.

### Common pitfalls
- Forgetting to set `is_end = True` after the loop in `insert` (the node exists but the word is never marked complete).
- Returning `curr.is_end` in `startsWith` instead of `True` (turns it into a full `search`).
- Confusing prefix length with word length when tracing through examples.
- Using a 26-element array instead of a dict in Python. The dict is more idiomatic and handles non-lowercase inputs gracefully.
