# [50. Pow(x, n)](https://leetcode.com/problems/powx-n/)


Implement pow(x, n), which calculates x raised to the power n (i.e., xn).
**Example 1:**

```
Input: x = 2.00000, n = 10
Output: 1024.00000
```
**Example 2:**

```
Input: x = 2.10000, n = 3
Output: 9.26100
```
**Example 3:**

```
Input: x = 2.00000, n = -2
Output: 0.25000
Explanation: 2-2 = 1/22 = 1/4 = 0.25
```

Constraints:

- -100.0 < x < 100.0
- -2<sup>31</sup> <= n <= 2<sup>31</sup>-1
- -10<sup>4</sup> <= xn <= 10<sup>4</sup>

---

## Solution

### Intuition
[[Divide and Conquer]] (fast exponentiation): `x^n = (x^(n//2))^2` halves the problem at each step. This gives O(log n) multiplications instead of O(n). Handle negative `n` by computing `x^|n|` then taking the reciprocal.

### Approach 1: Brute force (for contrast)
Multiply x by itself n times. O(n) time, which times out for large n.

### Approach 2: Fast exponentiation (iterative)
Convert n to a positive exponent and handle the negative case at the end. Use the iterative bit-squaring approach: if the current bit of n is set, multiply the result by x; then square x and shift n right.

```python
class Solution:
    def myPow(self, x: float, n: int) -> float:
        if n < 0:
            x = 1 / x      # WHY: x^(-n) = (1/x)^n
            n = -n

        result = 1.0
        while n > 0:
            if n % 2 == 1:
                result *= x  # WHY: odd exponent contributes one extra factor of x
            x *= x           # WHY: square x to handle the next bit
            n //= 2          # WHY: shift right to process the next bit

        return result
```

> Negative n is handled by inverting x upfront rather than inverting the final result. This avoids a special branch inside the loop and correctly handles Python's arbitrary-precision integers for the absolute value.

### Walkthrough
x = 2.0, n = 10 (binary: 1010)

| n | n%2 | result | x after squaring |
|---|-----|--------|-----------------|
| 10 | 0 | 1.0 | 4.0 |
| 5 | 1 | 4.0 | 16.0 |
| 2 | 0 | 4.0 | 256.0 |
| 1 | 1 | 1024.0 | 65536.0 |
| 0 | - | loop ends | - |

Output: `1024.0`

Each halving step squares x. Odd exponents also fold in one extra factor of x:

```text
n=10 (even)  →  n=5 (odd: result*=x)  →  n=2 (even)  →  n=1 (odd: result*=x)  →  n=0 done
```

### Complexity
- **Time:** O(log n). The loop runs once per bit of n.
- **Space:** O(1). Iterative approach uses constant extra space.

### Key concepts to review
- [[Divide and Conquer]] - halving the exponent at each step is the key insight
- [[Recursion]] - the recursive form `myPow(x, n//2) ** 2` is equivalent but uses O(log n) stack space
- [[0.BitManipulationGuide|Bit Manipulation]] - the iterative approach processes exponent bits directly
- [[05.PlusOne]] - another math problem with a key edge case (negative n here, all-9 digits there)

### Common pitfalls
- Not handling negative n, which causes an infinite loop or wrong result.
- Using `n % 2 != 0` instead of `n % 2 == 1` - equivalent but less idiomatic.
- The recursive approach using `myPow(x, n//2) * myPow(x, n//2)` calls the function twice per level instead of once - use a local variable to avoid O(n) calls.
- Integer overflow risk in languages with fixed-width integers when computing `-n` for `n = INT_MIN`; Python avoids this automatically.
