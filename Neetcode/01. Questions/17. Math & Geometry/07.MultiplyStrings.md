# [43. Multiply Strings](https://leetcode.com/problems/multiply-strings/)


Given two non-negative integers num1 and num2 represented as strings, return the product of num1 and num2, also represented as a string.

Note: You must not use any built-in BigInteger library or convert the inputs to integer directly.
**Example 1:**

```
Input: num1 = "2", num2 = "3"
Output: "6"
```
**Example 2:**

```
Input: num1 = "123", num2 = "456"
Output: "56088"
```

Constraints:

- 1 <= num1.length, num2.length <= 200
- num1 and num2 consist of digits only.
- Both num1 and num2 do not contain any leading zero, except the number 0 itself.

---

## Solution

### Intuition
Grade-school multiplication: each digit pair (i, j) contributes to positions `i + j` and `i + j + 1` in the result array (where indices are from the right). Accumulate all partial products into an integer array, propagate carries, then convert to a string.

### Approach: Position-based digit multiplication
Allocate a result array of size `m + n` (maximum possible product length). For each pair of digits, add their product to the correct positions. Finally, convert non-zero digits to a string, handling the leading-zero case.

```python
class Solution:
    def multiply(self, num1: str, num2: str) -> str:
        if num1 == "0" or num2 == "0":
            return "0"

        m, n = len(num1), len(num2)
        pos = [0] * (m + n)  # WHY: product of m-digit and n-digit number has at most m+n digits

        # WHY: iterate from right (least significant) for both numbers
        for i in range(m - 1, -1, -1):
            for j in range(n - 1, -1, -1):
                mul = (ord(num1[i]) - ord('0')) * (ord(num2[j]) - ord('0'))
                p1, p2 = i + j, i + j + 1  # WHY: p2 is units place, p1 is tens place
                total = mul + pos[p2]

                pos[p2] = total % 10   # WHY: units digit goes to p2
                pos[p1] += total // 10  # WHY: carry goes to p1

        # WHY: skip leading zeros; at least one digit will be non-zero (handled above)
        result = "".join(str(d) for d in pos).lstrip("0")
        return result if result else "0"
```

> The product of digits at positions i and j (0-indexed from left) maps to positions `i+j` (tens) and `i+j+1` (units) in the output array. This works because position i from the left of an m-digit number represents a value at decimal place `m-1-i`.

### Walkthrough

Use `num1 = "23"` and `num2 = "14"`. The grade-school layout shows the two partial products and why the second row shifts one place:

```text
        2 3
      x 1 4
      -----
        9 2    23 x 4
      2 3 0    23 x 1, shifted one place
      -----
      3 2 2
```

The code stores the same work in four result slots. Each digit pair writes its ones digit to `p2 = i + j + 1` and adds its carry to `p1 = i + j`.

| Digit pair | `p1`, `p2` | `total = product + pos[p2]` | `pos` after ones and carry |
|---|---|---|---|
| `3 x 4` | 2, 3 | `12 + 0 = 12` | `[0, 0, 1, 2]` |
| `3 x 1` | 1, 2 | `3 + 1 = 4` | `[0, 0, 4, 2]` |
| `2 x 4` | 1, 2 | `8 + 4 = 12` | `[0, 1, 2, 2]` |
| `2 x 1` | 0, 1 | `2 + 1 = 3` | `[0, 3, 2, 2]` |

```text
pos index:   0  1  2  3
final pos:   0  3  2  2
skip index 0:    [  3  2  2  ] -> "322"
```

### Complexity
- **Time:** O(m * n). Two nested loops over all digit pairs.
- **Space:** O(m + n). The position array holds at most m+n digits.

### Common pitfalls
- Forgetting the early return for "0" inputs, which causes the lstrip logic to return an empty string.
- Getting the position mapping wrong: the units digit goes to `i+j+1`, not `i+j`.
- Not adding the existing value at `pos[p2]` before splitting into carry and remainder.
- Converting the result with `int("".join(...))` which defeats the "no direct integer conversion" requirement.
