# 202. Happy Number


Write an algorithm to determine if a number n is happy.

A happy number is a number defined by the following process:

- Starting with any positive integer, replace the number by the sum of the squares of its digits.
- Repeat the process until the number equals 1 (where it will stay), or it loops endlessly in a cycle which does not include 1.
- Those numbers for which this process ends in 1 are happy.

Return true if n is a happy number, and false if not.
**Example 1:**

```
Input: n = 19
Output: true
Explanation:
12 + 92 = 82
82 + 22 = 68
62 + 82 = 100
12 + 02 + 02 = 1
```
**Example 2:**

```
Input: n = 2
Output: false
```

Constraints:
- 1 <= n <= 231 - 1

---

## Solution

### Intuition
The digit-squaring process either terminates at 1 (happy) or loops forever (not happy). This is a cycle-detection problem. We can use a [[Set]] to record seen values, stopping when we revisit a value (cycle found) or reach 1. Alternatively, [[Fast & Slow Pointers|Fast and Slow Pointers]] (Floyd's algorithm) detects the cycle in O(1) space.

### Approach 1: Set-based cycle detection

Store seen values in a [[Set]]. If we reach 1 return true; if we see a repeat return false.

```python
class Solution:
    def isHappy(self, n: int) -> bool:
        seen: set[int] = set()

        while n != 1:
            if n in seen:
                return False      # cycle detected
            seen.add(n)
            n = self._digit_square_sum(n)

        return True

    def _digit_square_sum(self, n: int) -> int:
        total = 0
        while n > 0:
            digit = n % 10
            total += digit * digit
            n //= 10
        return total
```

### Approach 2: Fast and Slow Pointers (O(1) space)

Run slow one step and fast two steps per iteration. They meet inside the cycle if one exists. If the meeting point is 1, the number is happy.

```python
class Solution:
    def isHappy(self, n: int) -> bool:
        slow, fast = n, n

        while True:
            slow = self._digit_square_sum(slow)
            fast = self._digit_square_sum(self._digit_square_sum(fast))
            if slow == fast:
                break

        return slow == 1

    def _digit_square_sum(self, n: int) -> int:
        total = 0
        while n > 0:
            digit = n % 10
            total += digit * digit
            n //= 10
        return total
```

> For unhappy numbers the cycle is always entered, so the fast pointer is guaranteed to lap the slow pointer. The meeting point being 1 confirms happiness.

### Walkthrough
n = 19 (happy):

| Step | n |
|------|---|
| 1^2 + 9^2 | 82 |
| 8^2 + 2^2 | 68 |
| 6^2 + 8^2 | 100 |
| 1^2 + 0^2 + 0^2 | 1 |

Reached 1 -> `true`

A happy chain terminates at 1. An unhappy chain always enters the same 8-number cycle:

```text
Happy (n = 19):   19 → 82 → 68 → 100 → [1] ✓

Unhappy cycle:    4 → 16 → 37 → 58
                  ↑                ↓
                 20 ← 42 ← 145 ← 89
```

Any unhappy number eventually enters the cycle above. The set or fast/slow pointer detects the revisit before looping forever.

### Complexity
- **Time:** O(log n). The digit-squaring process converges quickly; the number of steps is bounded by the number's digit count.
- **Space:** O(log n) for the [[Set]] approach; O(1) for [[Fast & Slow Pointers|Fast and Slow Pointers]].

### Key concepts to review
- [[Fast & Slow Pointers|Fast and Slow Pointers]] - Floyd's cycle detection in O(1) space
- [[Set]] - simple O(log n) space cycle detection via membership testing
- [[08.DetectSquares]] - another problem using square geometry

### Common pitfalls
- Not handling the termination condition for the fast/slow approach: the loop must break when `slow == fast`, not just when either equals 1.
- Integer division: use `n //= 10` not `n /= 10` to avoid floating-point issues.
- Forgetting that the meeting point in Floyd's must be checked against 1 afterward; meeting at a non-1 value means the cycle does not include 1 (unhappy).
- Infinite loop if the slow pointer's loop condition uses `n != 1` without checking for cycles.
