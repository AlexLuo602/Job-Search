# [45. Jump Game II](https://leetcode.com/problems/jump-game-ii/)

Given an array of non-negative integers nums, you are initially positioned at the first index of the array.

Each element in the array represents your maximum jump length at that position.

Your goal is to reach the last index in the minimum number of jumps.

You can assume that you can always reach the last index.
**Example 1:**

![[jump-game-ii-example.svg]]

```text
Input: nums = [2,3,1,1,4]
Output: 2
Explanation: The minimum number of jumps to reach the last index is 2. Jump 1 step from index 0 to 1, then 3 steps to the last index.
```

**Example 2:**

```text
Input: nums = [2,3,0,1,4]
Output: 2
```

Constraints:

- 1 <= nums.length <= 104
- 0 <= nums[i] <= 1000

---

## Solution

### Intuition
[[0.GreedyGuide|Greedy]] BFS-level approach: think of each "jump" as a level in a BFS tree. Within the current level (current window of reachable indices), find the furthest index reachable. When we exhaust the current window, we must make a jump (increment count) and the new window becomes everything up to that furthest index.

### Approach 1: Brute force (for contrast)
DP from right to left: `dp[i]` = minimum jumps from index i to end. For each i, try all valid jumps j in `[1, nums[i]]` and take `1 + min(dp[i+j])`. O(n^2) time, O(n) space.

### Approach 2: Greedy Window
Track `current_end` (end of current jump's reach) and `farthest` (maximum reach seen in current window). When `i == current_end`, we must take a jump - increment `jumps` and set `current_end = farthest`.

```python
class Solution:
    def jump(self, nums: list[int]) -> int:
        jumps = 0
        current_end = 0   # WHY: end of the range covered by current jump
        farthest = 0      # WHY: furthest index reachable from current window

        for i in range(len(nums) - 1):  # WHY: stop before last; no jump needed from there
            farthest = max(farthest, i + nums[i])
            if i == current_end:
                # WHY: exhausted current jump's range; must take another jump
                jumps += 1
                current_end = farthest

        return jumps
```

> We iterate only to `len(nums) - 2` because we never need to jump FROM the last index. The loop increments `jumps` exactly when we cross each boundary, producing the minimum count.

### Complexity
- **Time:** O(n). Single pass through the array.
- **Space:** O(1). Three integer variables.

### Key concepts to review
- [[0.GreedyGuide|Greedy]] - choosing the furthest reachable endpoint at each "level" is provably optimal
- [[BFS|Breadth-First Search]] - conceptually this is BFS where each level corresponds to one jump
- [[Dynamic Programming]] - the O(n^2) DP alternative, useful as brute force contrast
- [[02.Jump]] - prerequisite problem: determine IF the last index is reachable
- [[04.GasStation]] - another greedy circuit/path traversal problem

### Common pitfalls
- Iterating through all indices including the last - causes an extra jump to be counted.
- Updating `current_end = farthest` only after the loop, instead of during when `i == current_end`.
- Confusing `farthest` (global max reach seen so far) with `current_end` (boundary of current jump).
- Off-by-one in the loop bound: use `range(len(nums) - 1)` not `range(len(nums))`.
