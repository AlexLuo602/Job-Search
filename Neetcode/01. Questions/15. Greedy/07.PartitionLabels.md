# 763. Partition Labels

You are given a string s. Partition the string into as many parts as possible so that each letter appears in at most one part. Return a list of integers representing the size of these parts.

**Example 1:**

![[partition-labels-example.svg]]

```text
Input: s = "ababcbacadefegdehijhklij"
Output: [9,7,8]
```

**Example 2:**

```text
Input: s = "eccbbbbdec"
Output: [10]
```

Constraints:

- 1 <= s.length <= 500
- s consists of lowercase English letters

---

## Solution

### Intuition
[[0.GreedyGuide|Greedy]] in two passes. First, record the last occurrence index of every character. Then sweep left to right, expanding the current partition's end whenever we encounter a character whose last occurrence extends beyond it. When we reach the end of the current partition, we have found the smallest valid cut.

### Approach: Last-occurrence map + greedy sweep
Precompute `last[c]` = last index of character c. Walk the string tracking `start` and `end` of the current partition. At each index i, extend `end = max(end, last[s[i]])`. When `i == end`, the partition is complete: record its size and reset `start`.

```python
class Solution:
    def partitionLabels(self, s: str) -> list[int]:
        last = {c: i for i, c in enumerate(s)}  # WHY: last occurrence of each char
        sizes = []
        start = end = 0

        for i, c in enumerate(s):
            end = max(end, last[c])  # WHY: extend partition to include last use of c
            if i == end:
                # WHY: all chars in [start, end] have no occurrences beyond 'end'
                sizes.append(end - start + 1)
                start = i + 1

        return sizes
```

> The dict comprehension `{c: i for i, c in enumerate(s)}` naturally keeps the last index for each character, because later iterations overwrite earlier ones.

### Complexity
- **Time:** O(n). Two linear passes: one to build the last-occurrence map, one to sweep.
- **Space:** O(1). The map holds at most 26 entries (lowercase letters only).

### Key concepts to review
- [[0.GreedyGuide|Greedy]] - always extend the current partition as far as needed, cut as soon as it is safe
- [[Hash Map]] - stores the last occurrence index for O(1) lookup during the sweep
- [[04.GasStation]] - similar single-pass greedy with a running boundary reset
- [[06.MergeTripletsToFormTargetTriplet]] - greedy that also accumulates a running maximum

### Common pitfalls
- Using the first occurrence instead of the last occurrence, which creates incorrect partition boundaries.
- Incrementing `start` by `end - start + 1` instead of setting `start = i + 1`, causing off-by-one drift.
- Forgetting to update `end` before checking `i == end`, which cuts the partition too early.
- Using a loop index variable that skips characters after recording a partition, which is unnecessary here since every character must still be visited to track `end`.
