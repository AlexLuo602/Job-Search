# [55. Jump Game](https://leetcode.com/problems/jump-game/)

You are given an integer array nums. You are initially positioned at the array's first index, and each element in the array represents your maximum jump length at that position.

Return true if you can reach the last index, or false otherwise.

**Example 1:**

![[jump-game-example.svg]]

```text
Input: nums = [2,3,1,1,4]
Output: true
Explanation: Jump 1 step from index 0 to 1, then 3 steps to the last index.
```

**Example 2:**

```text
Input: nums = [3,2,1,0,4]
Output: false
Explanation: You will always arrive at index 3 no matter what. Its maximum jump length is 0, which makes it impossible to reach the last index.
```

Constraints:

- 1 <= nums.length <= 104
- 0 <= nums[i] <= 105

---

## Solution

### Intuition
[[0.GreedyGuide|Greedy]] works here because we only need to know whether the last index is reachable, not the exact path. Track the furthest index reachable from positions visited so far. If at any point our current index exceeds the furthest reachable index, we are stuck.

### Approach: Track Max Reachable Index
Iterate through every index. Maintain `reach`, the furthest index reachable so far. If `i > reach`, index `i` is unreachable, so return False. Otherwise extend `reach = max(reach, i + nums[i])`. If the loop finishes, every index (including the last) was reachable.

```python
class Solution:
    def canJump(self, nums: list[int]) -> bool:
        reach = 0  # WHY: furthest index reachable from positions seen so far

        for i in range(len(nums)):
            if i > reach:
                return False  # WHY: current index is already unreachable
            reach = max(reach, i + nums[i])

        return True
```

> Iterate over every index (`range(len(nums))`), not just up to `len(nums) - 1`. Stopping one short and returning an unconditional `True` is the classic bug here: on `[3,2,1,0,4]` the frontier stalls at index 3, and a short loop would finish without ever testing index 4.

### Complexity
- **Time:** O(n). Single pass through the array.
- **Space:** O(1). Only one integer variable maintained.

### Key concepts to review
- [[0.GreedyGuide|Greedy]] - tracking maximum reach greedily avoids exploring every possible jump path
- [[Dynamic Programming]] - DP alternative: dp\[i\] = can we reach index i? O(n^2)
- [[03.JumpII]] - extension: find minimum number of jumps to reach the end
- [[01.MaximumSubarray]] - another greedy tracking-a-running-maximum pattern
- [[04.GasStation]] - similar "can we complete a circuit?" greedy pattern

### Common pitfalls
- Iterating only to `len(nums) - 1` with the check `i > reach` - this misses the case where reach exactly equals the second-to-last index but the last index is still unreachable.
- Returning True immediately when `reach >= len(nums) - 1` inside the loop - this is an optimization but can be skipped for clarity.
- Confusing "maximum jump length" with "exact jump length" - nums\[i\] is the maximum, so any jump from 1 to nums\[i\] is valid.
- Off-by-one: the last index is `len(nums) - 1`, not `len(nums)`.
