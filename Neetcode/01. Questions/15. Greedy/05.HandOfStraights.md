# [846. Hand of Straights](https://leetcode.com/problems/hand-of-straights/)

Alice has some number of cards and she wants to rearrange the cards into groups so that each group is of size groupSize, and consists of groupSize consecutive cards.

Given an integer array hand where hand\[i\] is the value written on the ith card and an integer groupSize, return true if she can rearrange the cards, or false otherwise.

**Example 1:**

![[hand-of-straights-example.svg]]

```text
Input: hand = [1,2,3,6,2,3,4,7,8], groupSize = 3
Output: true
Explanation: Alice's hand can be rearranged as [1,2,3],[2,3,4],[6,7,8]
```

**Example 2:**

```text
Input: hand = [1,2,3,4,5], groupSize = 4
Output: false
Explanation: Alice's hand can not be rearranged into groups of 4.
```

Constraints:

- 1 <= hand.length <= 104
- 0 <= hand\[i\] <= 109
- 1 <= groupSize <= hand.length

> Note: This question is the same as 1296: https://leetcode.com/problems/divide-array-in-sets-of-k-consecutive-numbers/

## Solution

### Intuition
[[0.GreedyGuide|Greedy]] with [[Sorting]] and a [[Hash Map]]: always start the next group from the smallest remaining card. If the smallest card cannot form a complete consecutive group of size `groupSize`, no valid arrangement exists. Count frequencies, then consume groups in sorted order.

### Approach: Sort unique values + frequency map
Count each card's frequency. Iterate over sorted unique values. For each value that still has remaining count, try to consume a group of `groupSize` consecutive cards starting there. If any card in the group is missing, return False.

```python
from collections import Counter

class Solution:
    def isNStraightHand(self, hand: list[int], groupSize: int) -> bool:
        if len(hand) % groupSize != 0:
            return False  # WHY: total cards must be divisible into equal groups

        count = Counter(hand)
        sorted_keys = sorted(count)  # WHY: always start from the smallest card

        for val in sorted_keys:
            freq = count[val]
            if freq == 0:
                continue
            # WHY: try to form 'freq' groups starting at 'val'
            for offset in range(groupSize):
                if count[val + offset] < freq:
                    return False
                count[val + offset] -= freq

        return True
```

> We iterate over sorted unique values rather than all cards. When we encounter a value with remaining count `freq`, we must start exactly `freq` groups here, because no earlier value can start a group that includes this card.

### Walkthrough
hand = `[1,2,3,6,2,3,4,7,8]`, groupSize = 3

count = {1:1, 2:2, 3:2, 4:1, 6:1, 7:1, 8:1}

| val | freq | Groups formed | count after |
|-----|------|---------------|-------------|
| 1 | 1 | \[1,2,3\] x1 | {1:0, 2:1, 3:1, 4:1, 6:1, 7:1, 8:1} |
| 2 | 1 | \[2,3,4\] x1 | {2:0, 3:0, 4:0, 6:1, 7:1, 8:1} |
| 3,4 | 0 | skip | -- |
| 6 | 1 | \[6,7,8\] x1 | {6:0, 7:0, 8:0} |

All counts reach 0. Output: `true`

### Complexity
- **Time:** O(n log n). Sorting the unique keys dominates. Each card is processed a constant number of times.
- **Space:** O(n). The frequency map stores at most n entries.

### Key concepts to review
- [[0.GreedyGuide|Greedy]] - consuming from the smallest value first is the only valid greedy order
- [[Sorting]] - required to process values in ascending order
- [[Hash Map]] - frequency counting enables O(1) group validity checks
- [[04.GasStation]] - another greedy problem where an early decision eliminates many candidates
- [[06.MergeTripletsToFormTargetTriplet]] - also uses greedy filtering on valid triplets

### Common pitfalls
- Not checking `len(hand) % groupSize != 0` early, wasting work on impossible inputs.
- Iterating over `hand` directly instead of sorted unique keys, which can process values out of order.
- Decrementing by 1 for each card in the group instead of by `freq` (the count of groups starting here).
- Using a priority queue (valid but O(n log n) with extra overhead) when sorted unique keys suffice.
