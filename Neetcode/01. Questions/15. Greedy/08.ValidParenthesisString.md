# [678. Valid Parenthesis String](https://leetcode.com/problems/valid-parenthesis-string/)

Given a string s containing only three types of characters: '(', ')' and '*', return true if s is valid.

The following rules define a valid string:

Any left parenthesis '(' must have a corresponding right parenthesis ')'.
Any right parenthesis ')' must have a corresponding left parenthesis '('.
Left parenthesis '(' must go before the corresponding right parenthesis ')'.
'*' could be treated as a single right parenthesis ')' or a single left parenthesis '(' or an empty string "".

**Example 1:**

```text
Input: s = "()"
Output: true
```

**Example 2:**

```text
Input: s = "(*)"
Output: true
```

**Example 3:**

```text
Input: s = "(*))"
Output: true
```

Constraints:

- 1 <= s.length <= 100
- s\[i\] is '(', ')' or '*'.

---

## Solution

### Intuition
[[0.GreedyGuide|Greedy]] with a range of possible open-paren counts. Rather than tracking one exact count, track `lo` (minimum possible unmatched `(`) and `hi` (maximum possible unmatched `(`). A `*` widens the range by decrementing `lo` and incrementing `hi`. `(` shifts both up, `)` shifts both down. If `hi` ever drops below 0, too many `)` exist and the string is invalid. At the end, validity requires `lo == 0`.

### Approach: Greedy min/max open count
Maintain `lo` and `hi` representing the range of valid unmatched `(` counts. Clamp `lo` to 0 at each step (a negative minimum is impossible). If `hi < 0` at any point, return False. Return `lo == 0` at the end.

```python
class Solution:
    def checkValidString(self, s: str) -> bool:
        lo = hi = 0  # WHY: range of possible unmatched '(' counts

        for c in s:
            if c == '(':
                lo += 1
                hi += 1
            elif c == ')':
                lo -= 1
                hi -= 1
            else:  # '*'
                lo -= 1  # WHY: treat '*' as ')' for the minimum estimate
                hi += 1  # WHY: treat '*' as '(' for the maximum estimate

            if hi < 0:
                return False  # WHY: too many ')' even in the best case
            lo = max(lo, 0)  # WHY: negative open count is impossible

        return lo == 0  # WHY: minimum unmatched '(' must be closeable
```

> `lo` is the pessimistic count (all `*` become `)`) and `hi` is the optimistic count (all `*` become `(`). As long as 0 is within `[lo, hi]` at the end, some assignment of `*` makes the string valid.

### Complexity
- **Time:** O(n). Single pass through the string.
- **Space:** O(1). Only two integer variables maintained.

### Key concepts to review
- [[0.GreedyGuide|Greedy]] - tracking a range instead of a single value handles the wildcard `*` optimally
- [[Stack]] - an alternative O(n) space approach uses two stacks (indices of `(` and `*`)
- [[Dynamic Programming]] - memoized backtracking is O(n^2) and useful to see why greedy is faster
- [[07.PartitionLabels]] - another greedy that tracks a running boundary through a string

### Common pitfalls
- Forgetting to clamp `lo = max(lo, 0)` after each step, allowing the minimum to go negative.
- Checking `lo < 0` instead of `hi < 0` to detect impossibility. `hi < 0` is the correct early-exit condition.
- Returning `lo == 0 and hi >= 0` instead of just `lo == 0` (hi >= 0 is guaranteed by the early-exit check).
- Confusing the roles of `lo` and `hi`: `lo` is the minimum unmatched count (all `*` treated as `)`) and `hi` is the maximum (all `*` treated as `(`).
