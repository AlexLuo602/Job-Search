# [134. Gas Station](https://leetcode.com/problems/gas-station/)

There are n gas stations along a circular route, where the amount of gas at the ith station is gas\[i\].

You have a car with an unlimited gas tank and it costs cost\[i\] of gas to travel from the ith station to its next (i + 1)th station. You begin the journey with an empty tank at one of the gas stations.

Given two integer arrays gas and cost, return the starting gas station's index if you can travel around the circuit once in the clockwise direction, otherwise return -1. If there exists a solution, it is guaranteed to be unique.

**Example 1:**

![[gas-station-example.svg]]

```text
Input: gas = [1,2,3,4,5], cost = [3,4,5,1,2]
Output: 3
Explanation:
Start at station 3 (index 3) and fill up with 4 unit of gas. Your tank = 0 + 4 = 4
Travel to station 4. Your tank = 4 - 1 + 5 = 8
Travel to station 0. Your tank = 8 - 2 + 1 = 7
Travel to station 1. Your tank = 7 - 3 + 2 = 6
Travel to station 2. Your tank = 6 - 4 + 3 = 5
Travel to station 3. The cost is 5. Your gas is just enough to travel back to station 3.
Therefore, return 3 as the starting index.
```

**Example 2:**

```text
Input: gas = [2,3,4], cost = [3,4,3]
Output: -1
Explanation:
You can't start at station 0 or 1, as there is not enough gas to travel to the next station.
Let's start at station 2 and fill up with 4 unit of gas. Your tank = 0 + 4 = 4
Travel to station 0. Your tank = 4 - 3 + 2 = 3
Travel to station 1. Your tank = 3 - 3 + 3 = 3
You cannot travel back to station 2, as it requires 4 unit of gas but you only have 3.
Therefore, you can't travel around the circuit once no matter where you start.
```

Constraints:

- n == gas.length == cost.length
- 1 <= n <= 10<sup>5</sup>
- 0 <= gas\[i\], cost\[i\] <= 10<sup>4</sup>

## Solution

### Intuition
Two [[0.GreedyGuide|Greedy]] observations unlock an O(n) solution. First: if the total gas is less than total cost, no solution exists. Second: if starting at index s fails (tank goes negative) at some station j, then no starting point between s and j can work either. Any such start would still encounter the same deficit at j but with less accumulated gas. So we reset the candidate start to j+1 and continue.

### Approach: Greedy Single Pass
Track the running tank `current` and total surplus/deficit `total`. If `current` ever goes negative, reset it to 0 and set the new candidate start to `i + 1`. After the loop, return the candidate if `total >= 0`, else -1.

```python
class Solution:
    def canCompleteCircuit(self, gas: list[int], cost: list[int]) -> int:
        total = 0    # WHY: net gas across entire circuit; determines feasibility
        current = 0  # WHY: running tank from current candidate start
        start = 0    # WHY: current candidate starting station

        for i in range(len(gas)):
            gain = gas[i] - cost[i]
            total += gain
            current += gain
            if current < 0:
                # WHY: can't reach i+1 from 'start'; reset candidate
                current = 0
                start = i + 1

        # WHY: if total >= 0, a solution is guaranteed unique by problem constraints
        return start if total >= 0 else -1
```

> The key insight is that the failing prefix is not just bad for the current start. It eliminates every potential start within that prefix. This lets us scan the array only once rather than trying each starting point.

### Complexity
- **Time:** O(n). Single pass through both arrays.
- **Space:** O(1). Three integer variables.

### Key concepts to review
- [[0.GreedyGuide|Greedy]] - the "reset start" insight eliminates O(n) candidate starts in one pass
- [[02.Jump]] - similar greedy pattern of tracking a running value and resetting
- [[03.JumpII]] - another circular/boundary greedy problem
- [[05.HandOfStraights]] - greedy with additional data structure overhead

### Common pitfalls
- Trying every starting point with a simulation is O(n^2) and unnecessary.
- Checking only `total >= 0` without tracking the `start` candidate tells you if a solution exists but not which index.
- Off-by-one: setting `start = i` instead of `start = i + 1` when resetting.
- Forgetting that the circuit is circular. The greedy approach handles this implicitly because a valid start from the candidate guarantees the second half works (covered by the total >= 0 check).
