# 1899. Merge Triplets to Form Target Triplet

A triplet is an array of three integers. You are given a 2D array triplets and a target triplet. In one operation, choose two triplets and replace one with the element-wise maximum. Return true if you can obtain target as one of the triplets.

**Example 1:**

```text
Input: triplets = [[2,5,3],[1,8,4],[1,7,5]], target = [2,7,5]
Output: true
```

**Example 2:**

```text
Input: triplets = [[3,4,5],[4,5,6]], target = [3,2,5]
Output: false
```

Constraints:

- 1 <= triplets.length <= 10^5
- triplets\[i\].length == target.length == 3
- 1 <= ai, bi, ci, x, y, z <= 1000

---

## Solution

### Intuition
[[0.GreedyGuide|Greedy]] filtering: any triplet with a value exceeding the corresponding target component is dangerous, because merging it would push that component above the target permanently. Discard such triplets, then take the element-wise maximum of the safe ones. If the result equals the target, it is achievable.

### Approach: Filter then element-wise max
Iterate through all triplets. Skip any triplet where any component exceeds the corresponding target value. For the remaining triplets, accumulate the running element-wise maximum. Check if it equals target.

```python
class Solution:
    def mergeTriplets(self, triplets: list[list[int]], target: list[int]) -> bool:
        result = [0, 0, 0]

        for t in triplets:
            # WHY: a triplet exceeding any target component can never be safely merged
            if t[0] > target[0] or t[1] > target[1] or t[2] > target[2]:
                continue
            # WHY: take element-wise max across all valid triplets
            result[0] = max(result[0], t[0])
            result[1] = max(result[1], t[1])
            result[2] = max(result[2], t[2])

        return result == target
```

> The merge operation is idempotent and commutative: repeated merging of valid triplets accumulates the element-wise maximum. We do not need to simulate the actual sequence of operations.

### Walkthrough
triplets = `[[2,5,3],[1,8,4],[1,7,5]]`, target = `[2,7,5]`

| Triplet | Exceeds target? | result after |
|---------|----------------|--------------|
| \[2,5,3\] | No (2<=2, 5<=7, 3<=5) | \[2,5,3\] |
| \[1,8,4\] | Yes (8>7) | skip |
| \[1,7,5\] | No (1<=2, 7<=7, 5<=5) | \[2,7,5\] |

result == target, return `true`.

### Complexity
- **Time:** O(n). Single pass through all triplets.
- **Space:** O(1). Only a 3-element result array maintained.

### Key concepts to review
- [[0.GreedyGuide|Greedy]] - filtering out "bad" triplets and accumulating the max is provably optimal
- [[05.HandOfStraights]] - another greedy that filters candidates before processing
- [[07.PartitionLabels]] - greedy that accumulates a running boundary in a single pass

### Common pitfalls
- Including triplets that exceed the target in any position, which can overshoot the target.
- Checking only one or two components instead of all three when filtering.
- Comparing the result list against target before processing all triplets.
- Assuming the order of merges matters. It does not, because element-wise max is associative and commutative.
