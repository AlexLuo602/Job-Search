## Template

String problems are about **character-level decomposition** -- by breaking strings into individual characters and comparing via frequency maps, sorted canonical forms, or positional checks, you reduce complex string relationships to simple data-structure operations. ### 1. Character Frequency Comparison

Compare two strings by reducing each to a frequency map. Two strings share a property (anagram, permutation, subset) if and only if their frequency representations match.

```python
from collections import Counter

def freq_compare(s: str, t: str) -> bool:
    if len(s) != len(t):                    # early exit: lengths must match for anagrams
        return False

    freq_s: dict[str, int] = Counter(s)     # decompose into character counts
    freq_t: dict[str, int] = Counter(t)

    return freq_s == freq_t                 # compare canonical representations
```

**Invariant:** Two strings are anagrams if and only if they produce identical frequency maps. The frequency map is a _canonical representation_ -- it discards positional information and retains only what matters: which characters appear and how often.

### 2. Palindrome Check (Two-Pointer)

Compare characters from both ends moving inward. A string reads the same forwards and backwards if and only if every mirrored pair matches.

```python
def is_palindrome(s: str, left: int, right: int) -> bool:
    while left < right:
        # optional: skip non-alphanumeric characters here
        if s[left] != s[right]:             # mismatch at mirrored positions
            return False
        left += 1
        right -= 1

    return True                             # all mirrored pairs matched
```

**Invariant:** At every step, `s[0..left-1]` and `s[right+1..n-1]` have been verified as mirror images. If the pointers cross without a mismatch, the entire string is a palindrome. O(1) space because no auxiliary structure is needed -- the string itself encodes positional information.

### 3. String Building / Encoding

Use a list buffer to construct or transform strings character by character. Avoids O(n²) repeated concatenation due to Python's string immutability.

```python
def build_or_encode(data: list[str]) -> str:
    result: list[str] = []

    for item in data:
        # transform, filter, or encode each item
        encoded = f"{len(item)}#{item}"     # example: length-prefixed encoding
        result.append(encoded)

    return ''.join(result)                  # O(n) final assembly
```

**Invariant:** Each `append` is amortized O(1). The final `join` is O(total characters). Total work is O(n), compared to O(n²) for repeated `+=` concatenation. Use this whenever you build a string incrementally.

### 4. Character-to-Index Mapping

Map each character to a fixed index (e.g., `ord(c) - ord('a')` for lowercase English) to use an array instead of a hashmap. Enables O(1) lookups with lower constant factor.

```python
def char_index_map(s: str) -> list[int]:
    count = [0] * 26                        # fixed-size array for 'a'..'z'

    for char in s:
        count[ord(char) - ord('a')] += 1    # map character to index

    return count                            # canonical representation as tuple/list
```

**Invariant:** `count[i]` always equals the number of occurrences of `chr(i + ord('a'))` in the processed portion of the string. This array serves as a canonical representation equivalent to a Counter but with O(1) space (fixed 26 slots) and faster constant-time access.

## When to Use -- and When You Can't

### String Techniques Apply When

The core power is **canonical representation** -- by decomposing strings into frequency maps, sorted forms, or positional comparisons, you reduce string equality/similarity questions to simple data-structure lookups.

| Source of Advantage                       | Example                              | Why String Decomposition Wins                                                                                    |
| ----------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| **Frequency-based equivalence**           | Anagram detection, permutation check | Sorting or counting characters produces a canonical key; direct string comparison would require all permutations |
| **Positional symmetry**                   | Palindrome check, mirrored strings   | Two-pointer exploits the symmetry directly in O(n) time, O(1) space                                              |
| **Character-by-character transformation** | String encoding, compression         | List buffer avoids O(n²) immutability penalty; process each character independently                              |
| **Prefix/suffix relationships**           | Longest common prefix, starts-with   | Vertical scanning compares position-by-position across multiple strings                                          |
| **Parsing with local state**              | String to integer, number validation | Finite-state character processing handles signs, digits, and overflow in a single pass                           |

### String Techniques Do NOT Apply When

- **You need substring matching with wildcards or regex.** Pattern matching engines (KMP, Rabin-Karp, regex) use specialized algorithms that go beyond character-level decomposition.
- **The problem requires optimal substructure over substrings.** Longest common subsequence, edit distance, and similar problems need dynamic programming -- decomposing into characters alone is insufficient.
- **The problem involves a dictionary of words.** Trie-based approaches (prefix trees) are more efficient for autocomplete, word search, and dictionary lookups than flat string operations.
- **You need to find all occurrences of a pattern in a text.** Sliding window or KMP is appropriate, not simple frequency comparison.
- **The problem requires comparing strings by edit operations.** Levenshtein distance and similar metrics need DP, not canonical-form comparison.

### String Patterns vs. Other Techniques

| Problem Shape                                    | Better Approach                | Why Not Basic String Decomposition?                                                       |
| ------------------------------------------------ | ------------------------------ | ----------------------------------------------------------------------------------------- |
| Find all substrings matching a pattern           | Sliding Window / Rabin-Karp    | Substring problems need windowed views, not global frequency counts                       |
| Autocomplete / prefix lookup across a dictionary | Trie                           | Trie shares prefixes across words; flat string comparison is O(n·k) per query             |
| Minimum edit distance between two strings        | DP (Wagner-Fischer)            | Requires considering insert/delete/replace operations across all positions                |
| Longest palindromic subsequence                  | DP                             | Subsequence ≠ substring; two-pointer palindrome check only works on contiguous characters |
| Pattern matching with `?` and `*` wildcards      | DP / Backtracking              | Wildcards break the character-by-character comparison model                               |
| Repeated substring / string period detection     | KMP failure function           | Requires understanding of the string's internal repetition structure                      |
| **Anagram grouping / frequency equivalence**     | **Frequency Map (this guide)** | Canonical form comparison is the direct and optimal approach                              |
| **Palindrome validation**                        | **Two-Pointer (this guide)**   | Positional symmetry is exactly what two-pointer captures                                  |

## In-depth Explanation

### The Core Principle: Character-Level Decomposition and Canonical Representation

> **String problems are solved by decomposing strings into their constituent characters and comparing via canonical representations -- frequency maps, sorted forms, or positional checks.** The key insight is that most string relationships (anagram, palindrome, prefix, encoding) reduce to a simpler structural property once you strip away the positional ordering and look at character-level invariants.

This principle manifests in three forms:

1. **Frequency canonical form:** Two strings are anagrams ↔ `Counter(s) == Counter(t)`. The frequency map is the canonical representation that erases positional differences.
2. **Sorted canonical form:** `sorted(s) == sorted(t)` is an equivalent test. Sorting is another way to produce a canonical string from any permutation.
3. **Positional canonical form:** A string is a palindrome ↔ `s[i] == s[n-1-i]` for all valid `i`. The two-pointer technique checks this positional symmetry directly.

### Why Canonical Representation Works

Consider the anagram problem: "are `listen` and `silent` anagrams?" Naively, you'd check all 6! = 720 permutations of one string. But if you decompose both into frequency maps:

- `listen` → `{l:1, i:1, s:1, t:1, e:1, n:1}`
- `silent` → `{s:1, i:1, l:1, e:1, n:1, t:1}`

The maps are identical, so the answer is yes. The frequency map collapses 720 permutations into a single canonical form, reducing O(n! · n) brute force to O(n).

### Verification Checklist

Before implementing a string solution, confirm:

1. **Is the problem about character-level properties?** If the answer depends on character frequencies, positions, or identity (anagram, palindrome, prefix), decomposition applies. If it depends on substring structure or edit operations, consider DP or sliding window instead.
2. **Which canonical form is appropriate?** Frequency map for anagram/permutation problems. Sorted form for grouping. Positional comparison for palindromes and prefixes.
3. **Are you handling case sensitivity?** Most problems specify lowercase-only or require `.lower()`. Forgetting this is a common bug.
4. **Are you handling non-alphanumeric characters?** Palindrome problems often require filtering with `.isalnum()`. Skipping this changes the answer.
5. **Are you using list-based string building?** If constructing a result character by character, use `[]` + `.join()`. Never use `+=` in a loop.
6. **Have you considered the character set size?** `[0]*26` works for lowercase English. Unicode or mixed-case requires a hashmap.
7. **Does integer overflow apply?** For string-to-integer conversion, check against `2^31 - 1` and `-2^31` bounds before each digit multiplication.

### Counterexample: When Character Decomposition Fails

**Problem:** Find the longest substring without repeating characters.

**Incorrect approach -- use frequency map comparison:**

```python
def length_of_longest_wrong(s: str) -> int:
    from collections import Counter
    best = 0
    for i in range(len(s)):
        for j in range(i + 1, len(s) + 1):
            freq = Counter(s[i:j])
            if max(freq.values()) == 1:     # all unique
                best = max(best, j - i)
    return best
```

This is O(n³) -- it checks every substring and builds a frequency map for each. The correct approach is **sliding window**: maintain a window `[left, right]` with a set of seen characters, expanding right and shrinking left when a duplicate appears. The sliding window exploits the _contiguous_ nature of substrings, which raw frequency decomposition cannot capture.

**Lesson:** Character decomposition answers "do these characters satisfy a property?" but not "what is the optimal contiguous range?" For substring optimization, use sliding window. For subsequence optimization, use DP.

| --------------------------------- | ---------- | ----- | ---------------------------------------------------- |
| Frequency map (Counter)           | O(n)       | O(k)  | k = unique characters (≤ 26 for lowercase English)   |

## Template Variants

### Variant 1: Valid Anagram (LC 242)

**Why frequency decomposition works here:** An anagram is a rearrangement -- same characters, same counts, different order. The frequency map erases order, so two anagrams produce identical maps. Comparing maps is O(n) total, far cheaper than generating all permutations.

```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False

        count = [0] * 26
        for i in range(len(s)):
            count[ord(s[i]) - ord('a')] += 1
            count[ord(t[i]) - ord('a')] -= 1

        return all(c == 0 for c in count)
```

`count` has non-zero entries → return `False`. "rat" and "car" are not anagrams.

**Time:** O(n) | **Space:** O(1) (fixed 26-slot array)

---

### Variant 2: Valid Palindrome (LC 125)

**Why two-pointer works here:** A palindrome has mirror symmetry -- `s[i] == s[n-1-i]` for all i. Two pointers moving inward check this symmetry directly. Skipping non-alphanumeric characters and normalizing case handles the "consider only alphanumeric" constraint without building a new string.

```python
class Solution:
    def isPalindrome(self, s: str) -> bool:
        left, right = 0, len(s) - 1

        while left < right:
            while left < right and not s[left].isalnum():
                left += 1
            while left < right and not s[right].isalnum():
                right -= 1

            if s[left].lower() != s[right].lower():
                return False

            left += 1
            right -= 1

        return True
```

**Time:** O(n) | **Space:** O(1)

### Variant 3: Longest Common Prefix (LC 14)

**Why vertical scanning works here:** A common prefix must match at every position across all strings. Scanning column by column (position 0 of all strings, then position 1, etc.) lets you stop at the first mismatch. This is the positional form of character-level decomposition applied across multiple strings simultaneously.

```python
class Solution:
    def longestCommonPrefix(self, strs: list[str]) -> str:
        if not strs:
            return ""

        for i in range(len(strs[0])):           # scan position by position
            char = strs[0][i]
            for j in range(1, len(strs)):        # compare across all strings
                if i >= len(strs[j]) or strs[j][i] != char:
                    return strs[0][:i]           # mismatch: prefix ends here

        return strs[0]                           # first string is the prefix
```

**Time:** O(n · m) where n = number of strings, m = shortest string length | **Space:** O(1)

### Variant 4: String to Integer -- atoi (LC 8)

**Why character-by-character parsing works here:** Integer parsing is a finite-state problem: skip whitespace → detect sign → accumulate digits → clamp to 32-bit range. Each character maps to exactly one state transition. This is character-level decomposition applied as sequential state processing rather than frequency counting.

```python
class Solution:
    def myAtoi(self, s: str) -> int:
        INT_MAX, INT_MIN = 2**31 - 1, -(2**31)
        i, n = 0, len(s)
        result, sign = 0, 1

        # Phase 1: Skip leading whitespace
        while i < n and s[i] == ' ':
            i += 1

        # Phase 2: Handle optional sign
        if i < n and s[i] in ('+', '-'):
            sign = -1 if s[i] == '-' else 1
            i += 1

        # Phase 3: Accumulate digits
        while i < n and s[i].isdigit():
            digit = ord(s[i]) - ord('0')

            # Overflow check before multiplying
            if result > (INT_MAX - digit) // 10:
                return INT_MAX if sign == 1 else INT_MIN

            result = result * 10 + digit
            i += 1

        return sign * result
```

**Return:** `sign * result` = `-1 * 42` = `-42`

**Time:** O(n) single pass | **Space:** O(1)

### Variant 5: Group Anagrams (LC 49)

**Why sorted canonical form works here:** Every anagram of a word produces the same sorted string. Using the sorted form as a hashmap key groups all anagrams together in a single pass. The alternative -- using a character count tuple as the key -- avoids the O(k log k) sort per word, replacing it with O(k) counting.

```python
from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: list[str]) -> list[list[str]]:
        groups: dict[tuple[int, ...], list[str]] = defaultdict(list)

        for word in strs:
            count = [0] * 26
            for char in word:
                count[ord(char) - ord('a')] += 1
            groups[tuple(count)].append(word)   # canonical key = frequency tuple

        return list(groups.values())
```

**Why count-tuple over sorted key?** Sorting each word is O(k log k). Building a 26-element count array is O(k). For large k (long words), the count-tuple approach is asymptotically faster. Both produce valid canonical representations.

"eat" and "tea" map to the same count tuple → same group.

**Time:** O(n · k) where n = number of strings, k = max word length | **Space:** O(n · k)

### Variant 6: Encode and Decode Strings (LC 271)

**Why length-prefixed encoding works here:** The challenge is encoding a list of strings into a single string such that decoding is unambiguous -- even if strings contain delimiters. Length-prefixed encoding (`"4#word"`) uses character-level building and parsing: the length tells the decoder exactly how many characters to consume, making any delimiter character safe within the payload.

```python
class Solution:
    def encode(self, strs: list[str]) -> str:
        result: list[str] = []
        for s in strs:
            result.append(f"{len(s)}#{s}")  # length + delimiter + payload
        return ''.join(result)

    def decode(self, s: str) -> list[str]:
        result: list[str] = []
        i = 0

        while i < len(s):
            # Find the '#' delimiter to extract the length
            j = i
            while s[j] != '#':
                j += 1

            length = int(s[i:j])            # parse length prefix
            word = s[j + 1 : j + 1 + length]  # extract exactly 'length' chars
            result.append(word)
            i = j + 1 + length              # advance past this word

        return result
```

**Time:** O(n) for both encode and decode, where n = total characters across all strings | **Space:** O(n)
